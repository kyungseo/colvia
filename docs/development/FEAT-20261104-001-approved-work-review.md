# 승인한 작업의 수정본 검토

2026-11-04 · 일반 로컬 Work · Owner 수락·완료

사용자가 두 문서의 편집과 검사, 수정본 검토까지 담은 계획을 승인하면 에이전트가 두 문서를 고치고 검사한 뒤 같은 채팅에 제출본을 보여준다. 수정본 수락은 사용자에게 남는다.

## 변경한 곳과 이유

- 기존 Core는 전체 파일 상태, 허용 범위, 선택된 판본과 수락 결정을 대조한다. 새 상태나 제출 API를 추가할 필요는 없었다.
- [어댑터](../../adapters/colvia-work/SKILL.md#show-the-revision-for-review)와 [작업 규칙](../GENERAL-WORK.md#supervised-work-iteration)에 승인한 계획의 끝을 명시했다. 초안만 맡긴 경우, 필수 검사 실패, 범위 축소, 제출 상태 불명, 판본 변경과 복수 후보를 구분한다.
- 처음 쓰는 사람의 한영 실습과 설치본 안내에서 사용자가 제출을 한 번 더 요청하는 단계를 뺐다. 별도 기기 알림은 사용자가 맡기는 흐름에 둔다. 새 대화에서 어제 확인한 결과를 찾는 결제 재시도 사례는 README에, 예약 FAQ 실습은 시작 가이드에 둔다.
- [공개 준비 계획](preview-release-order-and-user-journey.md)에 문서 언어와 배치 제안, 보호 경로의 재검토 조건과 선택형 가명 사본 요약 후보를 기록했다.

## 확인 범위

합성 프로젝트에서 범위 밖 기준 문서가 바뀌면 제출 준비가 거부됐다. 승인된 파일을 수정해 제출한 뒤 새 Python 프로세스가 같은 Work와 판본을 읽었고, 상태는 검토 대기, 수락 결정은 0건이었다. 검토한 파일을 다시 수정하자 이전 판본에 대한 수락 적용이 거부됐다. 이 시험은 실제 Core 저장소와 런타임 확인용 시험 대역을 사용했다. 별도로 범위·수락·불완전한 제출·재개 View의 집중 검사 13건이 통과했다.

깨끗한 VM에서 Codex와 Claude Code가 실제 대화 중 추가 제출 요청 없이 수정본을 보여주는지, 새 채팅에서 같은 판본을 찾는지는 공개 후보의 사용자 시험에 남긴다.

추가로 합성 프로젝트의 실제 관리 실행기를 반복해서 새 프로세스로 열었다. 같은 제출 판본을 표시했고, 파일을 다시 편집하자 그 판본과 현재 파일이 다르다고 표시했다. 두 조회 모두 기록을 바꾸지 않았다. 복수 Work 요약에서 자동으로 하나를 선택하지 않는 검사와, 선택 변경 뒤 오래된 수락 티켓을 거부하는 검사도 통과했다.

독립 계획·결과 리뷰를 각 1회 진행했다. 결과 리뷰에는 차단 의견이 없었다. 이후 한영 실습에서 계획을 고쳐 달라고 할 때, 24시간 기준을 대조할 때, 검사가 계속 실패할 때의 설명을 맞췄다. 이 문구 보정은 독립 재리뷰 대상에 포함되지 않았다.

## Owner 수락과 완료 · 2026-11-04

Owner가 승인한 편집을 별도 제출 요청 없이 검토할 판본까지 보여주는 변경과 공개 준비 계획의 문서 언어·배치안을 수락했다. 개별 작업의 결과 수락은 해당 판본을 본 사용자가 결정한다. 깨끗한 VM의 Codex·Claude Code 실사용 확인은 공개 후보 시험으로 남긴다.
