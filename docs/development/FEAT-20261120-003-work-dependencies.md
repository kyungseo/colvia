# Explicit Work dependencies

The Owner authorized an advisory relationship between two existing Works in the same project. This extends the [project overview](FEAT-20261120-001-project-status.md) after the [candidate priority change](FEAT-20261120-002-candidate-priority.md). The implementation started from `141d26f`. See the [proposed contract](../decisions/DR-0009-explicit-work-dependencies.md) and the [user guide](../../manual/en/work.md#work-dependencies).

## Scope and checks

Store the direction, captured versions, relevant request, recorder and previous event. Check add, remove and atomic replacement without changing either Work. Derive each direction from the same bounded set of edges. Keep a user-requested dependency separate from priority, a follow-up, a replacement, and the required child results in an existing parent submission. No new identity or ownership model is introduced.

The [focused checks](../../tests/test_foundation_work_dependencies.py) exercise stale requests, concurrent opposite changes, cycles involving child requirements, recovery after an interrupted write, an uncertain response after publication, reopening, archive, unavailable evidence, and backup restore with an older reader. The [worker](../../tests/test_foundation_worker.py) and [composition](../../tests/test_foundation_composition.py) cases cover the acceptance and capture used by the overview. Closing criteria also include the actual prior version’s compatibility boundary, both manuals and three fixture ZIPs. The static result reviewer requested corrections. The Driver restricted composition checks to new child selections, distinguished a retained parent acceptance from a child result that needs another check, and marked incomplete relationship details separately from an incomplete Work list. Adding a child still requires enough readable evidence to rule out a conflicting dependency.

The post-review run passed 17 focused cases. The previous version refused a write on a synthetic copy after the first relationship; the original DB and backup remained intact. Checks covered 21 prerequisites across two detail pages, 12 child Works under a reduced read budget, three distinct accepted prerequisites and the bundled code and guides on all three fixture platforms. Prior status and priority evidence was reused. The Driver verified the corrections after the single review round. Product acceptance and release are separate decisions.
