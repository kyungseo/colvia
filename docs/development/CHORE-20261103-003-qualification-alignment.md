## Win11 x64

첫 공개에 Intel·AMD 계열 Windows 11 x64를 포함하려면 아래 순서를 한 묶음으로 진행한다. r5의 플랫폼·아키텍처별 판단과 [기존 x64 집중 검사](windows-native-implementation-plan.md#regression-and-reuse)를 따른다. [ARM64 수락 기록](FEAT-20261102-006-windows-basic-distribution.md#owner-수락과-완료-2026-11-03)은 지정 표준 계정의 선행 후보에서 첫 Work·View·재개, 갱신·롤백·런처 복구·프로젝트 연결 해제를 확인했다. 연결 해제 뒤 전용 Python과 사용자 문서·작업 기록을 보존했다. 마지막 ARM64 관리 도구에서는 요청 저장 경로 8단계만 확인했다. 선행 결과를 재사용할 때에는 공통 코드와 입력에서 달라진 점이 없는지 항목별로 대조한다.

1. **후보 고정.** 관리 도구와 전용 CPython을 Windows x64용으로 준비한다. 공급 경로, 버전, 설치본·런타임·검사 명령의 식별자와 해시를 고정한다. 스크립트형 진입점은 실제 호출하는 실행 파일까지 추적하고, 네이티브 실행 파일·로드되는 DLL의 PE Machine, 공급자·무결성, 다른 아키텍처 입력 거부를 대조한다.
2. **개발 측 집중 검사.** ARM64 근거 중 코드·입력 계약·기대 결과가 동일한 Work 상태 전이와 View 표시를 재사용한다. x64 네이티브에서 설치 명령이 실제 고정된 전용 x64 Python을 선택하는지 확인한다. ABI·인수·종료 코드, 핸들 수명·잠금, 교체·flush 및 한글·공백 경로는 변경 영향에 맞춰 확인한다. 갱신·롤백을 안내하려면 지원 버전 쌍으로 왕복하고 Work 보존을 확인한다. 복구는 알려진 손상을 짝이 맞는 배포본으로 복원하고, 제거는 프로젝트 연결 해제 뒤 남을 문서·작업 기록·전용 Python을 대조한다. 관리 도구나 Python까지 제거한다고 안내하려면 그 동작도 별도 증거가 필요하다. 개발용 네이티브 x64 환경이 없다면 확인하지 못한 기능은 공개 범위에서 보류한다.
3. **외부 확인은 최종 후보로 한 번.** 개발 검사를 마치고 실제 배포 경로 사용이 승인된 뒤에만 요청한다. 사전에 서명 상태와 표준 계정에서 예상할 일반 다운로드·설치 화면을 고정한다. SmartScreen·평판·서명 등 보안 경고 또는 UAC 승격 요청이 나타나면 그 단계에서 중단한다. Windows 11 네이티브 x64 표준 계정에서 안내한 경로로 받아, 관리자 권한 없이 제공한 명령 하나로 전용 x64 Python 기동 → 예제 Work 생성 → View에서 제목과 ID 확인 → 새 프로세스에서 같은 ID 재개까지 확인한다. 설치·확인 명령은 실제 배포본과 동일한 설치 진입점을 이용한다. 임시 첨부 파일이나 ARM64 에뮬레이션으로 대체하지 않는다.
4. **한 줄 회신과 공개 판단.** 확인자는 성공하면 명령이 출력한 후보 SHA-256·Windows 빌드·native x64·전용 Python 사용·동일 Work 재개 결과를 한 줄로 전달한다. 다운로드 또는 실행이 막히면 경고를 우회하지 않고 멈춘 단계만 회신한다(예: `중단 · 다운로드 경고`). 이름·기기 ID·경로·로그는 필요 없다. 성공한 환경과 기능만 안내하며 미확인이나 차단 시 재요청 없이 범위를 줄이거나 보류한다. 최종 후보나 배포 경로가 바뀌면 영향을 다시 판단한다. 갱신·롤백·복구·제거 결과를 안내할 때는 개발 측에서 확인한 후보·기능과 외부에서 확인한 첫 사용 흐름을 구분한다. 외부 유지보수 검증은 이 요청에 포함하지 않는다. 확인된 한 기종을 Intel·AMD 두 기종 각각의 실측으로 표시하지 않는다.

현재 x64는 계획 단계다. 첫 공개를 ARM64로 한정할 경우에는 기존 공개 조건과 달라지는 범위를 Owner가 명시적으로 결정한다. 공개 배포, 외부 확인 요청과 실제 adopter 적용은 별도 결정이다.
