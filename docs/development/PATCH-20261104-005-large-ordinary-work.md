# 대량 파일 변경의 제출·수락과 저장 한도

2026-11-04 Owner가 기존 형식 보강과 격리 실험 결과를 수락해 완료했다. 기존 일반 Work 형식을 유지하는 보강과 새 형식의 격리 시제품을 구분한다. 새 형식의 실제 도입은 별도 결정이다.

## 일반 작업에서 바뀐 점

- 승인할 파일이 많을 때는 경로를 표준 입력으로 넘길 수 있다. 검토할 때는 변경 경로가 열 개를 넘으면 추가·수정·삭제 건수와 상위 다섯 폴더를 제공한다. 전체 경로 목록은 계속 조회할 수 있다.
- 기기 알림을 요청한 일반 제출은 승인 범위와 제출 시점의 지문을 인계한다. 작업자는 당시 기준과 현재 파일로 변경 기록을 재구성한다. 확인 이후 다른 파일이 바뀌거나 제출 내용이 다르면 수락으로 넘어가지 않는다.
- 기준 기록이 4 MiB를 넘으면 계획을 기록하기 전에 측정값과 한도를 안내한다. 한도의 75% 이상인 새 계획에는 남은 바이트 수도 표시한다. 실제 수정 뒤 한도가 넘으면 저장할 수 없으며 기존 기록을 보존한다.

| 파일 12,000개 중 1개 변경 예정 | 기준 기록이 4,752,677바이트. 이전에는 승인 뒤 시작 단계에서 실패했으며, 보강본은 목표나 Work를 쓰기 전에 안내 |

별도 프로세스에서 수신기가 없는 상태로 검증했다. 기기 배너와 클릭, 실제 팀 작업의 속도는 측정하지 않았다. 구버전과 보강본이 서로의 기존 형식 수락 기록을 읽었고, 구버전 수신함에서도 보강본의 완료 제출을 읽었다. 구버전 런처는 축약된 신규 인계 요청을 거부했다. 제출 후 수신함 기록 직전 중단은 실행을 반복하지 않고 기존 선택 기록을 대조해 복구했다.

## 새 형식의 격리 실험과 전환 조건

12,000개 파일의 목록을 256개 항목씩 나누고, 조각 검증 후 최종 참조를 기록했다. 한 파일 수정과 1,000개 수정 모두 기존 논리 기록과 바이트 단위로 일치했다. 최종 참조를 쓰기 전 중단, 누락·변조된 조각, 잘린 참조, 잘못된 구조와 판독량 초과는 거부했다. 실험 코드는 제품에 포함하지 않는다.

전환을 선택하면 새 배포 형식 식별자를 부여하고 기존 기록 읽기를 먼저 보장한다. 미처리 작업자를 비우고 복구 사본 확인 뒤 이전 쓰기를 막는 전환 기록을 남긴다. 새 기록을 쓴 후에는 이전 버전으로 자동 복귀하지 않는다. 합성 미래 바인딩에서 이전 런처의 쓰기 전 거부를 확인했다. 실제 업그레이드·복원, 운영체제별 정전·저장 실패 및 모든 이전 쓰기 경로는 별도 검증이 필요하다.
