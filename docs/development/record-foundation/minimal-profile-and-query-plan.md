# 최소 문서 실행 정책·Claude 최종 답변 확인 계획

상태: 제안. Owner의 다음 진행 요청에 따라 실행안을 준비했다. 제품 정책은 아직 바꾸지 않았고 새 모델·네이티브 호출은 시작하지 않았다. 기존 Work가 이 묶음도 소유한다.

## 목적과 근거

전용 runtime의 준비·종료 및 문서 5단계는 확인했으나, 실제 출력된 정책에는 진단용 read 규칙이 남아 있다. Claude는 정확한 조회를 마쳤으나 최종 답변 전에 시험 도구가 진행 이벤트를 거부했다. 이번 묶음은 이 두 잔여만 다룬다. [직전 결과](runtime-alignment-result.md)의 원 실행과 실패는 변경하지 않는다.

읽기 전용 대조 결과, `DarwinWorkerPlan.materialize`는 입력 template에 있는 진단 부록도 그대로 출력한다. `worker.sb.in`의 'not approved or active' 주석은 실행 상태와 일치하지 않는다. 삭제 후보는 두 진단 부록과 개인 패키지 관리 도구 경로의 gettext 두 literal이며, 승인 문서·전용 runtime·시스템 라이브러리와 정확한 쓰기 대상 규칙은 유지한다. 이는 읽기 권한의 축소 후보다. 불필요하다는 실행 근거는 새 검사 전까지 미확정이다.

## 구현 범위와 순서

1. 새 Claude CLI 정적 계획 리뷰: 아래 정확한 후보 diff, renderer, 직전 결과 및 보정된 시험 판정만 전달한다. 구독 인증을 확인하고 도구 없는 새 세션으로 진행한다.
2. 후보를 `runtime/official/worker.sb.in`에 반영하고 `tests/test_foundation_worker_plan.py`에 진단 부록·외부 gettext 경로 부재 및 기존 읽기/쓰기 경계 보존 검사를 추가한다. renderer 변경이나 대체 실행 경로는 포함하지 않는다.
3. 새 합성 fixture와 실행 입력을 고정한다. 기존 ready/stop 게이트와 판독기를 재사용하며, CLI 실행 파일 식별·관측 버전·지원 이벤트 스키마 및 최종 답변 조건을 함께 고정한다. 개별 코드 hash만 바뀌었다는 이유로 전체 제품 검사를 반복하지 않는다.
4. 전용 runtime의 최소 정책 비활성 작업자 준비·종료 1회(60초 이내). 성공한 경우에만 같은 정책으로 원 문서 5단계 1회(180초 이내). 실패 시 그 경로에서 중단하고 이전 넓은 정책으로 우회하지 않는다.
5. 독립된 Claude 조회 1회(240초 이내). 기존 Codex가 수락한 합성 Work를 읽는 wrapper만 허용한다. 조회 1회·성공 응답 1회 뒤 최종 자연어 답변, 정상 종료, 거부 없음, 프로젝트·정본 무변경을 모두 확인한다. 내부 ID·hash·경로를 나열하지 않고 이미 수락한 결과를 다시 수락하라고 묻지 않는지도 판독한다. 새로운 변경·수락 권한은 주지 않는다.
6. 결과 리뷰와 범위 내 오프라인 보정·집중 검사·결과 기록을 마친다. Reviewer 지적 보정은 이 묶음에 포함한다. 새 라이브 실패는 재시도하지 않고 원 실행 결과를 보존한다. 한 경로 실패가 다른 독립 경로 실행을 막지는 않는다.

## 검사 선택과 재사용

- 새 검사: template/renderer 읽기·쓰기 경계, 비어 있는/바뀐 프로세스 신원과 종료값, 진행 이벤트와 권한 이벤트 구분, EOF·최종 답변·세션·명령 조건.
- 재사용: 제품 버전 경계 33개, 이미 완료한 Codex 작성·제출·수락, 이전 공급 대조와 전체 Mach-O 의존 대조. 실행 직전 입력 일치만 확인한다. 불일치는 자동 새 후보 생성이나 재실행으로 처리하지 않는다.
- 공통 controller 44개 검사는 직전 현재 코드 검증을 재사용한다. 해당 코드가 다시 바뀌면 영향받은 검사만 선택한다.
- native 성공은 raw 전용 runtime과 이번 emitted 정책의 증거다. 정규화 설치 슬롯·설치본·앱·Windows의 통과가 아니다. 알려진 진단 부록 제거를 완전한 보안 감사로 표현하지 않는다.

## 시간과 호출 한도 제안

예상은 리뷰·모델 대기 포함 60–100분, 중단 상한은 120분이다. 직전 묶음 약29분의 실측에 정책 변경·새 fixture 입력 고정과 리뷰 보정 여유를 더한 판단치다. 순차 실행 대기는 경과에 한 번만 계산하고 Owner 대기는 제외한다. 기존 4시간 실행 묶음의 잔여 약145분과 누적100시간 안에서 사용한다.

- 행동 대화 한도 11 → 12개: Claude 새 대화 1개, 메시지 1개, 호출 대기 240초. 메시지18개·행동 대기2400초의 기존 누적 상한은 유지한다.
- 리뷰 한도 25 → 27회: 계획·결과 각 최대360초. 현재 누적6538.481초를 보존하고 누적 상한6900 → 7800초를 요청한다. 추가 호출을 자동으로 늘리지 않는다.
- 네이티브는 새 비활성 확인1회와 조건부 문서 흐름1회뿐이다. 실제 실패 재시도·추가 허용 규칙·timeout 확대는 포함하지 않는다.
- 기존 실패·소비량을 이월한다. 예산을 넘기거나 새 권한·제품 경계 변경이 필요하면 해당 경로만 중단한다.

## 제외와 이후

실제 설치, OS/호스트 권한·설정 변경, 키 생성, 알림, 커밋·push·PR·공개는 계속 제외한다. 이전 결과의 Owner 수락도 임의로 대신하지 않는다. 미완료 외부 효과가 있는 복원본은 조회 전용으로 유지한다.

이 묶음 뒤에는 설치본 후보 구성과 플랫폼별 검증 계획을 정리한다. 실제 설치 승인 없이 설치하거나 기존 프로젝트를 갱신하지 않는다. 동일 내용을 다시 검사하지 않도록 설치본에 전용되는 근거와 새로 필요한 근거를 분리한다.
