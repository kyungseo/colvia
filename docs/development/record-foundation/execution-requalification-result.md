# 신규 실행 검증 결과

상태: 계획·결과 정적 리뷰와 범위 내 오프라인 보정 완료. 부분 결과이며 Owner 수락 대기. [승인 계획](execution-requalification-plan.md) · [소유 Work](../FEAT-20261106-002-record-foundation.md)

## 결론

Codex의 작성·검토 제출·같은 대화 재개 수락은 이번 합성 흐름에서 통과했다. 네이티브 문서 실행과 Claude의 완료 결과 조회는 통과하지 않았다. 실패 시도를 재실행하거나 통과로 바꾸지 않았다.

| 단계 | 실제 결과 | 범위 |
| --- | --- | --- |
| 네이티브 비활성 worker | 준비 응답 전에 exit -6. Python의 외부 공유 라이브러리 로딩이 sandbox에 차단된 stderr 확보. 관측한 프로세스·그룹 부재 확인 | 이번 실패 지점을 확인했다. 이전 group 종료 EPERM의 원인은 미확정. 조건부 문서 본시험 미실행 |

Claude 시도 전후 프로젝트와 authority의 내용·권한·디렉터리 snapshot은 동일했다. 관측한 프로세스 종료도 확인했다. 시험 로그까지 무변경이라고 주장하지 않는다. Codex의 수락 결과는 유지한다.

## 실행 연결과 검증

새 fixture, 고정 manifest, 단계별 admission 원장을 사용했다. 선행 결과 hash·실패 상태·정확한 Work·파일·실제 권한 문맥을 대조하고 동일 단계를 반복하지 못하게 했다. wrapper와 controller에서 첫 실패를 보존하고, 허용 명령·편집 이벤트·보호 파일을 감사했다. controller 관측은 협력적인 에이전트 시험이며 적대적인 우회 방지나 완전한 자손 격리를 증명하지 않는다.

기존 실행기 오프라인 44개 검사와 정상 부모 종료 근거, 변경 없는 제품 기준점을 재사용했다. 새 연결부 14개 검사가 통과했고 결과 리뷰 보정까지 반영한 최종 누적18개가 통과했다. 검사 수를 합산하지 않는다. 초기 검사 코드의 변수 오류는 로그를 남긴 뒤 수정했다. 제품 전체 회귀를 반복하지 않았다.

CLI 도움말을 저장해 새/재개 설정과 Claude의 출력 형식을 확인했다. source-only wrapper를 사용했으며 실제 설치본·데스크톱·Windows 적합성으로 확대하지 않는다. 상세하고 제한된 시험 지시를 썼으므로 이전 실습보다 짧은 시간을 일반적인 사용성 개선 수치로 주장하지 않는다.

## 네이티브 실패가 뜻하는 것

이전과 동일한 profile template을 사용했다. 시험 Python의 의존성 목록과 실제 파일 존재를 읽기 전용으로 확인했고, profile에 해당 라이브러리의 허용 문구도 있었다. 따라서 누락된 경로 한 줄을 추가하면 해결된다고 단정하지 않는다. 조상 metadata·loader 처리·바깥 sandbox 관계는 아직 확인하지 않았다.

이번은 개인 Python 실행환경을 사용하는 소스 진단이다. 전용 설치 runtime의 성공이나 실패를 대신하지 않는다. 다음에는 준비된 전용 runtime의 실제 의존성과 profile의 관계를 먼저 대조해야 한다. 제품의 group-stop은 이번 private controller의 개별 신호/회수와 다르며, 이번 종료 부재 확인으로 제품 종료 경로를 통과 처리하지 않는다.

## Claude 판독 보정의 한계

정상 사용량 안내 이벤트도 미지원이면 중단하는 기존 규칙이 작동했다. 실패 당시 코드·원시 이벤트·종료 근거를 보존했다. 확인한 사용 가능 상태의 안내만 별도 판독하도록 오프라인에서 보정했다. 이 이벤트는 도구 성공이나 작업 완료의 증거가 아니며, 거부 상태·추가 과금 사용·미확인 구조는 계속 중단한다.

보정 후 실제 모델을 다시 실행하지 않았다. 이번 조회 결과는 미검증으로 남는다. 원 실행의 식별값은 새 코드로 덮어쓰지 않았고 추가 실행은 별도 준비와 승인 없이는 진행하지 않는다.

## 남은 작업

1. 네이티브 실행에 사용할 전용 runtime과 sandbox의 로더 요구를 대조하고 최소 보정·검증안을 정한다. 권한을 넓혀 우회하지 않는다.
2. 사용량 이벤트 보정의 결과 리뷰와 집중 검사는 완료했다. 별도 신규 실행 승인으로 Claude 조회 한 번을 검증한다.
3. 그 결과와 기존 근거를 합쳐 실제 설치본·플랫폼별 검증 순서를 정한다. 실제 설치·권한 변경·제품 수정·키 생성·알림·커밋·공개는 계속 보류한다.

이번에 사용한 소스·실행기·리뷰 입력·실패 fixture는 다음 원인 진단과 공개 전 검증이 사용하므로 비공개 근거를 보존한다. 저장소에는 비식별 방법·결과·한계만 남긴다.

## 결과 리뷰와 증거 보완

결과 정적 리뷰는 약141초에 끝났고 입력 drift는 없었다. 부분 통과·실패 판정은 유지하되 전후 snapshot의 시점·동일성, 중단 시 wrapper 상태, 보존 실행기 동일성을 보완했다. 정확한 시각과 hash는 비공개 근거에 남겼다.

Claude 시작 전 authority snapshot과 실행기 launch 전 project snapshot을 각각 확보했다. 중단 후 둘 다 동일했다. 선행 호출 이후 추가 wrapper trace·started 행·거부 파일·wrapper latch는 모두 없었다. 이는 조회 완료의 증거가 아니며 미관측 자손의 부재도 증명하지 않는다. 네이티브는 launch 시 실제 pgid와 pid가 같았고, 모델 경로는 launch pgid 기록이 없어 종료 증거를 관측 PID 범위로 제한한다.

다음 실행에서 조회 없이 답변만 해도 통과할 수 있었던 판정 빈틈을 보정했다. 정확한 조회 한 번과 대응 도구 응답 한 번, 올바른 메시지 역할을 요구한다. 저장된 실제 사용량 이벤트도 외부 전송 없이 로컬에서 재판독했으며, 정상 안내로 처리되지만 완료 증거가 되지는 않는 것을 확인했다. 보정 뒤 모델을 재실행하지 않았다.

자동 보고서 검사는 원본 CSV의 집계·보존과 보고서 길이·숫자 문자열 존재 확인에 한정된다. 보고서 표의 수치와 비중, 우선순위 미선택은 Driver가 본문을 별도로 대조했다. 자동 의미 검증으로 확대하지 않는다. 보정 뒤 추가 확인은 Driver가 수행한 오프라인 검사이며 Reviewer의 재검증으로 표시하지 않는다.
