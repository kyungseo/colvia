# 남은 소스 실행 검증 결과

상태: 계획·결과 정적 리뷰 완료. 이번 승인 시도는 부분 확인으로 종료했고 실패 경로는 중단 상태다. 원 결과와 실패 기록은 보존했다. [계획](held-execution-resume-plan.md) · [소유 Work](../FEAT-20261106-002-record-foundation.md)

## 판단

작성·제출·다른 에이전트의 조회는 확인했다. 그러나 Codex 재개 수락과 네이티브 문서 실행은 이번 묶음에서 통과하지 않았다. 실제 설치·호스트 권한 설정·알림·Git 게시에는 변경이 없다. CLI가 정상적으로 만든 사용자 홈의 세션 기록은 있으며, 구독 인증의 내부 갱신 여부는 조사하지 않았다. 제품 구현을 수정하지 않고 비공개 시험 실행기의 설정 전달과 관측·판독을 보정했다.

## Codex: 권한과 행동 실패를 분리

실제 turn 문맥은 workspace-write, fixture cwd, network false, approval never, 두 임시 폴더 예외 해제였다. 쓰기 경로는 legacy sandbox_policy 배열 대신 managed permission_profile의 entry에 기록됐다. 같은 fixture 경로가 중복 표기됐지만 다른 쓰기 경로는 없었다. 최초 판독기는 legacy 배열만 기대해 미확인으로 처리했다. 원 결과를 보존하고 판독기와 합성 거부 검사를 보정해 저장된 동일 문맥만 재판독했다. 모델을 재실행하거나 권한을 바꾼 것이 아니다. 현재 판독기는 쓰기 경로 추가·루트 쓰기·네트워크 허용과 알려진 필드의 미지원 값을 거부한다. 낯선 추가 키를 모두 거부하는 정규 스키마 검증기는 아니며 잘못된 타입은 예외가 날 수도 있다. 이번 실제 문맥을 판독한 근거 이상으로 확대하지 않는다.

첫 작성 중 에이전트가 승인 계획에 없는 unavailable 검사 항목을 추가해 제출했고, 제품이 check-report-mismatch로 거부했다. 이후 에이전트는 상태를 조회하고 그 항목을 빼서 다시 제출했다. 결과 파일과 기록은 유효한 검토 상태가 됐으나, 이번 시험의 새 실패 후 재시도 금지 조건을 지키지 못했다. Driver가 첫 요청과 fixture 지침에 모든 명령 실패 시 중단을 명확히 전달하지 못한 문제도 있다. 실행 후 감사에서 확인했으며 즉시 중단을 강제한 시험이라고 주장하지 않는다. 제품의 check-report-mismatch 거부 자체는 승인된 검사 범위를 지킨 보호 동작이다. 에이전트의 계획 이탈과 Driver 시험 지시의 누락을 제품 저장 실패와 구분한다. Reviewer는 재시도 금지의 대화 내부 적용을 보수적인 해석으로 보았으나, Driver는 Owner의 새 실패 중단 요청을 넓게 지키기 위해 실패 판정을 유지한다. 전체를 성공으로 바꾸지 않고 재개·수락은 보내지 않았다.

관찰된 명령에는 개인 문서·소스·authority 직접 읽기/쓰기나 첫 turn의 수락이 없었다. authority가 fixture 쓰기 범위 안에 있으므로 우회 불가능성이나 적대적 에이전트 격리를 증명한 것은 아니다. OS/호스트 설정 파일은 변경하지 않았다.

## 네이티브: 확인된 것과 남은 원인

정상 종료 probe는 바깥 프로세스 제어 경로를 확인했다. 시간 초과 probe는 현재 materializer/profile을 그대로 사용하되 문서 작업 대신 최대 30초에 끝나는 비활성 프로그램을 넣었다. 프로그램 준비 응답에 도달하지 못했으므로 의도한 시간 초과 종료 단계도 검증되지 않았다. 일반 프로세스의 시간 초과 종료도 별도로 시험하지 않았다. 따라서 시간 초과 종료 경로 전체는 미검증이다. 그 뒤 종료 시도에서 EPERM이 났다. 이전 실패와 비슷한 관찰이지만 동일 원인으로 확정하지 않는다.

현재 runner는 준비 실패를 보존했지만 child stderr와 최종 returncode를 실패 요약에 남기지 않아 최초 시작 실패의 상세 원인은 복원할 수 없다. 이 한계도 보존한다. 실행 요청은 scoped escalation으로 승인됐지만 실제 controller의 상속 sandbox 전체를 독립 확인한 것은 아니다. 비공개 profile 메타데이터의 outside-agent-sandbox 표현은 요청 경로 설명이며 실제 상속 권한의 증거로 쓰지 않는다. 실패 뒤 PID/그룹 부재를 읽기 전용으로 확인했으나 종료 성공으로 소급하지 않는다. 새 문서 fixture·profile 변경·권한 확대는 하지 않았다.

## 검증·재사용·후속

실행기 설정·문맥 판독·파일 변화·부모 exit와 종료 판정 구분의 오프라인 검사 5건이 통과했다. 제품 동작은 이번에 바뀌지 않아 기존 822개 기준점과 이후 복구·예약 결과 집중 검사를 반복하지 않는다. 이 수치를 실제 네이티브/모델 성공 횟수와 합산하지 않는다.

후속 재개에는 먼저 준비 실패 stderr·최종 종료 상태를 보존하는 진단과 실행 controller 환경 확인이 필요하다. Codex에는 실패 시 즉시 중단 조건을 정확히 전달하고 관찰하는 시험 실행기가 필요하다. 실제 재실행·추가 모델 호출은 새 승인 전 보류한다. Claude의 수치 재확인 요청과 장황한 안내는 사용성 관찰로 남기며 이번 조회 성공을 일반 사용자 경험의 완성으로 보지 않는다.

기존 실패·새 실패·fixture·정확한 리뷰 패킷은 원인 비교와 후속 검증이 소비하므로 비공개 durable artifact에 보존한다. 원본을 삭제하거나 과거 실패를 성공으로 덮어쓰지 않는다. 실제 설치본·macOS/Windows·앱·알림 적합성은 별도다.

## 최종 결과 리뷰 처분

새 Claude의 도구 없는 결과 리뷰가 129.733초에 끝났고 입력 drift는 없었다. 정적 판단이며 재현 시험은 하지 않았다. Reviewer는 부분 확인·실패 경로 중단 판정을 유지하고 제품 소스 보정 없이 이번 시도를 마무리할 수 있다고 보았다.

- D1·D6 수용: Claude는 계획의 수락 결과 조회를 통과하지 않았다. 대체 review 상태 관찰로 표기하고 이번 시도와 리뷰의 종료 상태를 명확히 했다.
- D2 수용: 사후 문맥 판독기의 검증 범위를 알려진 필드/값으로 좁혀 설명했다. 전체 키 허용 목록과 엄격한 타입 검사는 후속 보정 후보로 남긴다.
- D3 수용: 정상 부모 종료·자식 정리는 확인했지만 일반/샌드박스 시간 초과 종료는 미검증이다.
- D4 수용: 호스트 설정 파일을 바꾸지 않았다는 뜻이며, CLI 세션 저장이나 인증 내부 갱신까지 없었다는 뜻은 아니다.
- D5 수용: 실제 대화·메시지·대기·경과량을 아래에 기록한다. 사용하지 않은 재개 호출은 실패 경로 재개 권한으로 전환하지 않는다.

Claude inspect 진입 조건은 Codex 실패를 확인하고 저장된 권한 문맥을 재판독한 뒤 바뀌었다. 기존 계획의 독립된 조회·정리 계속 허용을 근거로, 정상 종료와 제한된 권한이 확인된 fixture를 읽기만 했다. 같은 fixture와 결과에 의존하므로 완전히 독립적인 시험은 아니다. Write/Edit를 제공하지 않았고 실제 도구 기록과 전후 파일 bytes digest로 무변경을 확인했다. Read 자체가 fixture 밖 접근을 완전히 차단하는 도구 구성은 아니므로 강제 격리의 증거로 쓰지 않는다.

## 후속 후보 · 실행 승인 아님

1. 네이티브 준비 실패의 stderr·종료 코드·신호 전 상태와 controller 상속 환경을 먼저 기록한다. sandbox 중첩, 이미 종료된 프로세스 회수 순서, sandbox 사이 신호 제한은 판별할 가설이며 원인으로 확정하지 않는다. 제품 process port를 바꿀지는 이 근거로 별도 결정한다. EPERM을 성공으로 무시하지 않는다.
2. 행동 시험 요청에 모든 명령 실패 중단을 넣고, 실행기에서 첫 실패 이벤트를 관찰해 추가 행동을 멈출 수 있게 한다. 원 실패와 종료 상태를 함께 보존한다. 실제 재시도는 별도 승인이다.
3. 문맥 판독기의 키/타입 검증, 조회 도구의 경로 제한, 비정상 종료에도 예산을 남기는 finally 처리, 디렉터리·모드·symlink를 포함한 파일 상태 비교를 다음 실행기 보정에 포함한다. 현재 bytes 비교를 완전한 파일시스템 무변경 증거로 확대하지 않는다.

이번에는 후속 후보를 구현하거나 추가 모델·네이티브 실행을 하지 않는다. 실패 fixture와 패킷의 소비자는 다음 원인 진단 및 공개 전 검증이며, 그 소비자가 끝나기 전까지 원본을 유지한다.

## 실제 사용량

이번 승인 시도 경과는 약 17.9분(리뷰·모델 대기 포함)으로 4시간 상한 이내다. 실패 경로에서 멈춘 시간이며 원래 목표를 모두 검증한 소요 시간이 아니다. 새 대화 2개, 메시지 2개, 모델 대기 78.996초를 사용했고 재개 1회는 미사용이다. 계획·결과 정적 리뷰는 총 297.513초를 사용했다. 누적 행동 대화 8/8개, 메시지 11/18개, 모델 대기 378.160/2,400초, 정적 리뷰 18/18회와 5410.893/6,000초다. 원래 한도와 소비량은 이월하며 미사용 예산이 중단 경로 재실행 승인을 뜻하지 않는다.
