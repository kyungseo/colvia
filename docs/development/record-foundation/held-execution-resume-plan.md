# 남은 소스 실행 검증 재개안

상태: 2026-11-07 Owner가 실행 범위와 한도를 승인했다. 실제 설치본 적합성은 별도다.
[소유 Work](../FEAT-20261106-002-record-foundation.md) · [기존 진단](held-execution-diagnosis.md)

## 목적과 순서

수락한 저장·복구·예약 결과 보강은 유지한다. 새 기능을 추가하는 대신 중단된 두 실행 경로의 실제 소스 동작을 확인한다. 이 결과는 실제 설치본·데스크톱·Windows 적합성 확인을 대신하지 않는다.

1. 시험 실행기의 새 실행/재개 설정 전달과 자식 종료 처리를 최소 보정한다. 계획 정적 리뷰 후 오프라인 구성·오류 보존 검사를 먼저 한다. 환경변수·계정 정보는 출력하지 않고 기존 구독 인증 경로만 확인한다.
2. 네이티브 경로: 새 합성 폴더와 이번에 만든 프로세스만 사용해 정상 종료와 시간 초과 종료를 각 1회 확인한다(각 60초 이내). 실행 식별·소유권·종료를 검증할 수 없으면 실제 문서 worker를 시작하지 않는다. 통과하면 기존 읽기·쓰기·검사 3종의 소스 네이티브 fixture를 1회 실행한다(180초 상한). 모델·설치·알림은 없다. 부모 종료만으로 자식 전체 종료를 선언하지 않는다.
3. Codex 경로: 새 합성 프로젝트에서 제한된 쓰기 설정을 새 실행과 재개에 명시적으로 전달한다. 실제 turn 권한과 파일·Colvia 기록을 함께 확인한다. 첫 호출에서 합성 범위의 작성·검사·제출, 같은 대화의 두 번째 호출에서 미리 지정한 합성 결과 수락을 확인한다. 이 fixture의 수락은 제품 개발 결과의 Owner 수락을 대신하지 않는다.
4. Claude 새 대화 1회로 같은 합성 Work의 수락 결과·남은 결정·파일 일치를 조회한다. 이미 통과한 Claude 작성 실습과 전체 회귀 검사는 반복하지 않는다.
5. 필요한 좁은 보정과 영향 검사, 결과 정적 리뷰, 공개 가능한 결과·미검증 목록을 기존 Work에 반영한다. 실행 경로 하나가 막혀도 독립된 다른 경로와 문서 정리는 계속할 수 있다.

## 허용할 실행과 중단 경계

- 기존 개발 작업 트리와 새 task-owned 합성 폴더에만 실행기·필요한 최소 소스 보정, fixture Git 준비, 시험 파일·기록 쓰기를 허용한다. 기존 사용 프로젝트·이전 실패 fixture는 실행 대상으로 쓰지 않는다.
- Codex 실행 인자의 제한된 fixture 쓰기 설정만 전달한다. 전역/프로젝트 호스트 설정 파일, OS 권한, 앱 모드, full-access 정책은 바꾸지 않는다. 필요한 권한이 그 경계 밖이면 해당 경로를 멈춘다.
- 이번 시험에서 생성하고 소유를 확인한 프로세스만 정상 종료·제한된 종료 요청 대상으로 삼는다. 과거 PID나 확인되지 않은 process group에는 신호를 보내지 않는다. 더 넓은 권한 없이는 종료를 보장할 수 없으면 launch 전에 멈춘다.
- 기존 로그인한 Codex ChatGPT 및 Claude Pro 경로만 사용한다. 원격 전송은 비식별 명세·관련 코드·합성 내용·검사 요약으로 한정한다. API 결제·실제 고객 자료·개인 경로·기존 원시 실습 로그는 제외한다.
- 승인 후 네이티브/모델 실패 경로의 새 시도만 허용한다. 새 실패·시간 초과·권한 불일치·종료 불명확은 보존하고 그 경로를 자동 재시도하지 않는다. 정적 확인과 국소 합성 단위 검사의 보정은 범위 안에서 가능하다. 실행 의미·기록 형식 변경이 필요하면 별도 결정으로 남긴다.
- 실제 설치·OS/호스트 권한 변경·키 생성·알림·커밋·공개는 계속 제외한다. 미완료 외부 효과 내보내기는 조회용으로 유지한다.

## 예상 시간과 요청 한도

예상 2–3활동시간에 모델·리뷰 대기 최대 24분이 추가된다. 기존 fixture와 실패 로그 재사용을 전제로 한 판단치이며, 네이티브 종료 원인이 미확정이라 차이가 날 수 있다. 중단 상한은 대기를 포함해 실제 작업이 진행되는 경과 4시간이며 기존 누적 소스 100시간 안에서 차감한다. Owner 응답을 기다리는 중단 시간은 별도로 기록한다. 서로 겹친 시간은 중복 차감하지 않는다.

| 항목 | 이번 요청 | 누적 한도와 관계 |
| --- | --- | --- |
| 행동 모델 | 새 Codex 대화 1개 + 그 대화 재개 1회 + 새 Claude 조회 대화 1개, 총 3호출·3메시지, 각 240초 | 새 대화 한도 6→8개; 메시지는 기존 18개 유지(현재 9개); 누적 모델 대기 2,400초 유지(현재 약 299초, 이번 최대 720초) |
| 정적 Claude 리뷰 | 계획·결과 2회, 각 360초, 도구 없음 | 호출 16→18회; 대기 6,000초 유지(현재 약 5,113초 + 최대 720초 = 약 5,833초) |
| 네이티브 실행 | 비모델 종료 probe 정상/시간초과 각 1회, 통과 시 5개 문서 연산 fixture 1회 | 이번 합성 프로세스만, 실패 경로 자동 재시도 없음 |
| 집중 소스 검사 | 실행기 설정·종료·오류 보존 및 실제 바뀐 경로 | 4시간 범위 안; 기존 822개 기준점과 이후 영향 검사 근거 재사용 |

리뷰 도구에는 기존 구독 인증을 확인한 CLI로 직접 요청한다. 새 정확한 패킷에 자동 승인 심사가 별도 동의를 요구할 경우에만 패킷과 목적지를 밝혀 확인한다. 이 제안은 아직 어떤 외부 전송도 시작하지 않는다.

## 종료 기준과 보존

Codex 작성·제출·재개 수락과 Claude 조회가 정확한 같은 Work에 연결되고, 파일과 기록이 일치해야 한다. 네이티브 fixture는 결과와 자식 종료를 함께 확인해야 한다. 성공하지 못한 조합은 원인·필요 조작·추가 비용을 남기고 미검증으로 표시한다.

이전 실패 로그·리뷰 입력·재현 fixture는 원인 비교와 공개 전 검증이 사용하므로 유지한다. 새 결과도 지정된 비공개 task artifact 위치에 저장한다. 설치·지원 범위 선언은 이번 소스 검증 완료와 별개다. 실제 설치본/플랫폼/알림 검증은 후속 실행 승인으로 남긴다.

## 계획 리뷰 처분

새 Claude의 도구 없는 계획 리뷰가 167.780초에 끝났고 입력 drift가 없었다. B1–B8 및 비차단 보완을 수용한다. 정상 종료 probe는 같은 그룹의 자식을 관찰한 뒤 부모가 먼저 종료하는 경우를 다룬다. 시간 초과 probe는 현재 문서 worker의 profile·materializer를 사용한 비활성 프로그램으로 controller→sandbox 신호 관계를 확인한다. 이 둘이 모두 통과하지 않으면 문서 fixture는 실행하지 않는다. 제품 sandbox 규칙은 변경하지 않는다.

Codex는 새 실행·재개 모두 동일한 호출별 설정, 정규화된 fixture cwd, 임시 폴더 예외 해제, core 환경 상속을 사용한다. 실제 turn 문맥과 명령 기록을 감사하며 fixture 안의 authority에 직접 쓰지 않았는지도 대조한다. 이 확인은 정상 경로 검증이지 악의적인 우회가 불가능하다는 증거가 아니다. 재개 ID는 첫 응답의 정확한 ID만 사용하고 수락 대상은 Driver의 저장 기록 조회로 고정한다. Claude 조회는 읽기 도구와 조회 명령만 허용하고 전후 digest를 대조한다.

외부 시험 상한에는 관찰한 자손을 포함해 종료 상태를 남기며 부모 exit만으로 성공을 선언하지 않는다. 관찰·종료 권한이 불명확하면 해당 경로를 멈추고 미확인으로 보존한다. 새 실패 후 같은 경로의 반복 실행은 없다. 국소 오프라인 보정은 승인 범위에 포함되며 마지막 결과 리뷰 1회는 유지한다.
