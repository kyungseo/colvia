# P4 source checkpoint

Status: bounded result reviews completed; source corrections verified in focused checks; reviewed-source removal after partial application remains an Owner policy question. Nothing here activates an installed contract, accepts source work for the Owner, or qualifies a platform release.

## Implemented behavior

- One project-wide pending effect is read by common Work, connection and planning writers inside their CAS validation, including absence. Reads remain available. P7 must extend the same rule to lifecycle activation/import.
- Direct-child composition fixes parent/child role, plan and semantic accepted-result references. The parent has its own scoped integration report, reported checks and human acceptance. Archive alone leaves child evidence valid. Rebinding is explicit, binds the shown old/new selection, preserves previous decisions and resets parent approval. Removing a child releases its current membership without deleting its results.
- Worker preview prepares an exact source result and distinct verified destination. The full destination content tree and policy must match the source baseline. Applying bytes is a separate request from ordinary acceptance. The sole exact isolated-worker grant does not authorize parent acceptance or host permissions.
- Applying a reviewed source result explicitly includes accepting that result. Completion publishes the application outcome, source acceptance and pending removal atomically. If the source was already accepted, preserve its decision. A cancellation never accepts a result and requires exact current preimage content without any evacuated original. Unrelated edits and safe-save inode replacement do not authorize file writes and do not block that no-effect cancellation.
- Source Darwin/APFS writer uses a process lock, no-follow directory descriptors, native identity, exclusive rename, content checks and sync. It retains evacuated originals, preserves racing user writes and refuses unknown state. No OS lock can prevent an unrelated privileged editor from moving a directory between system calls; checks before/after effect detect observed topology drift and preserve the recovery state. No universal hostile-process isolation or power-loss guarantee is claimed.
- CLI operations are source-only. Ordinary responses omit receipts, private paths and schema names. Machine JSON remains explicit.

## Record details fixed during implementation

- Composition observed head is provenance; exact plan/result/accept references establish validity independently. Required captured content is semantically checked, not merely linked.
- A worker binding's exact source selection is a decision edge because reservation/completion require it. Treating it as optional provenance would contradict that use.
- A separate immutable worker.manifest contains paths, pre/post entries, staging identities and ancestor constraints. Each progress/outcome refers to the same manifest. This prevents repeatedly storing an entire changed-file list at every step.
- Source configuration origin uses an absolute lexical file path. Git's relative primary-checkout spelling and absolute linked-worktree spelling identify the same file; actual overrides, source bytes, values and tool identity remain significant. This fixes a reproduced safe refusal without dropping policy evidence.
- Cancellation can proceed after reproducible staged-post loss, unrelated edits, safe-save replacement or source checkout removal when the actual target preimage content is exact and no original is evacuated. Root/authority/stage identity, attached no-follow paths and immutable dependencies remain verified. Unknown target bytes still refuse.
- Cross-workspace `.gitignore` changes refuse before staging/reservation. Per-step policy application remains a follow-up. Original ordinary scoped policy editing is unchanged.
- A vacant target with an exact staged post, or a verified installed postimage, can complete while a late edit to the same retained original inode is preserved and flagged in application view. Replaced/missing retained original identity still refuses. See [result disposition](p4-result-disposition.md).

## Limits and downstream obligations

- Actual installation, managed runtime, desktop/CLI host access, Windows native writer and public qualification are not covered here. No notifications, OS permission changes, real signing keys or product Git actions occurred.
- No parallel editing scheduler, forced recovery, automatic original deletion or general external-change baseline reconciliation is added.
- Full observations around effects deliberately retain the old safety floor. Large changed-file batches still need P9 cost measurement; metadata deduplication is not a throughput claim.
- Evacuated originals can receive writes through an already-open external file descriptor. Keep them after terminal outcome. P7 lifecycle/backup must account for recovery-critical filesystem material as well as recorded before/after bodies; it must not discard unique late edits when moving/restoring authority or treating staging as disposable. Such material remains in the old authority until an explicitly verified preservation path exists.
- Source schema is unactivated. No compatibility with old private trial records is inferred. First-public compatibility, restoration and supported feature configuration remain mandatory later-stage criteria.
