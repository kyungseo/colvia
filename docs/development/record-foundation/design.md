## Chosen Foundation

One project authority, multiple content workspaces. Owner selected per-project OS user-data authority storage on 2026-11-06, with explicit narrow host access. The original common-dir/colvia authority proposal is withdrawn. Exact locator/schema rules are in [C1–C8](implementation-contracts.md); actual host access still requires qualification; the old .hrn name must not silently mix formats. Logical repository-wide authority is distinct from physical placement. No legacy records/profile imports. Project UUID, workspace UUID, Work UUID, attempt UUID and submission UUID are distinct from human labels. Same cloned UUID does not prove a shared live authority; no cross-clone merging.

The new package is separate from hv2ref while implemented. Old code is a private behavioral oracle only. Public packaging selects only the new implementation after required capabilities are integrated; do not ship a fallback that silently writes the old format. Work in a new topic worktree preserving the existing dirty checkout. Select existing user-visible assets and guides into the new public surface by meaning, not whole-directory copying.

## Transactional Authority And Immutable Objects

Use Python-standard-library SQLite for the authoritative metadata and immutable typed objects, rather than implementing a custom journal, recovery engine and B-tree. Domain/application depend on a store port, not sqlite3. R2 challenged locking, corruption, body size and read-only behavior; detailed C3/C4 contracts define the implementation and qualification gates. A database is not an authenticated boundary against its OS owner.

Authority has one active SQLite store generation in the verified authority directory. Unique generation directories isolate DB/journal paths; a versioned active pointer selects the current generation under C4, without replacing an open DB pathname. Retained recovery generations are not additional writable authorities. `format/project/schema version`, immutable objects, Work/intent heads, workspace registrations, candidate/follow-up references and lifecycle state live in typed tables with constraints. SHA-256 references are domain-separated by object kind/version and include byte length. Read verifies referenced kind/digest/length. Unknown schemas, duplicate JSON keys in stored typed payloads, non-finite numbers, path aliases and unsupported modes refuse. Human labels are not keys.

SQLite owns transaction locking and crash atomicity. Start with rollback-journal mode, foreign keys enabled and synchronous EXTRA, not WAL-dependent read initialization. Read-only queries pin heads/references in a short read transaction, then read immutable non-GC objects in bounded transactions; classify hot-journal recovery separately from corruption. C3 sets SQLite 3.37 as the minimum and requires qualified bundled settings, including macOS fullfsync. The writer uses BEGIN IMMEDIATE, rechecks expected head(s) and context, inserts immutable records/objects then updates heads in the same commit. Failed CAS never publishes. Different Work changes preserve each other; same Work stale head refuses. External editors remain outside this lock. No custom per-work lock that splits a common authority. Initialize the DB before exposing a project binding. Restrict SQL to fixed statements, no extension loading or user SQL. DB/schema/foreign-key integrity and object hash validation have separate purposes.

Store bodies as immutable content-addressed chunks with bounded buffers. Stage chunks in bounded write transactions under an import identity; a failed import may leave unreferenced staged data, never a visible completed result. Atomically publish a bounded descriptor and referencing heads only after checking chunk completeness, expected workspace/Work context and CAS. Published chunks are immutable and cannot be reclaimed by staging repair. A short transaction can still block readers; qualify maximum observed reader delay and explicit busy/timeout behavior under concurrent imports. The provisional body size caps below are not latency guarantees. C3 fixes 1 MiB chunks, batches bounded by 4 MiB/64 chunks, and bounded busy acquisition; measured latency remains a qualification gate. Automatic collection of published objects is excluded. The proposed logical export pins a complete root set, then streams its immutable closure with kind/hash/length checks; mutable settings and lifecycle metadata must be included at the same snapshot boundary. The Owner adopted this export policy and location principle in the R2 disposition; C4 specifies framed logical export and explicit local restore/rebind, with implementation verification still required. Never raw-copy a live DB with an active journal or merge imported identities silently.

Tree metadata uses deduplicated immutable path-hash-trie nodes stored as typed objects, not repeated whole project lists per Work. Each branch partitions by the next byte of SHA-256(canonical relative path), up to256 children; leaves hold sorted unique path entries, at most128 entries/4MiB. The proposed canonical rule depends only on the complete entry set: a leaf exists iff count and encoded-byte limits permit it; otherwise split by the next path-hash byte, remove empty children and collapse eligible subtrees after deletion. Incremental construction must equal this canonical reconstruction. C2 specifies the complete-set function and encoding; property and overflow tests remain required. Split deterministic buckets to depth8; exceeding bound refuses before commit. Validate edge prefix, ordering, duplicate paths, node kind/hash/length, depth and total traversal bytes. Unchanged nodes are shared. Pure functions construct and compare nodes; SQLite supplies ordinary indexing/transactions instead of a second bespoke B-tree. One path update rewrites only affected trie path. Full filesystem observation still checks all admitted content where scope protection requires it.

Read a validated Work head once and follow its immutable references. A paged overview is a projection, not a second authoritative registry. Whole-store audit is distinct from targeted verification. Corrupt DB/object means unavailable, not automatic fallback to an older accepted state. Fault injection must include pre/post-commit ambiguity, journal recovery, disk-full and missing/corrupt blobs. SQLite durability guarantees remain bounded by OS/filesystem behavior and must be qualified on supported local filesystems; do not claim a synced/network folder is safe by default.

## Bodies, Observation And Acceptance

At start, capture approved files' before bytes; at submit, preserve after bytes. Tree metadata includes observed paths/mode/size/hash, but no bodies of reference-only/source files by default. Full content-tree metadata uses the same bounded persistent map; one entry change does not copy a whole flat tree into every Work record. Addition/deletion/mode change explicit. Arbitrary binary bodies are opaque bytes; text diff is optional and encoding-aware.

Ordinary acceptance binds the exact submitted result and review receipt to user decision, never to another workspace's matching content or a Git commit. It does not apply bytes or stage/commit. Worker integration remains an explicit separate operation. Scope protects against out-of-scope changes; global observation is not truncated to make a Work pass.

Workspace observation separates raw ignore configuration/provenance, registered structural boundaries, and actual content membership. D1: nested registered same-common-dir workspace is observed separately; foreign repositories, symlink aliases, tracked parent collisions, orphan registry entries and changes during observation refuse or mark unavailable. D7: known app-added exclude text alone is not a whitelist. Equivalent observation requires proving actual effect confined to the verified structural boundary. Policy change does not erase historical acceptance.

Same-workspace simultaneous edits are not introduced now. Scope claims and expected baseline/context are recorded so a future scheduler can reject/order overlapping writes. Different workspace results remain distinct until explicit integration. Multi-session writers serialize; multiple live Works remain representable. S11 is a schema condition, not a new parallel execution claim.

## Query And Archive

Selected Work query reads its head and required reference closure from one root, rather than every Work graph. One command resolves topology/runtime policy once into an immutable observation context, with pre-publication refresh for mutation. Cached validations are per-command and keyed by identity/ref, not mtime. Cross-command caches cannot replace reading/hash verification of content needed for a decision.

Lists use immutable map traversal/paging. Archive is a state/index visibility policy preserving query/search, accepted bodies, decisions and follow-up references. It does not move or delete referenced objects or seal files against external modification. A checkpoint digest is not proof all descendants remain intact. Reads verify accessed objects; decisions verify their required closure; full audit checks all reachable objects. User-facing output distinguishes these guarantees.

## Git Candidate Contract

Observe working tree, HEAD and entire index, including unrelated staged edits and partial staging. Use a private copied index for write-tree or other potentially mutating Git observation; retain original index hash and compare before/after. No implicit stage/unstage. Candidate approval binds complete tree, parent/ref, path/mode changes and known hook policy. Recheck immediately before Git mutation and inspect actual resulting tree/ref afterward. Unknown hooks, conflict index, LFS/submodule behavior and unsupported topology refuse with a clear reason rather than a generic success claim. Hook execution and user Git operations are not authorized merely by Work acceptance.

## Numeric Bounds And Failure Cases

Initial implementation limits are engineering guards, not public qualification claims: metadata object4MiB; trie branch fanout256, leaf128 entries/depth8; body256MiB per file per version,1GiB combined before/after bytes per submission (C3); command input16MiB; bounded streamed body reads; reference traversal enforces depth, visited-set and total-byte budget. Exact limit-minus/at/plus tests are required; limits may be revised before format acceptance based on observed costs, never silently after a public version ships. Oversize must refuse before authority publication and leave old root/approved files intact. Total retained store capacity is measured, not advertised from a fixture pass.

Temporary free-space failure, short write, fsync/replace failure, hash mismatch, missing object, duplicate path, malformed range/deep graph, stale root/head, changed workspace and malicious path traversal must not produce acceptance/completion. Integrity hashes are not protection from an attacker with the same OS account rewriting all authority bytes. No claim of encryption, PII isolation or authenticated multi-user permissions.

## Regression And Incremental Order

First pin semantic oracles: exact result acceptance; stale/ambiguous refusal; scope exclusion; multiple Work histories; revise/reject/revoke; planning versus execution; follow-up identity; worker/umbrella/optional execution boundaries; notification click points to original result plus current state; lifecycle leaves records accessible; Git index preservation. Old format/version/profile strings and old friction are not regression requirements.

1. Pure schema, refs, trie and transactional immutable store with fault-injection tests.
2. Authority/workspace locator and observation context, including D1/D7 synthetic fixtures.
3. Work/intent lifecycle vertical path with before/after bodies, query, archive and export/import. Differential semantic checks against retained tests where valid; no old-byte compatibility assertion.
4. Planning/follow-up, bounded worker/umbrella and optional execution, delivery/notification and platform ports. Keep supported features behind explicit capabilities until integrated; do not ship two formats.
5. Git whole-candidate support, packaged launcher/entry and bilingual user docs. No old profile vocabulary in user paths.
6. Cumulative regression and result review; actual candidate installation/apps/OS click qualification still separate.

Structural checks enforce import direction and single ownership of identity/observation/scope/transactions. Source metrics compare against saved baseline but smaller LOC is not a pass by itself. Focused tests during development; full applicable regression only after integrated behavior warrants it. Initial implementation is not a new support claim for every file type, architecture or runtime version.

## First Public Release As Compatibility Baseline

The Owner clarification is explicit: only pre-public internal trial history/profile compatibility is dropped. Project connection, functional capability selection, version management, update, repair and detach remain required. First public release starts the compatibility promise; subsequent public versions must preserve its records, settings and human acceptance history.

- Version dimensions are separate: product/build version; store schema version; protocol version; capability identifiers/versions. Use feature names in UX. Retire old trial labels without removing necessary feature selection/management.
- Connect previews target/authority/runtime/capabilities and changes. Existing project-owned rules/settings are preserved. Reconnecting new-format history must identify the same project or explicitly refuse a mismatch; no silent fresh identity or history overwrite.
- Updates check current schema/capabilities and migration eligibility before mutation. Compatible runtime replacement leaves authority bytes/meaning unchanged. An incompatible future schema requires explicit supported migration, a recoverable consistent checkpoint and validation before binding activation. First release need not implement a nonexistent future migration, but version negotiation/refusal and the migration transaction interface must exist and be tested with synthetic compatible/incompatible candidates.
- Persist project settings and capability selections independently from disposable runtime payloads. Disabling a capability never makes its historical results/acceptances unreadable. Required reader capability cannot be removed by an unchecked downgrade.
- Failed download/hash/signature or preflight leaves current binding and data intact. Interrupted staging, replacement or migration is classified; recovery chooses a verified complete state, never guesses by newest path. Rollback of runtime is allowed only if it supports current store/schema/capabilities. No automatic data-schema downgrade or loss of records created since update.
- Repair restores runtime/links without fabricating acceptance or discarding project records. Detach disables integration/receiver binding while retaining records, settings and referenced bodies. Removing installed tools and deleting project data are separate explicit actions; detach is not data deletion.
- Tests: new connection; normal compatible update; unknown/incompatible schema refusal; capability enable/disable with historical reads; corrupt/incomplete candidate; interruption before/after activation; supported runtime rollback; incompatible rollback refusal; repair after missing runtime; detach then archive/read/export and explicit reconnect; project rules/settings/body/acceptance equality across every applicable operation. Reuse pure lifecycle fixture mechanisms, then qualify changed actual install/platform paths separately.

New public compatibility tests are regression requirements. Old trial profile/format fixtures are not. Actual existing internal repositories still remain untouched until separately scheduled.
