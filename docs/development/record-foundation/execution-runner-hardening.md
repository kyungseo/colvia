# 시험 실행기 오프라인 보강

상태: 계획·결과 정적 리뷰와 범위 내 보정·오프라인 집중 검사 완료. 결과 수락은 Owner에게 남긴다. [이전 실행 결과](held-execution-resume-result.md) · [소유 Work](../FEAT-20261106-002-record-foundation.md)

## 목적과 범위

실행 시험에서 최초 오류 뒤 에이전트가 재시도하거나, 종료 처리 오류가 최초 원인을 가리지 않도록 시험 실행기를 보강한다. 제품 코드와 기록·수락 의미는 변경하지 않는다. 이전 실행기와 실패 fixture를 보존하고 별도 비공개 구성 요소를 만들었다.

| 경계 | 보정 |
| --- | --- |
| 첫 실패 | controller 메모리와 fixture 밖 기록에 실패를 유지한다. 보조 명령 wrapper는 실패를 반환하기 전에 기록하고 후속 명령을 거부한다. |
| 결과 판정 | 알 수 없는 이벤트·비정상 종료·불완전 응답은 성공으로 처리하지 않는다. 실패 뒤 성공 응답도 실패 상태를 해제하지 않는다. |
| 오류 보존 | 최초 오류를 종료 요청보다 먼저 기록한다. 종료·출력 수집·파일 닫기 오류는 별도로 보존한다. |
| 종료 대상 | 관측한 PID와 생성 식별값을 신호 직전에 대조한다. 불명 대상에는 신호를 보내지 않고 EPERM을 성공으로 해석하지 않는다. |
| 권한·파일 대조 | 알려진 권한 구조만 판독한다. 파일 내용 외에 디렉터리·권한·symlink도 비교하며 hardlink·특수 파일은 열지 않고 미확인으로 둔다. |
| 예산·재시도 | 시작 전 예산을 예약하고 중단 시에도 차감한다. 새 실행기나 새 출력 폴더를 만든 것만으로 이전 실패를 재시도할 수 없다. |

Claude 조회 명령은 특정 Work의 읽기 전용 wrapper로 제한하도록 구성했다. Codex 새 대화와 재개 명령에 같은 시험 권한 설정을 전달한다. 이 명령 구성이 실제 호스트에서 적용되는지는 이번에 검증하지 않았다.

## 검증 근거

처음 31개 집중 검사가 통과했고 명령 연결부·감사 조건·불명 프로세스 식별값 검사를 추가한 35개 누적 검사가 통과했다. 리뷰 지적 보정 후 최종 누적 44개 검사가 통과했다. 검사 수를 합산하지 않는다. 가짜 process·clock·signal port, 합성 byte stream과 파일만 사용했다. 기존 제품 기준점과 영향 경로 검사는 제품 변경이 없어 재사용했다.

이전 실행기·probe·지원 helper·검사 파일 네 개의 hash는 변경되지 않았다. 기존 실제 실행 실패와 로그는 보존했고 통과로 재분류하지 않았다. 필요한 소스·검사·리뷰 원본은 비공개 근거에 남긴다.

## 한계와 다음 실행 조건

보정본은 오프라인 검증된 구성 요소와 주입형 연결부다. 실제 모델을 다시 실행하는 명령은 제공하지 않는다. 제품 process port에 연결하는 live adapter, 실제 wrapper 배치, 명시적으로 선택한 세션 문맥 파일 판독, wrapper trace와 실제 명령 이벤트 대조는 신규 실행 준비에서 확인해야 한다. Codex JSONL과 Claude 출력은 같은 판독기로 처리하지 않는다.

관측 뒤 신호 사이 PID 재사용 경합과 미관측 프로세스 이탈을 막는 보안 경계는 아니다. wrapper는 협력적인 에이전트를 위한 보조 장치이며 polling으로 모든 명령을 경합 없이 차단한다고 주장하지 않는다. 권한·호출 trace·보호 파일 감사가 통과해야 별도 수락 단계로 갈 수 있다.

다음 실제 검증은 새 fixture에서 별도로 승인받아야 한다. 먼저 네이티브 준비 실패의 stderr·종료 상태를 보존하는 진단, 그다음 승인 조건을 만족하는 경우에만 Codex 작성·재개·수락과 Claude 조회를 진행한다. 실제 설치·권한 설정·키 생성·알림·커밋·공개는 계속 보류한다.

## 결과 리뷰 처분

계획 리뷰 114.191초, 결과 리뷰 168.393초에 완료했고 검토 중 입력 drift는 없었다. 결과 리뷰는 두 차단 결함을 지적했다. 오류/latch 기록 실패 시 종료 정리를 건너뛰는 경로와 새 fixture 동일·중첩·오타 경로를 허용하는 검사를 보정했다. 잠금 경합, 오류 기록 실패, 같은 경로·중첩·없는 경로의 사전 거부를 합성 검사로 확인했다.

추가로 최종 출력 수집 중 외부에서 기록한 실패를 결과에 반영하고, 미완료 후속 turn의 성공 판정·호출 기록 경합·예산 정산 예외를 보정했다. 보정 뒤 확인은 Driver의 오프라인 검사이며 재리뷰 판정을 받았다고 표시하지 않는다. 저장 장치가 쓰기를 전부 거부하면 증거 보존 자체는 보장할 수 없고 그 상태에서 다음 단계로 진행하지 않는다.

실제 연결에서 남은 항목은 wrapper latch 흡수, 정확한 cwd, 보호 파일 선택, 실제 명령 이벤트와 wrapper trace 대조다. 읽기 전용/쓰기 권한의 실제 적용과 네이티브 준비 실패·종료 EPERM은 여전히 미해결이다.
