# 전용 실행환경 대조와 남은 실행 검증

상태: 2026-11-07 Owner가 전체 묶음·120분 상한·행동 대화11개·리뷰24회를 승인했다. 기존 누적 한도와 제외 범위를 유지한다.
[소유 Work](../FEAT-20261106-002-record-foundation.md) · [이전 검증 결과](execution-requalification-result.md)

## 확인한 차이

- 이전 네이티브 진단은 개인 Python 3.14.7을 worker로 선택했다. stderr는 외부 라이브러리 로딩의 sandbox 차단을 명시한다.
- 현재 보관된 두 managed runtime의 헤더는 3.14.10이다. 각각 발견한 실행 파일·공유 라이브러리 6개의 직접 의존성을 정적으로 대조했으며 외부 패키지 관리자 경로는 없었다. 모든 지연 로딩·import 의존성이나 정상 기동을 입증한 것은 아니다. 헤더 표기는 실제 실행 버전 검증을 대신하지 않는다.
- 새 설치 슬롯의 허용 버전은 3.14.6·3.14.7뿐이다. 이 guard와 보관 배포본 사이에 불일치가 있다. 단순히 시험 Python을 교체한 성공을 관리 실행기 통과로 표시할 수 없다.
- worker plan은 전달받은 Python root를 허용하며 개인 설정을 자동으로 고르는 부분은 이번 private 진단 연결이었다. 제품 materializer의 의존성 처리 결함으로 단정하지 않는다.
- 현 profile에는 과거 진단용이라는 주석과 loader 허용 규칙이 함께 있다. materializer는 이 규칙을 제거하지 않고 템플릿을 사용한다. 주석만으로 비활성이라고 판단하지 않는다. 기존 bytes는 보존하고, 이번 계획에서는 규칙 추가·삭제·권한 확대를 하지 않는다. 정확한 사용 규칙과 공개 적합성은 별도로 표시한다.

## 권장 묶음

1. 고정한 배포 runtime의 기존 공급 근거·파일 해시·실제 Python/SQLite 조합을 확인한다. 시스템 설치 상태를 변경하지 않고 작업 전용 fixture에서 사용한다. 검증된 배포 버전이 계약과 맞지 않으면 macOS의 해당 고정 버전만 슬롯 검증에 정렬하는 제한 보정안을 리뷰한다. 임의 Python 지원이나 PATH fallback은 넣지 않는다. 신뢰 근거가 부족하면 다운로드/설치로 대체하지 않고 중단한다.
2. 계획 리뷰 뒤 private 실행기에 명시적 worker Python을 연결하고 오프라인 경계 검사를 한다. 제품 보정이 필요한 경우 slots의 플랫폼·버전 판정과 직접 관련 검사만 대상으로 한다. 저장 형식·수락 의미·sandbox profile·OS/호스트 권한은 변경하지 않는다.
3. 새 합성 fixture의 비활성 worker를 한 번, 준비·종료 포함60초 이내로 확인한다. 이번에 생성한 프로세스의 identity를 대조하고 실제 제품 group 종료 경로까지 확인한다. 실패·종료 불명은 해당 경로를 닫는다. 준비와 제품 종료가 통과한 경우에만 문서 읽기·쓰기·검사 fixture 한 번을180초 상한으로 수행한다. private 개별 종료의 성공은 제품 종료 통과로 치환하지 않는다.
4. 이전 Codex 수락 결과의 hash·authority를 대조하고, 새 Claude 대화 한 번으로 정확한 결과를 읽기 전용 조회한다. 이전 Codex 두 단계는 반복하지 않는다. 조회 호출/응답 각각 한 번, 완료 응답, 원본·authority 유지와 관측 프로세스 종료를 확인한다. 앞서 보정한 사용량 이벤트는 성공 증거로 쓰지 않는다. 실패하면 재시도하지 않는다.
5. 결과 리뷰와 필요한 오프라인 보정·집중 검사로 마감한다. 실행 당시 코드와 보정 뒤 코드를 구분한다. 실제 설치본·데스크톱·Windows 통과로 확대하지 않는다.

## 예상·상한과 승인 조건

기존 실행기와18개 연결부 검사, Codex 두 단계, 이전44개 오프라인 근거를 재사용한다. 예상 활동45–75분에 모델·리뷰 대기 최대12분을 더해 약57–87분이다. 판단치이며 runtime 공급 근거·native 종료가 주요 불확실성이다. 묶음 상한120분은 기존4시간 실행 묶음 잔여에서 사용하고 누적100시간은 유지한다. 대기 시간을 작업 경과에 중복 가산하지 않는다.

- 행동 새 대화 한도10→11, 신규 Claude1회·1메시지·240초. 기존 메시지18개와 대기2400초 상한 유지.
- 정적 리뷰22→24회, 계획·결과 각240초. 기존 누적 대기6600초 유지(현재 약6051.532초 사용,480초 추가 이내).
- 네이티브 신규 진단1회60초, 조건부 문서1회180초. 실패한 시도의 원본·원장·코드를 변경하거나 재시도하지 않는다.
- 제품 보정은 고정된 macOS 배포 runtime과 슬롯 버전 판정의 불일치를 해소하는 최소 범위에 한정한다. profile/프로세스 권한이나 다른 결함의 변경은 포함하지 않는다.
- 실제 설치·사용자 설정/권한 변경·키 생성·알림·커밋·공개는 제외한다.

기존 승인에서 실패 후 재시도를 금지했고 행동 대화와 리뷰 호출 수도 소진했으므로 이 신규 시도·호출 증액을 한 번 승인받는다. 남은 시간만으로 호출 수를 늘리지 않는다. 이전 결과의 Owner 수락을 추정하지 않는다.

## 보존

이전 실패·실행 코드·리뷰 및 이번 읽기 전용 dependency audit는 다음 runtime/종료 진단의 근거로 보존한다. 제품 소스에는 경로·계정 등 식별 정보가 없는 결론과 계획만 남긴다. 배포본과 기존 설치 파일은 수정·삭제하지 않는다.
