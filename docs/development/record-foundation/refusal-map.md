# Refusal rules and migration map

Status: static source inventory and semantic migration requirements, 2026-11-06. This is not execution evidence, new-format test results or approval to weaken a refusal. Source contract: [C1–C8](implementation-contracts.md). Existing [regression map](validation.md) remains the behavior oracle; trial byte formats and profile names are not the new compatibility baseline.

## Scope and method

Scanned 34 first-party files / 17,912 lines: product Python under `src/hv2ref` and `distribution`, plus distribution Go, Objective-C and shell. Excluded tests, third-party parser code and runtime dependencies. The second scan includes the `need` alias used by official execution; the initial scan omitted it and is retained as an intermediate result, not reported as complete.

Found 2,289 syntactic sites: 579 raises, 1,612 guard calls, 38 failure projections and 60 native lexical candidates. These are not 2,289 independent safety rules. Wrapper calls repeat checks; some sites implement deliberate fault injection or presentation. The AST scan captures enclosing conditions, function, exact expression, source digest and line. Native extraction is lexical, not a control-flow proof. Implicit I/O exceptions, assertions in dependencies and every possible exception handler are not proven exhaustive by this scan.

The table below is the semantic inventory requested in R2 M9: actual condition/source, treatment and required negative oracle. Exact per-site input/route remains in the private task evidence; all extracted sites have a family and test target. Family routing is mechanical; critical named functions and boundary conditions were read, not all 2,289 sites individually proved. A porting diff must resolve each removed/changed guard in its affected modules. Generic family assignment alone does not authorize its deletion. A discovered additional semantic refusal extends this inventory before the affected layer passes.

`RF-Tnn` are planned new-format oracle IDs, not existing or passing test functions. Source pointers without a directory prefix refer to `src/hv2ref/`. Reuse existing `test_ordinary_work`, `test_trial_usability`, `test_general_work_recovery`, `test_worktree_integration`, `test_umbrella`, `test_continuation_recovery`, `test_local_delivery`, `test_official_faults_v2`, `test_official_recovery`, `test_productization_safety` and platform suites by their applicable behavior, not by unchanged implementation bytes.

## Intentional replacement, not silent removal

- Exact trial Python patch/profile/window names: retire as public user requirements. Retain verified runtime identity and capability eligibility; a managed slot must supply the qualified runtime. Source-development guards remain explicit and separate.
- Primary-only mutation and project-local authority files: replace with shared authority + registered workspace identity. Never generalize this into “every linked worktree is trusted.”
- Flat 4 MiB manifest and candidate-file limits: replace with typed/paged storage and explicit C3 budgets. Keep early size refusal, bounded readers and no partial publication.
- Multi-file authority rename/current-pointer checkpoints: replace their mechanism with SQLite atomic root publication and external-effect journals. Preserve crash/unknown-effect oracles; injected crashes are tests, not user requirements.
- Full graph scan before every query: replace with selected closure verification and explicit full audit. Never hide corruption in the accessed closure or use a cached label to certify a decision.
- Old format migration and profile transition chains: no compatibility obligation. First-public schema/capability compatibility and retention are mandatory new tests.
- Token/rule/path exposure and duplicate approval friction: not protected behavior. Internal receipt binding stays exact; user sees a short reason only when a new decision is actually necessary.

No row retires scope protection, exact-result acceptance, unresolved-effect refusal, controlled tool access, user-file preservation or signature/identity verification. Existing unaccepted usability changes are tracked separately from the accepted safety baseline; a frozen dirty-tree fixture alone is not proof of accepted semantics.

## Implementation gate

Before porting each layer, freeze expected success/refusal/state invariants using the applicable old fixtures. For each changed guard, retain it, consolidate it under a named new check, or retire only its obsolete mechanism with a written reason. Add the RF-T oracle and C1–C8 cases; record old/new result evidence. Existing green tests and a reviewer verdict do not replace Owner acceptance or qualification of a new installed path.

Inventory preparation is complete at the stated static scope. Semantic port verification, fault execution and native platform qualification remain implementation work. Unexpected permission errors remain unavailable evidence, never passes or motivation to broaden permissions silently.


## R3b preservation and replacement details

Protected opaque representation deliberately replaces the blanket regular-only enumeration/index/manifest checks (RF-02/04/06/13), not path/identity/scope protection. Accept unchanged qualified symlink/gitlink entries; refuse their additions, deletions, type changes, selected edits, opaque ancestors, unsafe native representations and unsupported index flags. Special devices, multiple links and unknown types remain rejected. Cover submodule ignore overrides/policy drift, nested submodule refusal and Windows emulated symlink before qualifying those paths.

RF-27 reuse pointers: `tests/test_official_s1b.py` tests for nested JSON escapes/identifiers, preserved context, boundary joins and late effect. Driver checked `safe_text`: it detects credential-like strings and non-approved identifiers but does not decode nested JSON. The exact decode path is `official_adapter.py: RPC.send`, which parses the tool-result text as JSON and checks its decoded value, including JSON Unicode escapes. This is not arbitrary recursive or repeated escape decoding. `checked_payload` preserves depth 16, 4,096 nodes, bounded containers/queues, finite permitted integer range, string keys, restricted controls and default 65,536-byte bound; context/assembled-output bounds remain explicit.

Before CLI permission/start, inspect retained prefix/suffix context; before writer effects, inspect the complete new output. A refused frame emits no new bytes; prior delivered counters and applied effects are retained. Rejection responses use fixed reasons, without rejected source content or its hash in run/journal/evidence logs. In the actual-boundary fixture, one callback reservation may exist, but no recovery-ready event, no write effect and original bytes unchanged; do not incorrectly promise no reservation at all. The late-result fixture ends interrupted with earlier applied effect retained. Pattern misses/false positives remain limitations. Approved body storage is a separate deliberate retention feature, not the rejected-payload log.

Generation fences/activation (RF-03/06/18/23/24), immutable semantic order and deep-history import (RF-06/07), and qualified Git lock recovery (RF-13) are required negative oracles from C2/C4/C6. Existing source and original failure evidence are retained; this map does not claim the new implementation has passed them.
