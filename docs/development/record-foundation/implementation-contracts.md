# Detailed implementation contracts

Status: Driver design decisions following R3b and the three Owner policies, 2026-11-06. See the [R3b disposition](review-r3b-disposition.md) and [initial implementation proposal](implementation-start.md). No format is active and no installation or host permission has changed. This document closes the algorithm/protocol choices in [design](design.md); it does not report implementation or platform qualification. [Refusal map](refusal-map.md) and [implementation plan](implementation-plan.md) are part of the same specification. Review findings remain preserved in their original files.

The compatibility boundary is the first public release. No import of pre-public trial records or profiles is required. New public records, bodies, settings, decisions and feature selections must survive supported update, recovery, detach and restore. Ordinary acceptance records a decision about a submitted result; applying content elsewhere and creating a Git commit remain separate operations.

## C1 — Project identity, location and access

- A project has one logical authority, stored in the user's OS data directory: macOS `~/Library/Application Support/Colvia/authorities/<project-uuid>/`; Windows the known-folder LocalAppData equivalent of `Colvia/authorities/<project-uuid>/`. Resolve the OS known folder, not an untrusted environment variable alone. The authority contains one active store generation, a small versioned active pointer, and retained recovery generations only as needed. Each generation has a unique, never-reused directory `stores/<generation-id>/state.sqlite3` and its own SQLite journal namespace. Store generation is distinct from project/workspace identity, authority-instance UUID and binding epoch. Never replace or unlink an open database at the same path; use the generation activation protocol in C4. It is not inside a checkout, Git metadata or a runtime slot.
- Connection metadata is a bounded, versioned locator, not a credential: `project_uuid`, `authority_instance_uuid`, `binding_epoch`, `binding_nonce`, `locator_version`. Git common-dir `colvia/connection.json` identifies the project and must not contain one shared workspace UUID; resolve the specific workspace from its verified root/gitdir identity and authority registration. A non-Git root uses `.colvia-link.json` with its additional `workspace_uuid`. Creation/removal of locators occurs only in an explicitly authorized connection operation; read-only discovery does not write them.
- Store the registered canonical root/common-dir identity, per-workspace identity, epoch and nonce inside the authority too. Verify path ancestry, actual filesystem object identity and current Git worktree membership, rather than trusting copied locator bytes. Same common-dir linked worktrees share a project but have different workspace IDs. A nested app worktree is a boundary only after this proof. An unregistered, stale or foreign nested repository is not silently excluded.
- A moved root requires explicit rebinding with the expected authority generation, retirement of the previous binding and new nonce/epoch in a transaction. Missing old paths do not prove a move. A copied root at a different location refuses writes; explicit fork creates a new project/authority. If two copies still claim one registered path, identity mismatch or concurrent generation change refuses. These are accidental-copy protections, not security against a hostile owner able to rewrite the whole database.
- Permit a host only the specific authority directory and the runtime paths it needs. Ordinary Work needs authority writes, not Git metadata writes. Connecting or Git integration can require separate Git-directory permission. Do not silently broaden the host sandbox. Explain a missing permission with the action and narrow path, without making the user repeat a valid task approval. Actual permission persistence/inheritance is an installation qualification gate. If a locator is lost (for example by cleaning an untracked non-Git marker), authority data survives; explicit reconnect can identify its registered root, never create replacement empty history silently.
- A restore retains historical project/Work/submission IDs but creates a new local authority-instance binding. Activating it at an already connected project requires retiring the old instance and invalidating old sessions. Import never merges two writable live authorities or silently reattaches an old locator.

The first connection unit is a verified Git workspace root or an explicitly selected non-Git project root. Invocation inside a connected root may resolve that root without changing the Work's approved path scope. Independent monorepo subproject connections are deferred. Same-project verified linked/app worktrees can resolve read-only; register their distinct workspace identity only on the first authorized mutation, rechecking membership/generation. Do not auto-commit missing agent entry files; explain entry propagation to new worktrees. Copied/foreign roots do not display original history as current.

Detect Git/non-Git identity transitions separately from missing executable or denied metadata access. Block stale-binding writes, retain the OS-data history and offer explicit reconnect/new connection with historical identity preserved for inspection/export. No silent empty-history replacement or automatic active-Work rebase. Detailed scope and follow-ups: [connection boundaries](connection-edge-scope.md).

C1 checks: primary/sibling/nested worktrees; independent clone/copy; non-Git copy; move with original present/absent; replaced symlink/reparse ancestor; stale nonce/epoch; missing authority permission; concurrent connection; detach and explicit reconnect. No project copy alone may redirect another project's writes.

## C2 — Paths, entries and the canonical tree

Logical paths are UTF-8, NFC-normalized, relative and slash-separated. Reject absolute/drive/UNC forms, empty components, `.`/`..`, NUL, control characters and invalid UTF-8. Canonical path length is at most 4,096 bytes; a component at most 255 bytes. Native spellings and platform identities belong to an observation record, not the content-tree hash. Never rename a user's path just to normalize it.

Enumerate actual entries without following links. Collapse Git and filesystem spellings into one logical entry only when they designate the same observed native entry. Distinct entries mapping to the same NFC key refuse. Also refuse detected case aliases; Unicode casefold is a conservative collision check, not proof of filesystem equality. Revalidate native handles/ancestry on use. A name valid on one platform may remain readable in history on another while materialization there refuses (reserved names, trailing spaces/dots, path limits).

Entries are a versioned discriminated union: regular content retains path/mode/size/body digest with modes 100644/100755; a protected symlink uses mode 120000 and exact target-string byte identity; a protected gitlink uses mode 160000 and an algorithm-tagged Git commit OID. Opaque links do not imply preservation or approval of their referent/submodule contents. Regular bytes retain encoding, BOM and line endings. No implicit executable-mode conversion or link traversal.

Opaque entry addition, deletion, mutation or type conversion refuses even within approved paths. A selected path must be regular/absent as permitted, with no opaque ancestor or directory/file conflict in the relevant source tree, destination HEAD/index/working tree. Recheck native ancestry at use. Unchanged opaque entries may remain in a complete tree/index; editing/materializing them is unsupported. Unknown kinds, special devices, multiply linked content and unqualified reparse points still refuse.

For the first implementation, an initialized gitlink boundary must be topology-verified and clean before starting and submitting. Compare checkout HEAD and tracked/untracked changes with fixed overrides that cannot hide dirt (`--ignore-submodules=none`, explicit untracked enumeration, optional index refresh/fsmonitor disabled); pin relevant submodule config/ignore inputs. A changed policy, init/deinit, dirty state, unknown observation or nested submodule refuses. Do not fetch/init/reset a submodule. An absent/deinitialized boundary has an explicit state; an unregistered nonempty directory is not absence. Ignored content is outside this limited boundary claim. This is protective coexistence, not submodule editing support.

On a qualified Windows Git checkout, mode 120000 materialized as a regular file under core.symlinks=false is an emulated link: compare its target-string bytes and forbid edits as opaque changes. Native symlinks require qualified type/target evidence; junctions and unqualified reparse representations refuse. A non-Git Windows reparse point is not guessed from its display name. Binary-document support remains byte preservation, not semantic editing of every format.

Object references are `{kind, version, byte_length, sha256}`. Hash preimage is a fixed ASCII product-domain/version prefix, unsigned 16-bit big-endian kind byte length and ASCII kind, unsigned 32-bit big-endian object version, unsigned 64-bit big-endian payload length, then exact canonical payload bytes. Body chunk bytes are raw; typed metadata is UTF-8 canonical JSON: sorted keys, two-space indentation, one terminal newline, finite integer values only, no duplicate keys. Do not reuse this serializer for signed update metadata governed by its own standard.

Dependencies use a generic versioned envelope of `{role, ref}` edges. Fixed v1 roles are decision, integrity, provenance and display. Each `(kind, version, field)` has exactly one role; wrong/unknown roles refuse. Operation validators declare a static required-closure table and validate it against the field schema. Writers/importers cannot demote a required dependency by choosing another label. These rules are shared across commands, not heuristic per-agent decisions.

Known typed payloads reference other objects only through validated envelope edge indices. Validators reject authoritative raw references outside that envelope; raw chunk bytes are not scanned for reference-shaped text. Unknown optional kinds must still expose generic dependencies to preserve lossless export; their hidden semantic references cannot be proved absent, so conformance tests and required-feature declarations remain necessary. Only a known parent schema may permit skipping unknown optional display/provenance for a specific read. Unknown required reader/writer capabilities refuse that operation; unknown extensions are never silently erased by a write or export.

Semantic order (current decision, supersession, ordered display) lives in hashed edges/sequence fields or root-map heads. Local creation ordinals are derived, excluded from identities/exports and reassigned after import graph validation. Different valid import traversal orders must produce the same semantic state. Import/full audit uses iterative, disk-backed graph validation with explicit total-resource preflight and bounded pages, not the depth-64 selected-decision limit. A valid deep provenance history is not corruption. Export/restore budgets and capability requirements must align; resource exhaustion leaves the original store intact and reports unavailable.

For a complete set S of unique entries, define `Node(S,d)`:

1. Sort by canonical path UTF-8 bytes. Encode the complete leaf with its kind/version and entries.
2. If count is at most 128 and encoded length at most 4 MiB, return that leaf. The empty tree is the empty leaf.
3. Otherwise, if d equals 8, refuse overflow. Partition S by byte d of SHA-256(path UTF-8); omit empty groups; recursively encode each child at d+1. A branch contains sorted numeric bucket keys and exact child references.
4. Incremental insert/delete must produce exactly the same root as reconstruction from the full resulting set. Collapse a branch whenever its complete descendant set qualifies as a leaf. Do not base shape on insertion order, cache contents or current node occupancy alone. Pin the logical-path normalization/version in the format; a runtime Unicode-table change cannot silently redefine existing keys.

Readers verify kind, version, size, digest, ordering, unique paths, bucket prefix, depth and total budget. Unknown required kinds/fields refuse; an optional display extension may be skipped only if it is outside every decision dependency. This format is not activated until reorder/delete/rebuild properties, normalization collisions and injected hash-prefix overflow tests pass. Hash injection is a test-only seam.

## C3 — Store, bodies, limits and recovery

Use SQLite 3.37 or newer with an explicitly qualified bundled version; require foreign keys, `journal_mode=DELETE`, `synchronous=EXTRA`, and macOS `fullfsync=ON`. Check actual settings after opening. With DELETE journaling, require the extra journal-unlink durability step rather than assuming FULL plus file sync covers directory persistence. Qualify the actual VFS/filesystem; no universal power-loss guarantee is inferred from a pragma value. [SQLite synchronous modes](https://www.sqlite.org/pragma.html#pragma_synchronous) Do not load extensions or accept arbitrary SQL. Schema/integrity checks and reference/content hashes serve different checks. Hot-journal recovery is `recovery-required`, not automatically `corrupt`. A read-only command that cannot recover reports this distinction without changing permissions.

Published objects are immutable. A single root record points to persistent maps of Work/intent heads, candidates/follow-ups, workspace registrations, settings, capability selections, archive visibility and lifecycle state. Update the affected maps and root generation in the same transaction; normalized SQL indexes are rebuildable projections checked against that root. Do not add a second source of authority. A short read transaction pins this complete root, after which immutable closure reads can be paged without keeping one long reader lock. The persistent key maps use a separately fixed radix-16 trie: consume SHA-256 key nibbles from most significant to least significant, leaves contain at most 16 keys, depth is at most 16, and the empty map is a leaf. Canonical reconstruction and collapse use the same rule as incremental updates. This bounds repeated head/operation-map path copies; it does not change the byte-radix file tree defined in C2. These new-format primitives remain unactivated and have no legacy-fixture compatibility promise.

Body ingestion stages chunks of at most 1 MiB under an import ID. Batch at most 4 MiB of raw chunks and at most 64 chunks per short staging transaction; end the batch when either bound is reached. Keep bounded buffers and measure transaction/reader latency. Never combine a whole large import into one transaction or weaken durability to meet a timing goal. Descriptors list ordered chunk references, total length and whole-body digest. Publish a descriptor and the referring result/head only after all chunks and expected Work/workspace state are revalidated. A crash before publication leaves unreferenced staging, not a result. Maintain many-to-many chunk/import claims transactionally. Repair may remove abandoned staging only when no live import claim or published reference uses it; elapsed time alone does not prove abandonment. Published objects are not automatically pruned.

Every transaction verifies its immutable generation identity and retirement fence; paged reads recheck at each page and before reporting current state. Stale generations refuse rather than continuing through an old open handle. Each write uses `BEGIN IMMEDIATE` and rechecks the fence, expected heads, authority generation and relevant observation before mutation. An unrelated Work advancing the common root does not imply the target Work changed: rebuild against the latest root only if all target heads and shared dependencies still match, otherwise refuse. No lost updates. Scope overlap still requires scheduling; this is not authorization for parallel agents editing one workspace. The v1 root also contains an immutable operation-ID map and its publication operation ID. SQL operation lookup is a projection checked against that map; a missing projection must not make a completed operation eligible for replay. Within one process, coordinate transactions on the same store inode with a bounded local lock; preserve read-only open mode and SQLite inter-process locking. Subtract local acquisition time from the SQLite acquisition budget. This does not hold a store transaction during full-body hashing or export.

Busy acquisition is bounded to five seconds per operation, with no unbounded retry. Do not kill an in-progress commit merely because a duration threshold elapsed: classify ambiguous completion by reopening and checking expected root/operation ID. Record chunk-transaction and concurrent-reader latency separately; transaction size alone is not a latency guarantee. Qualification must show bounded failure and progress under a large import, disk-full, sync error and interrupted writer.

Initial engineering guards (not public capacity claims):

| Item | Limit and consequence |
| --- | --- |
| Typed metadata object | 4 MiB encoded bytes; refuse before publication |
| Command metadata input | 16 MiB; reject before parsing unbounded input |
| Approved body | 256 MiB per file per version; 1 GiB combined before+after bytes per submission, counting repeated files before deduplication |
| Tree | 1,000,000 entries; 512 MiB decoded entry metadata per observation; trie depth 8 |
| Reference validation | Graph depth 64; up to 1,000,000 references and 512 MiB metadata per bounded decision traversal; exceeding a budget is unavailable, never partial success |
| Streams | Bounded chunk buffers; full audit/export page at a pinned root, reporting explicit budget or storage exhaustion |
| Total retained history | No advertised maximum until measured; disk-space preflight is advisory and all writes still handle ENOSPC |

The combined body bound resolves the earlier ambiguous phrase “submitted bodies”; it is a draft guard, not a reduction of a published promise. Test below/at/above every effective bound. Wide graphs and cycles require separate tests. A large history may be paged/exported without pretending a truncated decision dependency passed validation.

## C4 — Backup, restore and compatible updates

Logical export is the official backup unit. Format v1 is a framed stream: fixed magic/version, bounded canonical header containing project ID/root reference/format requirements, then object frames (bounded kind/version/length/reference and exact bytes), ending with a manifest of object count, preceding-frame total length and SHA-256 of all preceding stream bytes (not the final manifest itself). Order is deterministic by kind/version/digest; duplicate references with conflicting bytes refuse. No filesystem path from an export controls an extraction destination.

Export pins the complete C3 root. It includes all reachable published bodies, decisions, settings, feature selections, workspace metadata and archive/follow-up links. Exclude active staging, machine credentials, host allowlists and private signing keys. Export of active/incomplete executions preserves their unfinished evidence; it cannot certify them closed. Verify full reachability, counts and hashes before reporting backup complete. Export to a caller-chosen durable destination, publish the output atomically, and report failures without replacing the last valid backup.

Restore validates the whole stream in a new unpublished store, checks required reader/writer versions and every reference, then performs explicit local rebinding under C1. Active executions restore as interrupted/unavailable until reconciled, never auto-resume external effects. Required historical kinds remain readable even when their execution capability is disabled. Unknown mandatory kinds or newer write schema refuse activation; they are not dropped from a converted export.

A compatible product update changes the verified runtime binding, preserving data/settings/decision meanings. Before a schema-changing update, require a complete verified export and recovery plan; quiesce affected writes, migrate to a separate store, validate it, then activate one binding. Old-runtime rollback is allowed only if it can read and write all active requirements; otherwise restore the pre-update checkpoint into a separate instance and explicitly account for newer data. Never erase post-update decisions to make a rollback pass. The first release tests synthetic compatibility/migration boundaries; it does not invent a future migration implementation.

Generation activation protocol (also required when individual body removal is absent):

1. Under an authority-scoped lifecycle exclusion, record an operation ID, old/new generation IDs, expected old root and active-pointer preimage. Establish a writer-quiescent state in the old store; unresolved execution effects block activation. This is a lifecycle state, not proof that an external side effect completed. Obtain or build the new store at a fresh generation path and verify the complete pinned source state and target requirements. No writer may advance the source unnoticed during this copy.
2. Record the validated target and activation intent durably, then commit the old store's retirement fence against the expected source root. Cooperating old writers are serialized by SQLite and must recheck this fence. Wait for registered in-flight operations according to bounded lifecycle policy; unknown liveness is not permission to retire files. Pending readers cannot carry a page from an old generation into a new-generation decision.
3. Atomically replace/sync only the small active pointer using the qualified platform primitive and expected generation check. New operations verify pointer, project/instance identity, generation marker and fence. Never rename a new DB onto an old DB pathname. Keep each DB with its own journal namespace. If pointer durability is uncertain, report activation pending and inspect the recorded operation, not directory order or newest timestamp.
4. An interruption before fence leaves the old committed generation usable after explicit lifecycle recovery. After fence but before pointer publication, normal writes remain blocked; recovery may complete only the recorded validated activation after exact checks. No silent un-fencing or fallback to an older writable generation. After pointer publication, confirm the new store before recording completion. Rollback that could lose newer decisions remains a separate C4 operation.
5. Old-generation retirement/deletion is separate from activation. Keep required recovery copies and any generation with live or unprovable users. Windows sharing failures leave retirement pending. Do not call pointer activation secure erasure, archive, or completion of body removal.

P1 fault fixtures cover every activation boundary, old readers/writers, hot journals, stale pointer and concurrent activation; P7 reuses them for real restore/update orchestration. Actual Windows/macOS durability and handle behavior need platform qualification. These guards assume conforming Colvia writers, not a hostile process with arbitrary DB access.

Owner has selected continued retention with explicit notice for the first release: no individual body-removal UI/command/overlay in v1. If later adopted, a required capability/schema migration must preserve prior record meanings; old readers may safely refuse the upgraded store. This is data-preserving evolution, not a promise that old runtimes can continue using it.

Detach removes integration/receiver connections, not authority data. Runtime uninstall and explicit project-data deletion are distinct actions. Keep active, in-use and required last-recovery runtime slots; two slots is not an unconditional cleanup maximum. Archive preserves query, historical bodies, decisions and follow-up links.

## C5 — Observation policy and D1/D7

Freeze admission policy inputs with origin and order: relevant Git configuration, ignore source bytes, per-rule occurrence positions, structural registry, resolved Git executable/version and observation root. Never persist a dump of unrelated Git config or credentials. Rule identity is `(origin, file_digest, occurrence_index)`, so duplicate text is not ambiguous.

Three separate decisions:

1. Historical result agreement compares its exact recorded path/mode/body to the specified workspace. It does not revoke history merely because ignore policy changed.
2. Ordinary submission protects the complete baseline membership and compares the new admitted tree. The previous verified structural registry is part of that baseline; adding a worktree cannot silently remove previously protected content. Previously admitted files remain protected even if a changed policy would now hide them. Out-of-scope changes refuse; a narrow report view does not narrow this protection.

   A narrow ordinary-rework exception may retain a flat proof of regular additions from other submitted Works while keeping the original baseline and scope intact. See [rework contract](rework-context.md) for the exact admission, protection and compatibility rules; general external baseline changes remain deferred.

3. Automatic D7 equivalence is intentionally narrow: old policy inputs are unchanged except appended literal directory exclusions in root Git `info/exclude`, without glob, escape or negation. Resolve Git's actual root-relative semantics, not just a leading slash: the observed `.claude/worktrees/` has an internal slash and denotes that root-relative container. Retain the raw rule bytes and interpreted path separately. [Git pattern rules](https://git-scm.com/docs/gitignore#_pattern_format)
4. The excluded path must be either one verified registered worktree root, or a verified container whose immediate entries, including hidden entries, are all current registered worktree roots of the same project. Do not accept regular files, links/reparse entries, foreign repositories, unregistered directories or ambiguous ancestry. Do not exempt `.claude` wholesale. A previously verified container may remain empty after its last child is removed; stale child registrations must first be reconciled in Colvia's authorized registry, without implicit Git worktree prune or metadata writes. Empty arbitrary directories are not automatically structural containers. An absent former container has no current exclusion effect and needs fresh proof when it reappears.
5. No baseline tracked/protected content may be swallowed by this classification. Verify the container listing, child identities, Git registration, policy and previous structural baseline before publication. Repeat structural proof at every relevant observation, even when exclude text has not changed; a later unregistered sibling must stop the operation. A prior empty-container pass is never a permanent allowlist. Unstable listing or insufficient visibility is unavailable, not equivalent. Other policy changes use the explicit policy-edit path below.

An app-added pattern that fails this proof stops submission with a short explanation. It does not become trusted merely because an app wrote it. Deleted/reordered rules, negation, changed global-ignore origin, ancestor wildcards, hidden new paths and orphan registrations are negative cases. Enumerate/check affected namespace including ignored paths without following links, bounded by C3; an inconclusive traversal refuses. A trusted structural boundary itself may be pruned only after current identity/membership proof.

Editing an ignore file can be a legitimate approved Work. Declare the policy-file change in its plan, retain old and proposed policies, and protect the union of old and new admitted membership plus all approved paths. Compare membership changes explicitly, including newly hidden files; freeze that union for the submission. Publish the new observation policy only for subsequent work, never retroactively remove checks from the current result. A user statement alone does not prove no hidden edits exist. If complete bounded union observation is unavailable, stop and explain before accepting the policy edit.

Changing a branch or running pull is not itself a universal refusal: assess actual identity, policy, admitted bytes and validation dependencies. Required scope/decision drift stops submission with the relevant changes. Do not silently replace the baseline or label unattributed changes as someone else's work. Preserve current files and old evidence, and offer a reviewed correction or separately approved new Work. An old blocked Work does not become accepted by creating a new one. Same-Work baseline advancement is deferred; no automatic reset/stash/checkout or global-ignore restoration.

## C6 — Git integration protocol

This operation creates a commit from a separately reviewed candidate; ordinary result acceptance does not write Git. Applying another workspace's content uses the existing worker preimage/postimage contract first, in the destination workspace. Source acceptance is not destination integration approval.

The candidate is the destination HEAD tree with only the selected accepted paths/modes/bodies applied. Show the resulting commit diff, parent, target ref, selected results and exclusions. In the credential-screened Git path, withhold previous file contents when the previous path is protected, the blob contains a recognized credential, or it cannot be inspected. Identify the file and its deletion or reviewed replacement. Bind this exact display to the candidate; never journal the raw sensitive patch. Unrelated staged changes stay out of this commit and remain staged afterward. For a selected path, current index content must equal either its HEAD version or its accepted version; divergent partial staging refuses rather than losing the user's staged selection. Unrelated unstaged content is preserved. Current selected working files must match the accepted result before committing; do not commit an old body while claiming it is the current file.

Require one verified attached destination branch, no other worktree checking out that branch, no unmerged index, and no unsupported sparse/split index, LFS/filter/eol transform or partial-clone/promisor dependency in the operation. An unborn branch is supported only by an explicit absent-ref CAS path tested separately. Git hooks must not be silently bypassed: if enabled hooks are present, refuse automatic integration and explain the manual Git path. For a verified hook-free operation, pin an empty private hooks directory to prevent a hook appearing between checks. Disable optional index refresh, fsmonitor and external diff; use bounded plumbing and an isolated index, never assume plumbing itself is hook-free. Resolve relevant config once and recheck its identity before mutation. No fetch or hook execution is implied.

Unchanged protected 120000/160000 entries and supported index flags are preserved; changed opaque entries or selected paths below them refuse. Verify parsed entry/flag preservation and final I1 bytes, not per-entry binary offsets that may change with index serialization. Unsupported index representations still refuse.

Protocol, with exact index bytes and content retained for recovery:

1. Verify authority/workspace/topology/config. Build objects and private candidate index without touching the live index. I1 keeps all unrelated staged entries from I0 and sets selected paths to the candidate versions, preserving supported index flags; unsupported index extensions refuse. Git object writes still need explicit Git write access. Record prepared operation ID, expected old ref O, new commit N, tree, full index preimage I0, intended index I1, symbolic HEAD and working-file preconditions.
2. Persist lock-creation intent (operation ID, target, nonce) before exclusive creation; then record file identity and process-start identity as ownership evidence. Intent alone is not ownership. Acquire the destination Git index lock without replacing an existing lock. Recheck I0, HEAD/ref, other-worktree membership, relevant config and selected working files. Save a durable prepared record before ref mutation. Do not hold a SQLite transaction while waiting on external Git.
3. Compare-and-swap the ref O→N. Record the observed ref phase. Recheck symbolic HEAD/ref and working-file assumptions before replacing the index with I1 through the held index lock. A mismatch stops with partial/unknown status; it does not authorize a rollback or index overwrite.
4. Durably replace the index, then compare exact index bytes with I1 digest and verify ref/selected working files; publish completion in the authority. Content was not rewritten by this commit operation. Persist exact operation identity for idempotent inspection.

There is no atomic transaction spanning SQLite, Git ref, index and external editors. Cooperation with Git locks reduces races but is not protection against an arbitrary process ignoring them. If another actor races, preserve evidence and refuse a completion claim unless all postconditions hold.

| Observed ref/index after interruption | Classification / allowed next step |
| --- | --- |
| O / I0 | Not applied; leave intact. A future attempt needs current preflight. |
| N / I0 | Ref changed, index incomplete. Explicit recovery may finish only after exact identity, ref, preimage, topology and working-file checks. |
| N / I1 | Commit/index postconditions reached; validate remaining evidence, then record completion idempotently. |
| O / I1 | Inconsistent; no automatic ref/index change. |
| Any other ref/index, including descendant of N | External divergence or unknown; no automatic index repair, rollback, or success by ancestry. |

Every recovery row also records index/ref-lock state: absent, proven owned, unproven or replaced. For a proven abandoned index lock, use one recovery route: preserve evidence, verify exact identity under lifecycle exclusion, remove, exclusively reacquire, recheck all C6 conditions and write I1. Unknown process liveness counts as potentially live. Intent-only, external or replaced locks are never automatically removed; explain the lock and missing proof without implying that age proves safe deletion.

Git child-process ref/HEAD/packed-refs locks are separately reported and never auto-deleted. Bounded cancellation must establish process identity/closure or retain unknown effect; timeout alone does not mean the ref update failed or authorize rerun. Do not adopt indefinite waiting as the alternative. Windows index replacement failure uses no automatic retry in the first implementation: if I0/ref state and our lock identity remain provable, release only our lock and report N/I0 for explicit recovery; otherwise preserve unknown evidence and stop. No blind ref rollback. Add abrupt-death, ref-child lock, replaced-lock, live/PID-reused owner and Windows sharing-failure fixtures.

Full binding/config and selected working-file admission is required before the ref changes. Once the exact candidate ref is visible, completion verifies the recorded destination, ref, index identity/bytes/mode and retained objects; later working-file edits remain unstaged and are not overwritten or accepted. Such edits invalidate a current-file agreement claim, not completion of the already approved index transition. Inject interruptions at every durable boundary, including after ref change but before its DB phase, and after index change before completion. Preserve index preimages and original failure records. Same Work in another workspace is never silently selected by title.

## C7 — Managed runtime and host entry

One per-user managed entry serves CLI and desktop. Its verified slot binding selects product, dedicated Python and SQLite; PATH/pyenv is not a fallback. Git is separately resolved to a qualified executable/version and checked configuration context for Git workspaces and Git operations. A verified non-Git folder must support ordinary Work, retained bodies, query, export/restore and detach without installing Git. Detect ancestor Git markers and ambiguous topology without silently treating a Git checkout as non-Git when the executable is missing. A Git operation with missing Git receives an actionable prerequisite message without launching a developer-tools installer during diagnosis.

A platform bootstrap starts installation or update with one command before any dedicated Python is available, obtains the verified manager/runtime/payload, selects a compatible channel/architecture, stages and checks them, then changes the binding. The user does not provide a Python ZIP, hash or internal profile. Separate first installation from later updates: a thin first-install shell/PowerShell or existing native stub can acquire a fixed manager-plus-runtime bundle from the official HTTPS entry, verify its pinned length/hash, and launch its packaged verifier/root. The fixed hash does not independently authenticate a compromised bootstrap channel. That initial bundle is explicitly the first-install trust assumption in C8. On an existing installation, the already trusted manager verifies signed metadata before executing any newly fetched manager/runtime. Re-running the one-command entry must not silently route an update through the weaker first-install path or discard trusted counters. A missing/damaged manager uses the explicit authenticated repair path, not an automatic trust reset. This avoids requiring a new full macOS native updater without weakening post-install verification. Keep shell/PowerShell quoting, archive traversal, reparse paths, file modes and disk exhaustion in platform ports. Product/OS permission, notification consent and subscription login remain distinct human steps.

Test actual installed entries in a personal-Python-free environment, the four host forms, ordinary folder, linked worktree and registered nested app worktree. Verify actual executable/slot identity and required read/write paths, not just printed versions. Source execution is not this test. Targets are macOS ARM64 and Windows 11 ARM64/x64; support possibility and observed qualification are separate. Linux and future agents are later implementations behind current ports, not generic frameworks built now.

## C8 — Distribution trust and activation

Use a standard update-metadata verification contract rather than home-grown signature-plus-version logic: pin TUF 1.0.37 semantics for trusted root, timestamp, snapshot and targets; root rotation must satisfy old/new authorization, metadata freshness and rollback checks precede target download, and target length/hash bind the fetched bytes. Select and pin a maintained compatible client during implementation; do not write cryptographic primitives. The standard does not bootstrap initial trust or perform product activation. [TUF specification](https://theupdateframework.github.io/specification/latest/)

Colvia-specific design defaults: initial bootstrap/manager is obtained over the official authenticated HTTPS distribution entry and contains the trusted root. This first-download channel is an explicit trust assumption, not a detached-signature guarantee from a secret source. Root keys are offline with a proposed 2-of-3 threshold; targets authorization is separate from online freshness roles. Key custody, actual domain and production key IDs are release-operations inputs, not values generated by this specification. Owner acceptance of the final release procedure is required before creating or publishing keys.

Signed target metadata binds product/build, OS/architecture, exact runtime dependency identities, store/protocol/capability requirements and channel. Keep trust roots, rotation chain and highest trusted metadata versions outside replaceable runtime slots and preserve them during authenticated repair; suspicious backward clock movement stops updating with clock guidance. Expired metadata blocks updates, not running an already installed compatible version. An authorized older product target can appear under fresh signed metadata; its activation still requires format/capability compatibility. Do not lower trusted metadata counters to roll back product code. Lost root trust requires an explicitly authenticated replacement installer, never an ignore-signature option. Freshness renewal needs a scheduled release-operations job independent of product releases, expiry monitoring and an outage procedure; configuring that service is not authorized here. Longer expiry trades outage tolerance against freeze detection and is not a free fix. Root/targets custody and automated online freshness roles stay separate. P7 includes renewal/outage fixtures and the operations procedure.

No paid signing membership is assumed. OS code signing/notarization and SmartScreen/notification prompts are separate from update metadata trust. Final validation must use the actual distribution entry and shipped trust root. Offline fixtures verify invalid signatures, rotation, expired/replayed metadata, mismatched dependencies, download failure and interruption; fixtures do not qualify the public channel.

## Closure and evidence

C1–C8 resolve the detailed design choices, not their implementation. Exact package version, production keys/domain, real host settings and performance bounds remain observable implementation/release gates with named owners in the plan. They cannot be silently substituted with prior source-only successes. Preserve existing measured failures; test-derived corrections update this contract before any public format activation.


## Bounded long-term use — final direction check

These clauses clarify existing C1–C7 requirements; they add no scheduler, data pruning, background service or new storage tier.

- Query locality is explicit. A selected Work read verifies the root/map lookup path and current required result/decision dependencies. A historical parent link is provenance, not automatically a demand to recursively read every earlier result or every other Work. Use the C2 fixed edge-role/required-closure rules and derived local ordinals; writes validate referenced object kind/identity and ordering, imports/full audits validate the complete reachable graph. This does not permit skipping a dependency actually needed for the decision. Pagination and optional history expansion must not turn an ordinary status query into a full-history audit. Keep default display budgets separate from integrity budgets.
- Capacity remains per project, even though all authority directories are under one OS user-data root. A fixed number of database/journal files does not imply bounded database bytes. Body chunks deduplicate exact chunks only; shifted/recompressed binary documents may create mostly new chunks. Do not forecast compression or deduplication ratios without measurement.
- Provide a bounded storage summary: authority bytes, logical/unique body bytes, staged orphan bytes, recovery/export bytes and recent growth. Maintain accounting with the same committed state and distinguish an estimate from a full audit. Report low space before ingestion/export/migration when the bound can be estimated, and still handle mid-operation exhaustion. Failed writes leave prior committed truth accessible. Do not silently prune accepted bodies or make archive imply freed disk space.
- Bound export memory and cancellation; compute/stream over the pinned root instead of collecting every body into RAM. Report estimated output and required staging/recovery space. An interrupted export leaves the last valid backup usable. Pure read/list must not trigger whole-store vacuum, compaction, export or audit. A verified backup outside the live authority failure domain is required to recover from physical loss; a pinned root in the same DB is only a logical checkpoint.
- Full content observation remains proportional to admitted files/bytes where scope checks require it. Removing repeated graph/topology scans does not make a million-file tree cheap to hash. Show bounded progress/cancellation for expensive observation, stop without publishing on a limit or unstable snapshot, and never silently omit source files to meet a latency target.
- Move the narrow host-access and managed-entry smoke checks to the earliest usable P2 prototype. They are a feasibility gate before the full capability port, not a discovery left to P9. Reuse existing installed evidence only for unchanged paths. Required settings/install/model actions remain separately authorized; until tested, keep the gate visibly unqualified and do not claim seamless app support.


## Follow-up advice integrated before R3

- Windows qualification here means native Windows processes and known-folder paths. WSL/Linux CLI execution belongs to the deferred Linux target; no shared Windows-authority writes through Linux mounts are qualified. Identify a Linux/WSL process before resolving a native Windows authority, explain the supported native path, and refuse that unqualified cross-OS write. A native Windows executable invoked through WSL interoperability is a separate unqualified route until tested. Do not label every WSL filesystem broken or infer guarantees from path spelling alone.
- Where hooks or unsupported transforms prevent automatic Git integration, offer a manual handoff as a normal workflow. Show candidate scope and existing staged changes before proposing exact commands; never blindly recommend `git add .` or path staging that destroys partial staging. Hook execution can alter files or commit contents. After the user's Git action, inspect the resulting commit/tree before connecting it to an accepted result; a hook-induced change is not automatically accepted. If a safe command sequence cannot be determined, explain the remaining decision without executing anything.
- Query may show the last successfully verified export time/root and whether a newer root exists. Do not call a mere export attempt a backup, infer that its destination still exists, or promise off-device protection. Keep a short on-demand status; no external reminder, scheduled export or repeated chat warning is introduced.
- Body-removal policy is not silently activated. See [the decision proposal](direction-advice-disposition.md). Current accepted retention remains until Owner chooses an explicit exception. Missing bytes without the corresponding valid removal authority remain corruption/unavailability, never silently “redacted”.


### P1 implementation clarifications — 2026-11-07

For the v1 same-instance generation primitive, activation requires identical canonical logical roots, including operation history and all heads. `prepare_empty` does not authorize replacing an existing authority with an empty history. A future schema migration must prove a separately specified equivalent semantic state; the current primitive refuses a changed root. Restoring an older checkpoint uses the distinct-instance/rebinding contract in C1/C4, not this same-instance shortcut.

A synchronous publication validator reads mutable heads through a fixed-root validation view; every read head is added to the final CAS set. Reading the complete root adds a root CAS. Immutable object loads remain paged. Validators must not query raw SQL or start asynchronous reads. Operation-result projections are checked against the captured current root's immutable lineage, using short guarded transactions and explicit traversal bounds.

Explicit lifecycle recovery may ask SQLite to roll back a hot journal only for the exact persisted plan's store paths, under lifecycle exclusion and identity/pointer checks. It then reopens read-only and revalidates the plan; no writable retired application handle is exposed. A successful rollback after COMMIT BUSY is a known uncommitted outcome. Other uncertain commits retain their unavailable/unknown classification.
