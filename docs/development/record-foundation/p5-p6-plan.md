# P5–P6 execution and delivery integration plan

Status: authorized source bundle; grouped plan review completed; apply the [Driver disposition](p5-p6-plan-disposition.md) before each slice. No installation, real model turn, OS notification, new key or host setting change is authorized here.

## Retained user behavior

An ordinary agent can edit and submit a Work without the optional execution engine. Formal execution is separately approved, bounded tool-mediated document execution. It never accepts the Work. Handoff runs one approved step and makes its exact outcome discoverable. A notice opens that original outcome alongside current Work state; a click never approves anything.

Reuse P0–P4's typed immutable objects, one generation store, workspace registration, retained bodies, CAS and common effect fence. Do not create another authoritative inbox DB, capsule tree or old-format fallback. Old source is a behavioral oracle and a source of tested pure checks, not the authority backend.

## P5 boundaries

1. Extract the existing bounded payload checks, exact JSON decoding and pure execution event reducer into product modules with no old store imports. Keep finite integer, depth 16, 4,096-node and payload size bounds; retain credential patterns, unapproved home/email identifiers, preserved prefix/suffix and composed-output checks. A protocol path exception never disables credential checks. Rejected content and its digest do not enter diagnostics. This is not general PII protection.
2. Define typed execution grant, event, bounded history index, checkpoint and cancellation records. Grant binds project/instance/workspace, exact Work plan/approval/head, document views and input identities, one output range, qualified runtime/tool/policy identities, recovery identity, actor statement, deadline and one-turn/worker/callback budgets. Every field has a fixed edge role. Causal order is validated inside the required history index using stable event sequence and predecessor content identity, never an import-local ordinal. Do not create an unbounded required-edge predecessor chain that exceeds the existing graph depth guard. Work selection is a decision dependency. Required retained input/output data use body integrity edges, distinct from metadata-only rejected frames.
3. Preserve the reducer's causal floor: runtime reservation before spawn; process identity after spawn; admission before binding; exactly read, write, then named link/GFM/claim verifiers; recovery readiness before writer spawn; callback result plus verified closure before completion; complete terminal evidence before success. Missing PID/birth after a spawn intent is unknown, not a known launch failure. A completed run is not accepted Work content.
4. A store-backed journal validates each append against the current exact predecessor and grant and publishes through CAS. Bound reads load only the selected run history under fixed record/byte limits. Cancellation is an independent request head that the live runner checks before each admitted effect; it does not fabricate process closure or mutate the Work. Recovery/status never launch a process. Closed reconstruction cannot regain live capabilities.
5. Reuse native process observation, bounded termination and private recovery I/O through explicit platform ports. Keep the known macOS observed-process limits; do not claim hostile daemon containment or PID-identity certainty beyond measured evidence. Platform/runtime adapter capability checks occur before reservation. Unavailable capability is a concise refusal. Agent brand is confined to the concrete protocol adapter, not durable acceptance meaning.
6. Host checks source/document/runtime/recovery identity and approved scope before runtime launch and every callback. Control/runtime/project roots remain separated; model-provided paths, commands or broader tools are not accepted. Writer effects retain an original recovery copy and exact before/after observations. No blind overwrite, replay or automatic rollback. Existing optional bounded single-range document semantics remain the initial engine; no generic autonomous agent framework is added.
7. The common pending-effect selection owns the run while external effects/processes can remain unresolved. Work/planning/connection/lifecycle writers cannot bypass it. Delivery may own an outer attempt; a formal run launched by that attempt must bind its parent ownership explicitly rather than acquiring a conflicting second authority. Terminal metadata publication and release of the fence require evidence-complete closure; uncertain process or document state retains a blocked, inspectable outcome.
8. Existing RPC decoding checks occur on the actual encoded frame before the first sink write. A partially written frame latches transport failure and refuses later sends, including interruption; report earlier sent bytes/effects honestly. A late rejected response preserves prior applied document effects and ends interrupted/unknown as the reducer requires. No retry adds another turn or increases the grant.

The concrete app-server adapter may retain its qualified fixed runtime policy while the Core requires capabilities. Neither a local model nor an authenticated CLI alone qualifies a tool-running agent. Actual current-runtime/subscription execution is separate optional synthetic behavior budget, not a prerequisite for source fault tests. Retaining the existing concrete optional runtime adapter does not claim formal execution for every normal Work host; Codex and Claude ordinary agent access remain separate from formal engine capability qualification.

## P6 boundaries

1. Typed delivery request binds the exact Work/head, requested action (inspect, submit prepared result or execute approved grant), fixed input/result references, deadline, budgets, receiver identity if requested and human authorization. Explicit approval covering notification is not asked again. No automatic acceptance or next-work selection.
2. Exactly one outstanding protected handoff per project retains the old serialized safety floor. Request identity and attempt epoch are immutable references, not timestamps. CAS publishes queued/running/question/reconcile/finished/cancelled state. A runner acquires the existing project process lock before claim and verifies the store generation, request selection and dependency identity. Lost lease or late output cannot complete a new attempt.
3. Before an external side effect, persist its exact intent and attempt ownership. After an ambiguous failure, record reconciliation need and never dispatch again automatically. Pure inspection and post-effect outcome reading are distinct from repeating the effect. A user may cancel unstarted work; started cancellation requests must wait for verified closure/effect classification. Unknown cannot be labelled cancelled merely because a deadline passed.
4. Prepared ordinary submission is one exact publication, not a model turn; share Work validation and an explicit owned-effect continuation path. The inner publication and final delivery outcome must be recoverably correlated when one transaction cannot include the external execution. The engine cannot quietly invoke unrestricted shell commands as a fallback.
5. Notice event binds project/instance, delivery/attempt, original Work result and receiver capability version. Store the event in the same authority; an OS receiver index is a reconstructable routing projection only. Details independently resolve original submitted result and current Work state; changed/removed workspace or missing receiver gives bounded recovery guidance. Equal Work labels across projects cannot alias. No accepted state is inferred from a banner or click.
6. The original notice outcome is typed: an ordinary submission, a formal execution outcome or a bounded status snapshot. Showing a completed formal run does not invent a Work submission or acceptance. The adapter explains that difference; a subsequent ordinary submission still uses its approved scope and current-file checks.
7. Native notification emission is a port with exact bounded payload and process outcome. Source tests use a recording/failing double only. P7 packages and binds the actual installed receiver; actual banner/click qualification remains held. Historical immutable events survive receiver replacement and do not silently point at a newer result.

## Concrete authority records and ownership transfer

The new vocabulary is v1 typed records, not a promise to read private trial capsule v2. Reuse the pure causal reducer and exposure functions by porting them without their old file/journal authority imports. Brand-specific admission fields live in the concrete adapter's qualified capability record; the Core validates that exact capability and grant, not a provider name. Native process identity is an explicitly versioned platform observation, never an imported local ordering counter.

- `execution.grant`: run/work/workspace IDs, exact document IDs/views/limits, approved transmission statement and fixed capability requirements. Work plan/approval/selected head and workspace/runtime capability references are decision edges. Approved view bodies, runtime-resource identities and recovery manifest are integrity references. Do not persist rejected content, token bytes, raw account fields or arbitrary stderr. Prompt and approved transmission content are checked before retained-body ingestion.
- `execution.event`: run ID, semantic sequence, predecessor event identity, kind and exact metadata; grant is a decision edge. Events are never standalone decision roots. `execution.history` requires a persistent map of every ordered event reference; validate consecutive stable sequence, exact previous event digest and grant identity while replaying the whole bounded history. All events are required through the map, without a linear required-edge chain hitting the depth-64 guard. The previous history checkpoint is provenance only because the current map already contains every required event. Preserve the old 8,192-event/metadata byte bounds; no local SQL ordinal or missing event may establish causal order. A state checkpoint must match the reducer, including every admitted effect and closure. No unknown event is skipped.
- `execution.state`: exact grant/event head, optional parent delivery attempt, phase and derived outcome; the mutable key `execution:<run>` advances through CAS. `execution-cancel:<run>` records an exact cancel request without asserting effects stopped. A closed run cannot be restarted; retries require a new grant after fresh observations.
- `delivery.request`: handoff ID, Work/workspace/action/deadline/step limit/notice choice, exact selected Work and prepared operation or execution grant. Required dependencies have fixed decision roles. `delivery.attempt` names one request and unique attempt identity; `delivery.state` records its current phase and exact result/event refs. `delivery:<id>` selects it; a shared outstanding key enforces the retained one-handoff floor.
- `notice.event`: event ID and exact project/instance/receiver/attempt/Work/submission references. This is immutable authority data. OS route caches contain only checked lookup material, never acceptance decisions or alternate result truth.

A claimed delivery owns the common pending barrier. Starting its approved formal run atomically transfers that barrier to the child execution state with the exact parent attempt as a required dependency; the parent remains inspectable. Known child closure atomically returns ownership to that parent, then delivery completion publishes its outcome and releases the barrier. Unknown child execution keeps its barrier. Late runners must match both current attempt and current owner; a parent cannot clear an unresolved child by declaring itself finished.

Prepared ordinary submission uses a narrowly validated delivery-owned publication path: the current pending record must be that exact delivery/attempt, its action must be submit, and Work/head/scope/prepared result must match. An arbitrary pending pointer is never a generic bypass argument to WorkService. Reuse ordinary full-scope, current-file, approval and composition validation. Publication and delivery result reference are atomic where possible; otherwise inspection finds the exact recorded operation, never replays it.

The old explicit operator-resolution semantics are retained separately from normal cancellation: prove all admitted process identities absent, reobserve named documents and recovery availability, present the exact current history/observations, then record the user's explicit unresolved-outcome decision. This neither restores bytes nor accepts the result and cannot revive the grant. Missing process identity or uncertain ongoing process remains blocked. Delivery close-unknown likewise requires the exact expired attempt and process exclusion; it cannot release an unresolved child execution or permit the same effect identity to run again. This preserves the existing supported resolution contract, not a new force-unlock for P4 worker applications.

Formal single-range writes reuse the no-follow/exclusive-move port where its before/post representation applies. The formal host adds retained context checks, one-write budget, process closure and verifier order. Original recovery bytes and per-attempt staging stay separate from model-readable views. An existing helper that assumes `.hrn`, path-Python, unrestricted callbacks or old capsule authority is adapted or refused; it is not called unchanged as a hidden compatibility backend.

## Guard migration and focused checks

RF-17–19 and RF-26–30 are ported together with common RF-01–11/20 safeguards. Each moved old guard is retained, replaced by a named new check or documented as obsolete authority layout. Do not count the old test suite passing as new storage qualification.

- Pure reducer oracle: full happy history; every missing prerequisite/duplicate callback/late result; cancelled before spawn and after read; write effect with missing closure; unknown terminal and explicit read-only reconciliation.
- Actual sink oracle: bounded encoded JSON, escaped content in tool-result JSON, credential across replacement boundary, prelaunch retained context, zero new bytes on refused frame, partial frame latch, late failure preserving earlier applied bytes.
- Store faults: CAS races, cancelled/expired grant, generation fence, damaged required edge, closed restore, unrelated writer while active, process reservation without PID, crash before/after atomic publication and no effect replay.
- Native synthetic process/recovery checks: isolated harmless child only, known/unknown process identity, termination failure, directory drift, retained original, write/sync/collision errors. No model/network or OS policy changes.
- Delivery: one-attempt ownership, duplicate start, late old epoch, deadline/cancel race, submission committed before response loss, execution nested ownership, missing receiver and notification-emitter failure after result completion.
- Notice: same Work title in two projects, original versus current result, receiver replacement, detached workspace and malformed event. Recording port only.

Focused checks run after coherent changes; final P5–P6 fixed-input regression consolidates the affected families plus common fence/Work/worker tests. Optimized Python covers assertion-independent guards. Failure records are retained; at most two diagnosed correction/rerun cycles for one cause. No permission/unknown-effect blind retry.
