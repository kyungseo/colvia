# P7 lifecycle and managed entry integration

Status: authorized source preparation; grouped plan review complete; apply [Driver disposition](p7-plan-disposition.md) before each slice. Product installation, host permissions, keys, OS notifications and publication remain held. P5 native closure is a separate stopped lane; no P7 fixture may restart it.

## User outcome

One managed entry selects the verified product and dedicated runtime for CLI and desktop. Connecting a project keeps records outside its checkout. Export preserves records and retained bodies; restore creates a separately verified instance. Updating code preserves the active data; detaching integration does not delete it. A failed or ambiguous operation explains the next action without silently resetting trust or selecting older data.

## Reuse and implementation order

1. Logical backup orchestration uses the existing full GraphAudit, framed ExportReader/write_export and ImportedSnapshot. Pin one root, stream bounded objects, publish a fresh destination only after flush and independent read-back. Preserve an existing complete backup on any failure. Export metadata records the verified root/time, not a promise the destination still exists. Path names in an export never control extraction.
2. Add an explicit unpublished-generation import API to GenerationStore. It cannot write into a selected or populated store. Validate all object bytes/references/capabilities and the imported project before sealing a candidate. Preserve semantic sequence and root identity; SQL ordinals remain local. Same-state generation replacement reuses Authority.activate and its fault oracles. Restoring an older/different snapshot creates a new authority instance and requires explicit local binding; it never overwrites newer decisions or inherits active process permission. A restored instance is inspection-only until a recorded rebind and unfinished-effect reconciliation. No automatic migration of private trial records.
3. Configuration records separate enabled execution features from historical read requirements. Disabling an execution capability must not erase or make its prior Work/result unreadable. Changes require exact previews and refuse unresolved effects. The first release keeps the already approved optional execution capability; no arbitrary plugin framework or old profile compatibility.
4. Lifecycle plans capture exact project/instance/generation/root, integration file identities and runtime binding. Connect/register reuse Connections and native topology. Detach alters only exactly owned entry blocks/locator/receiver routing, preserves unrelated user edits and all authority history, and records every external step for recovery. A missing runtime or damaged binding is repair-needed, never a fresh install. Receiver changes remain prepared source operations, not emitted notifications.
5. Runtime slots are immutable verified directories under one user management root. A small binding selects product/Python/SQLite and supported protocol/capabilities. Stage then validate; activation switches only the binding under a platform lock. Keep active/in-use/last-recovery slots. No automatic deletion merely because a third slot exists. Running a compatible installed release is allowed when update metadata expires; updating is blocked. No PATH, pyenv or source interpreter fallback.
6. Use python-tuf ngclient, pinned with its dependency identities, for root/timestamp/snapshot/targets and signed length/hash verification. No cryptographic primitive or replacement TUF protocol is authored. Trust cache/counters are outside slots and locked per updater instance. An explicit embedded bootstrap trust anchor, clock rollback refusal, bounded fetcher, target custom metadata, platform/architecture/channel and runtime compatibility checks precede activation. Fixed synthetic signed fixtures only; no new production keys. If the dependency or suitable fixtures cannot be obtained within authorization, retain a concrete unavailable boundary and continue independent source work, not a permissive verifier double labelled qualified.
7. First-install shell/PowerShell entry obtains one fixed manager-plus-runtime bundle from the release-owned HTTPS route and verifies pinned length/hash before launch. Existing installations route through the trusted updater; lost manager/trust uses authenticated repair, never the weaker bootstrap branch. A source-generated template without the final official route/key is prepared, not a publicly usable installer. Avoid inventing release URLs or keys. Downloads, safe extraction, quoting, disk-space checks and subprocess invocation belong to platform ports.
8. Windows ports reuse existing tested native API behavior for reparse/handle identity, locking, replacement and process creation, without importing the old record authority. Distinguish native source implementation and synthetic API fault tests from actual Windows qualification. Do not select POSIX primitives on Windows or claim a successful Darwin fixture qualifies Windows ARM64/x64. Unsupported adapters refuse before mutation.

## Restore and update safety

A backup can contain unfinished execution evidence but cannot certify closure. Imported workspace locations/host allowlists/process owners never become live authority merely through import. A new instance retains original Work/result references and provenance, with new local registrations and explicit historical-vs-live state. Rebinding cannot turn stale accepted bytes into a new acceptance. The pending-effect guard remains intact until a defined, evidenced transition; missing original processes are not automatically known closed.

For same-state migration/compaction, populate an unpublished candidate and keep the exact original root. Verify source root again before Authority.activate. Every transaction still checks generation/pointer/fence. Interruption after fencing must finish the recorded switch or remain blocked; never rename a DB over an open DB. Unknown future required schema/capabilities refuse. Synthetic migration boundaries exercise the protocol without promising an invented future transformer.

Runtime binding rollback is independent of metadata version rollback. A freshly authorized older product can activate only if it reads/writes all current requirements; preserve trusted metadata counters. If incompatible, present the separate pre-update restore choice with the newer-data consequence. Never discard post-update decisions for recovery convenience.

## Focused checks

- Backup: retained text/binary/opaque optional records, cancelled/ENOSPC/short write, corruption/truncation, root drift, bounded memory, existing destination untouched, verified receipt vs mere attempt.
- Restore: fresh candidate only, all dependencies and semantic order, unknown required capability, extra/unreachable bytes, historical registration isolation, interrupted execution, same-root activation boundaries and old reader/writer fences.
- Settings/lifecycle: disable then inspect old execution, exact preview stale refusal, detach edited entry, partial detach/repair, no authority deletion, no automatic new connection on topology change.
- Runtime/trust: wrong OS/architecture/dependency, source-vs-installed provenance, signed target mutation, expiry, rollback, root rotation authorization, interrupted metadata/slot staging, clock rollback, retained compatible runtime and recovery slot. Use existing fixed signed test material, not generated real keys.
- Platform/bootstrap: malformed archive/escaping paths/reparse entries, quote-sensitive paths, missing executable/denied authority with short guidance, interrupted slot switch and occupied destination. No actual installation or settings mutation.
