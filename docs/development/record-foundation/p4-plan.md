# P4 implementation plan: worker application and direct-child composition

Status: source implementation authorized within the 100-hour remaining bundle; plan review precedes code. Source-only; no actual installation, host permissions, notification, product Git mutation or real key generation.

## Retained meaning

One shared immutable authority, workspace identity per checkout. Ordinary Work acceptance remains a record-only human decision. Reviewing/accepting a source workspace result never authorizes writing a destination. Worker application needs a separately shown exact destination plan and human instruction. No Git ref/index changes occur. Direct-child acceptance never accepts a parent. Parent acceptance remains human even where an exact bounded ordinary-worker grant permits an agent acceptance. Source development acceptance stays human.

2. Extend product-owned fixed schemas for worker application plans/approval/progress/outcome and composition declarations/evidence, with decision versus provenance fields fixed in code. Reuse body/map/tree primitives and generation checks. External effects are journaled in authority, not inferred from a temporary script. History survives source revocation; new application/parent decisions require current eligibility.
3. Worker service binds source Work plan, approval, submitted result and exact source workspace registration to destination workspace registration, explicit scope, full destination baseline and retained pre/post bodies. Verify source result closure and same project, supported ordinary source role and source lineage; destination must match the intended preimage for every changed path. Source identity/current eligibility is rechecked before durable application authorization. A source result may be reviewed without accepting it; destination approval names the exact submitted result and application, not a different subsequent source revision.
4. Display/receipt binds the exact source result, destination baseline and scope. User approval records intent to apply; file application is explicitly separate from ordinary record-only acceptance. Reserve an effect head scoped to destination workspace and a read-set fence for dependencies in one CAS. Pending effects block conflicting ordinary/parent/worker writes, but preserve bounded read/history access. One affected destination writer at a time, no scheduler. Detect conflicting reservations deterministically; no stale lock stealing.
5. POSIX writer port uses no-follow directory descriptors, exact identity/preimage checks, owned staged files with sync and final replacement/deletion. Windows adapter remains explicit unavailable until P7 native implementation. Stage retained bytes before replacement; every changed path must be either exact pre or exact post on recovery, while all outside-scope paths and policy stay unchanged. Unknown content, wrong workspace, changed dependency or uncertain state refuse. Publish completion only after full intended result re-observation. Cancel only while all changed files remain pre; never roll back user files automatically. Keep idempotent completion/retry semantics distinct from replaying an unknown external effect. Tests inject death before/after authorization, staging, each file, and final publication. Recoverable evidence must live in authority; disposable scratch cannot become sole authority.
6. Composition service declares one same-project parent, unique direct children and their exact plan references; rejects self/cycles/nested umbrellas/role downgrade. Bind child membership in both directions and freeze current accepted child heads/results/decisions in an immutable parent evidence record. Missing children remain visible/unready, not silently omitted. Starting a parent can preserve an incomplete capture; submit/accept requires every declared child currently completed with exact captured evidence and a scoped integration document plus explicit passed integration checks. To incorporate later child results or a changed parent baseline, use an explicit human rebind which preserves old plan/capture and requires a new exact approval; never replace capture silently at submit. Rebinding is specific composition baseline maintenance, not general external-drift auto-reconciliation.
7. Parent submit/accept hooks are mandatory in ordinary Work writers, so calling the ordinary service directly cannot bypass composition readiness. New child decisions must respect pending parent application dependencies. Historical reads validate sealed chains without imposing current child completion; live readiness is separately derived. Preserve child acceptance after parent changes and parent historical acceptance after child changes. Unknown extension roles refuse decisions, not silently skip them.
8. Expose bounded CLI operations and concise review/status summaries; tokens/IDs remain machine payloads, not normal prose. Add exact ordinary worker delegation only where explicit accepted grant names target work, source/destination, bounds and actor; revoked/mismatched grant or parent role refuses. Never infer delegation from an actor string. Delegate acceptance is not OS authentication or bypass of a host grant.
