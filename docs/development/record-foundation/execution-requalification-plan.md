# 중단 실행 경로의 신규 시도 계획

상태: 2026-11-07 Owner가 실행 범위와 행동 대화·리뷰 한도 증액을 승인했다. 기존 중단 조건과 제외 범위를 유지하며 순서대로 진행한다.
[소유 Work](../FEAT-20261106-002-record-foundation.md) · [보정 결과](execution-runner-hardening.md) · [이전 실제 실패](held-execution-resume-result.md)

## 목표와 재사용

새 합성 fixture에서 네이티브 준비 실패의 원인을 보존 가능한 형태로 확인하고, Codex 작성·제출·같은 대화 수락과 Claude의 같은 결과 조회를 검증한다. 실제 설치본이나 데스크톱 지원 판정을 대신하지 않는다.

기존 44개 실행기 오프라인 검사, 정상 부모 종료·관측 자식 종료 근거, 제품 기준점과 이후 영향 검사, 기존 합성 문서·검사 계약을 재사용한다. 정상 종료 시험·설치·전체 제품 회귀를 반복하지 않는다. 이전 실패 fixture·세션·로그는 읽기 전용 근거로 보존한다.

## 순서와 실행 범위

1. 새 실행 연결: controller의 process port adapter, 별도 fixture의 동기적 명령 wrapper와 정확한 Work ID 조회, stdout 이벤트·호출 trace 대조, 보호 파일 snapshot, 실제 turn 문맥 선택을 연결한다. 새 fixture와 이전 실패 원장의 경로/hash를 고정한다. source root·runtime·cwd를 고정하며 기존 실행기를 덮어쓰지 않는다. 다음 단계로 가기 전 계획 리뷰와 변경 연결부만 대상으로 한 오프라인 주입 검사를 수행한다.
2. 비모델 네이티브 진단: 기존 materializer와 profile을 그대로 쓰는 새 비활성 worker를 한 번 실행한다. 준비 응답·stdout/stderr·최종 exit·신호 전 identity와 종료 결과를 보존한다. worker 자체 만료 30초, 관측·정리 전체 60초 상한이다. 정상 부모 종료 근거는 재사용한다. 준비와 종료가 모두 확인될 때만 기존 문서 읽기·쓰기·검사 소스 fixture를 한 번, 180초 상한으로 수행한다. 준비 실패·종료 불명은 즉시 해당 경로 중단이다.
3. Codex 신규 합성 대화 한 번: 범위가 고정된 보고서 작성·검사·제출을 요청한다. 첫 실패 시 wrapper와 controller에서 후속 명령을 차단한다. 권한·범위·검사·같은 Work·파일 일치·명령 trace 감사가 모두 통과하면 같은 대화에서 미리 한정한 합성 결과 수락을 한 번 요청한다. fixture의 시험 수락은 제품 결과의 Owner 수락이 아니다.
4. Claude 신규 읽기 전용 대화 한 번: 같은 수락 결과·파일·남은 결정을 조회한다. 정확한 Work의 조회 wrapper만 제공하고 전후 파일 상태를 대조한다. 앞선 Codex 단계가 실패하면 이 종속 조회도 생략한다. 실패한 결과의 대체 조회를 원래 성공으로 집계하지 않는다.
5. 계획·결과 정적 리뷰와 범위 내 실행기 보정·집중 검증, 공개 가능한 결과 및 미검증 조건을 같은 Work에 기록한다. 모델·네이티브의 새 실패는 재시도하지 않는다. 독립된 경로와 문서 정리는 계속할 수 있다.

## 권한·중단 조건

- 지정 소스 checkout은 읽기 및 결과 문서 기록에만 사용한다. 제품 구현, process port, sandbox profile, 기록·수락 의미 변경은 이번 실행 연결 범위에 포함하지 않는다. 제품 결함이면 근거와 최소 변경안을 남긴다.
- 작업 전용 durable artifacts 안의 새 fixture·Git 준비·임시 파일·로그·합성 authority만 쓴다. 기존 사용 프로젝트나 실패 fixture는 변경하지 않는다.
- 기존 구독으로 로그인한 Codex ChatGPT와 Claude Pro CLI를 사용한다. 계정·토큰은 기록하지 않는다. 모델 전송은 비식별 시험 지시·합성 문서, 리뷰 전송은 관련 코드·계약·합성 결과로 한정한다. 원시 실습 로그·고객 자료는 보내지 않는다.
- 호출별 fixture 권한만 사용한다. 사용자/프로젝트 설정, OS 권한, full access 정책, 설치 상태는 바꾸지 않는다. controller의 실제 실행 경계를 알 수 없으면 미확인으로 표시하고 더 넓은 권한으로 우회하지 않는다.
- 이번에 생성한 관측 프로세스에만 종료 요청을 보낸다. PID와 birth를 신호 전에 대조하며 과거 PID·미확인 그룹에 신호를 보내지 않는다. 개별 신호 연결부의 성공은 제품 group 종료의 성공을 뜻하지 않는다.
- 모든 실제 실패·시간 초과·권한 불일치·종료 불명은 그 시도를 닫는다. 정적 확인과 오프라인 주입 검사 보정은 가능하지만 새 네이티브/모델 시도로 대체하지 않는다.
- 실제 설치·설정/권한 변경·키 생성·알림·커밋·공개는 제외한다.

## 예상 시간과 필요한 한도

예상 활동 70–110분과 모델·리뷰 대기 최대 20분, 합계 약 90–130분이다. 기존 실행기·합성 fixture 재사용을 전제로 한 판단치이며 실제 sandbox 원인은 미확정이다. 기존 4시간 실행 묶음의 소비 약 37.44분을 이월해 잔여 약 202.56분 안에서 수행한다. 누적 100시간 상한은 늘리지 않는다. 사용자 응답 대기는 제외하고 동시 경과를 중복 계산하지 않는다. 실행 전 최신 원장을 대조한다.

| 자원 | 신규 사용 | 한도 처분 |
| --- | --- | --- |
| 행동 대화 | Codex 신규 1 + 동일 대화 재개 1 + Claude 신규 1, 3메시지·각 240초 | 새 대화 한도 8→10. 메시지 한도18 유지(11 사용), 모델 대기2400초 유지(378.160 사용) |
| 정적 리뷰 | Claude 계획·결과 각1, 각240초·도구 없음 | 리뷰 호출20→22. 누적 대기6000→6600초(5693.477 사용) |
| 비모델 실행 | 새 비활성 worker 1회, 통과 시 문서 fixture 1회 | 각각 정리 포함60초·180초. 실패 경로 반복 없음 |
| 실행 연결·검사 | 변경 연결부만 오프라인 검사 | 기존 44개 근거 재사용. 제품 전체 검사 반복 없음 |

리뷰 호출 한도는 현재20/20, 새 행동 대화는8/8로 소진됐다. 이전의 진행 승인이나 남은 작업 시간만으로 이 수량을 늘리지 않는다. 이 증액과 신규 시도를 한 묶음으로 승인하면 각 정상 단계마다 다시 묻지 않고 진행한다. 실제 권한 확대나 제품 의미 변경이 필요할 때만 별도 판단으로 남긴다.

## 종료와 보존

네이티브 결과와 프로세스 종료를 함께 확인하고, 모델 경로는 정확한 같은 Work·제출 결과·수락·현재 파일·읽기 전용 조회가 일치해야 통과다. 실행기 관측 성공, 제품 명령 성공, 행동 흐름 성공을 따로 보고한다.

기존 실패 및 이번 원시 로그·필요한 fixture는 공개 전 원인 진단·회귀 검증이 소비하며 해당 소비자가 끝날 때까지 비공개로 보존한다. 제품 문서에는 식별 정보를 뺀 근거와 한계를 남긴다. 이번 계획은 전체 기반 재작성의 완료나 공개 승인을 뜻하지 않는다.
