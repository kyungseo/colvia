# 시작 실패·축약 시험 지침 후속 분석

상태: 아래는 준비 당시 분석·실행안이다. 이후 Owner 승인으로 실행했으며 [결과](startup-and-context-result.md)에 관측과 리뷰 처분을 기록했다. 준비 당시에는 읽기 전용 분석과 다음 실행안 준비를 마쳤다. 새 모델·작업자를 실행하지 않았고 제품 정책·권한·설정은 바꾸지 않았다. [직전 결과](minimal-profile-and-query-result.md)의 실패는 그대로 유지한다.

## 확인한 사실

- 실패한 작업자의 PID·부모 PID·시각과 일치하는 OS crash report를 확인했다. SIGABRT이며 stack은 `ignition_halt` → `boot_boot` → `ignite` → `dyld4::CacheFinder`/`DyldCache` 초기화에 있다. 문서 작업이나 Python 본문의 실패로 볼 근거는 없다.
- 같은 PID의 전후4초 unified log는 조회 성공했으나 결과가 없었다. 거부된 정확한 경로·operation은 확인하지 못했다. 다른 프로세스 로그를 넓게 검색하지 않았다.
- 현재 시스템 캐시는 Cryptex의 dyld 디렉터리에 있고 공개 경로가 Preboot의 실제 경로로 연결된다. 두 표기에서 cache 관련84개 entry가 보인다. 현 template가 허용하는 legacy dyld 디렉터리는 이 기기에 없다.
- 이는 OS cache 초기화 관련 읽기 조건을 우선 대조할 근거다. 어떤 규칙이 충분하거나 필요한지, 삭제가 단독 원인인지는 실행 없이 확정할 수 없다. 루트 전체 또는 홈 전체 읽기를 허용하는 근거가 아니다.
- 제품 adapter는 completed 작업에 새 수락 질문이 필요 없다고 이미 명시한다. 이전 시험의 짧은 CLAUDE.md는 이 의미를 생략했다. 그 규칙을 변경 없이 제공하고 '이번 호출에서는 기록을 바꾸지 않는다'와 '과거 수락 상태'를 구분하는 시험 문구 후보를 준비했다. 특정 Work가 수락됐다는 정답은 입력에 주입하지 않는다.

## 다음 실행안 — 승인 대기

예상45–75분, 중단 상한90분. 기존4시간 실행 묶음과 누적100시간 안에서 사용한다. 리뷰·모델 대기는 경과에 한 번 포함하며 Owner 대기는 제외한다. 직전 리뷰/실행 소요와 추가 조건 분리 준비를 바탕으로 한 판단치다.

1. Claude CLI 계획 리뷰1회(최대360초): crash의 비식별 요약, 현재 정책, 아래 조건 분리안, 기존 adapter와 시험 문구 후보만 제공한다.
2. 같은 전용 Python·동일 준비 코드와 새 합성 fixture를 사용한다. 이전 실패 정책과 넓은 정책의 결과는 재사용하고 동일 실행을 되풀이하지 않는다. 새 후보는 아래 최대3개이며, 앞 후보가 통과하면 나머지는 실행하지 않는다.

| 후보 | 기존 실패 정책에 추가할 제한된 읽기 | 목적 |
| --- | --- | --- |
| A | 두 OS cache 경로와 조상들의 정확한 metadata literal만 | cache 탐색에 metadata만 필요한지 구분 |
| B | A + 현재 존재를 확인한 cache 파일들의 정확한 read-data literal과 해당 OS cache 디렉터리의 정확한 data read | cache 열기/열거 조건 구분. subpath 전체, 사용자 문서, 새 쓰기/네트워크/프로세스 권한 없음 |
| C | B + 루트 `/` 자체의 DIRECTORY data read만 | 기존 진단 부록의 마지막 차이 구분. 루트 하위 파일 내용 읽기는 허용하지 않음 |

각 준비 진단은60초 이내1회다. 예상한 준비 전 종료가 나오고 관측 종료가 확인되면 그 결과를 반례로 보존한 뒤 다음 서로 다른 후보로 진행하는 조건 분리 시험이다. 동일 후보 재시도는 없다. unknown 종료, 신원 불일치, 잔여 프로세스, 예산·기록 실패는 native 경로 전체를 중단한다. 이 '예상 반례 뒤 다른 후보 진행'은 이전 실패 후 중단 규칙의 명시적 한정 변경이므로 Owner 승인 전 실행하지 않는다.

3. 통과한 후보가 있을 때만 문서5단계1회(180초 이내)를 수행한다. 성공은 해당 후보의 관측 증거이며 보편적 최소권한 증명은 아니다. 실패하면 재시도하거나 규칙을 추가하지 않는다. 승인 범위 내에서 성공한 정확한 규칙만 source 후보에 반영하고 경계 검사를 수행한다. renderer·process port 및 호스트 권한/설정은 바꾸지 않는다.
4. 독립된 Claude 조회1회(240초 이내): 기존 adapter의 상태 의미를 제공하고 같은 수락 Work를 무변경 조회한다. 기존 기록에서 상태를 읽도록 하며, transport 통과와 최종 답변 의미 통과를 모두 요구한다. source가 아닌 실제 설치본/데스크톱 검증으로 확대하지 않는다.
5. 결과 리뷰1회(360초 이내), 범위 내 오프라인 보정·집중 검사와 상태 기록까지 마친다. 새 제품 기능이나 계약 개편은 하지 않는다.

한도 증액: 행동 대화12→13개, 리뷰27→29회. 현재 메시지16/18개·행동 예약1653.160/2400초에 신규1메시지·255초를 더한다. 리뷰 누적6983.106/7800초에 최대720초를 더하므로 대기 상한7800초는 유지한다. 각 결과의 소비량과 실패를 이월하고 추가 호출을 자동 허용하지 않는다.

실제 설치·OS/호스트 권한 변경·키 생성·알림·커밋·공개는 계속 제외한다. 원래 실패와 판독 코드, OS task-specific 요약, 후보·실제 시행 조건을 보존한다. 다른 개인정보·기기 식별자는 source/리뷰 패킷에 넣지 않는다.
