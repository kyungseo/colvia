Document effects and execution completion remain separate from the human's Work acceptance. A delivery-owned run returns its owner to the same delivery attempt; it does not release a different pending operation.

The explicit Darwin launch port pins runtime/helper bytes, policy, configuration, instruction/rule inputs, paths and capability identity. It uses existing private session directories and a minimal environment; it does not discover an executable on PATH, download a runtime, create credentials or read subscription credential contents. Mutable authentication files remain path/kind checked without content hashing. The composition root must supply qualified binary digests and explicit resource paths.

Verification is repeated after durable reservation, after spawn before session admission and at document admission/reply boundaries. This is not atomic descriptor execution or protection against a hostile process changing paths under the same OS account. An installed composition root, real runtime-image qualification and managed dispatch remain unfinished; optional managed execution stays disabled.

## Review corrections

- An identity failure records the actual returned process ID with unavailable birth and attempts bounded kill/reap through the owned process handle. It never adopts an unidentified process group. Parent termination alone does not establish descendant closure; unknown state retains the owner barrier.
- The TERM phase has an absolute half-budget and scans use remaining time. Identity/scan failure does not waive the no-unverified-signal rule. A bounded owned-handle abort is separate from group-closure evidence.
- Discovered child identities are recorded even on failed closure when publication remains reliable. A lost acknowledgement retains uncertainty and does not replay an event.
- Completed publication validates both execution cancellation and delivery-parent cancellation in the final compare-and-swap dependencies. A proved noncommit followed by observed cancellation may publish a different interrupted outcome.
- A trusted publication-refusal type distinguishes prepublication validation and confirmed rollback from unknown commit/acknowledgement outcomes. It permits recording closure, not retrying the refused action.
- Early known-no-effect refusal closes before launch. Reducer admission requires observed birth. Stream close attempts are independent. Readiness errors and static worker dependency binding received small corrections.

The Driver revised the suggestion to signal an unidentified group or regard PID reuse as absence. Both would weaken the existing conservative observation contract. OS process observations remain bounded cooperative-process evidence, not proof against daemon escape.
