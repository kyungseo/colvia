# Read the decisions behind a Work

An agent can answer a question about an earlier decision by reading one Work’s saved statements and reopening the corresponding submission. A change request can refer to a different revision from the one ultimately accepted. An explanation inferred from a progress note or supplied in today's conversation has a different source from the recorded decision.

`ordinary history WORK` uses the existing project publication order, Work heads, decision records, and progress notes. It provides a source reference for each entry, binds pagination to the selected Work and project root, and reports incomplete or unreadable history. Each page reads a bounded number of publications and bytes of metadata. The command opens the existing store read-only. It adds no record type or write capability. The stored order establishes relative sequence. A decision's free text does not establish speaker identity, a timestamp, or an unstated reason.

The focused tests cover a reopened acceptance, revision-specific contents, an archived Work, a progress note followed by scope and lifecycle changes, replacement, pagination within one publication, a bounded read that continues on another page, and the different outcomes of an unreadable entry and a broken publication chain. The managed CLI returned the same evidence in human and JSON output. The retained v0.3.0 fixture DB and backup kept their original SHA-256 digests. Fixture ZIPs for all three supported targets contained identical copies of the selected code and guides.
