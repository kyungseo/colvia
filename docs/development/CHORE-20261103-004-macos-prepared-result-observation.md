# macOS 도입 프로젝트의 준비된 결과 제출과 조회

[패키지별 검증 현황](CHORE-20261103-003-qualification-alignment.md) 이후, PR #46으로 갱신한 macOS 도입 프로젝트 한 곳의 기록을 현재 안내에 반영한다. 이 문서의 대상은 사용자가 맡긴 일반 Work 한 건의 제출과 조회다.

| 관측 지점 | 확인한 내용 |
| --- | --- |
| 기존 Work 재개 | 갱신 후 새 프로세스에서 기존 Work가 열렸다. 아래 새 Work 제출과 별개로 확인했다. |
| 새 Work 제출 | 사용자가 새 일반 Work에서 준비된 결과의 검토 제출을 맡겼다. 영수증에 제출과 로컬 알림 요청의 정상 반환이 기록됐다. |
| 사용자 조회 | 사용자가 수신함에서 해당 Work를 찾고, 상세에서 결과 위치·검사 내역·검토 대기 상태를 읽었다. |
| 기기에 표시된 알림 | 알림 센터에 Colvia 일반 알림이 보였다. 문구에 Work 식별자가 없고 상대 시각으로도 이번 제출과 연결할 수 없었다. |

일시 배너 표시, 알림 클릭, 결과 파일 열람과 결과 수락은 이번 관측 밖이다. 이 새 Work를 다른 대화에서 다시 찾아가는 과정도 미확인이다. PR #46 자체의 새 공식 모델 실행은 직접 실행과 맡기기 경로 모두 미검증이다. 지정 Windows ARM64의 격리 결과와 Windows x64 공개 준비는 앞선 기록을 따른다.

개발 인덱스와 기능 목록, 첫 사용 안내, 명령 레퍼런스의 관측 문구만 갱신한다. 기존 설치본과 과거 수락 기록은 당시 상태를 보존한다.

## 문서 대조와 리뷰

Driver는 갱신 뒤 기존 Work 조회와 새 Work 제출을 분리하고, 제출 영수증·사용자가 확인한 수신함과 상세·알림 센터 표시를 대조했다. Claude Opus 5.5가 비식별 요약과 문구를 별도 세션에서 두 차례 정적으로 검토했다. 계획 리뷰의 제안에 따라 관측을 한 도입처의 macOS 사례로 한정했다. 결과 리뷰 뒤에는 제출 문장에서 미리보기 절차를 덜어내고, PR #46의 직접 실행과 맡기기 실행, 다른 대화에서 새 Work를 찾는 경우의 검증 범위를 맞췄다. 보정 문구는 Driver가 로컬에서 대조했다.

문서 링크와 절 대상, Markdown 렌더링, 기능 목록 JSON 및 이전 수락 기록 보존을 검사했다. 보강 사항은 제품 소스의 안내에 해당한다. 설치본에 이 안내가 필요한 경우 이를 포함한 후보를 만들어 배포 시점에 대조한다.
