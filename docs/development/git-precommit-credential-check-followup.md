# Git 반영 전 자격증명 차단

## Owner 계획 결정 · 2026-11-16

등록판 `git-precommit-credential-check-r1`. Owner는 Colvia로 Git에 반영하기 전에 비밀번호와 API 키가 들어간 내용을 차단하는 기능을 첫 Preview 이후 후속 후보 0순위로 기록하도록 결정했다. 첫 Preview는 이미 정한 제품 범위로 진행한다. 이 결정의 적용 범위는 후보 등록이며 실제 구현은 미선택 상태다.

## 재개 조건과 완료 기준

- 첫 Preview 이후 후속을 선택할 때, [기존 검사](../../src/colvia/execution/guards.py)의 자격증명 패턴만 Git에 맞게 재사용할 수 있는지 대조한다. 알려진 토큰·개인 키와 설정에 평문으로 적은 비밀번호·API 키부터 범위를 정한다. 환경변수 참조와 정상 문서 예시를 함께 검증한다.
- Colvia가 이번에 반영할 승인된 제출본 전부와 커밋 메시지를 Git 객체를 만들기 전에 검사한다. 차단 시 위치와 유형만 표시한다. 실제 값은 출력·로그·미리보기에 담지 않는다. [현재 Git 반영 준비 흐름](../../src/colvia/git_integration.py)
- 기존 미리보기의 반영 전 재검사, 이미 시작한 작업의 복구, 일반 반영과 다른 변경의 부분 스테이징 보존을 확인한다. 마지막 파일·커밋 메시지에서 발견된 합성 자격증명도 새 Git 객체·후보·잠금이 생기기 전에 차단되는지 확인한다. 소스 집중 검사 뒤 macOS ARM64와 Windows x64·ARM64에서 이 변경의 경계만 확인한다.
- 첫 Preview의 소스·공개 이력·배포 자산 점검과 GitHub 보호 설정 확인은 기존 공개 준비 범위에 속한다.

## Owner 보충 결정 · 2026-11-16

비밀번호나 API 키를 알아서 분류하기 어려운 사용자도 처음 설정 없이 도움을 받도록, Colvia의 Git 반영 흐름에서 작동하는 최소 차단과 쉬운 해결 안내를 우선한다. 이 기능을 완료하고 새 판을 배포할 때 사용자 문서에 보호 범위와 해결 방법을 보강한다.
