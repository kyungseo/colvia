# 중단된 수정 요청 복구와 이전 알림에서 결과 확인

2026-11-04 Owner가 아래에 기록한 복구·알림 동작과 기능별 검증 범위를 수락해 완료했다. 기준은 PR #51 병합본 `59d5f10`이다. 개발 담당은 Codex, 독립 검토는 Claude, 결과 수락은 Owner가 맡는다. 비공개 개발 후보에서 [첫 공개 기능 표](preview-release-order-and-user-journey.md#첫-preview-기능과-매뉴얼-제안--11월-4일)의 열두 기능을 대조했다.

## 사용 중에 달라지는 점

- 수정 요청을 이미 기록한 뒤 프로그램이 닫혀도 같은 요청으로 작업을 이어간다. 이전 결정과 새로 바뀐 파일이 맞지 않으면 파일을 그대로 보존하고 차이를 먼저 확인한다.
- 수락을 기록하는 도중에 끊긴 경우에도 새 대화에서 이미 저장된 결정을 마저 반영한다. 대상 파일이 달라졌거나 어느 결정인지 확인되지 않으면 중단한다. 이미 수락한 제출 알림을 다시 열면 수락을 되묻지 않는다.
- 지난 알림에는 당시 제출 내용과 지금의 작업 상태가 구분된다. 이후 수정본이 있으면 새 결과를 따로 보여 주고 그 결과에 대한 결정을 기다린다. 닫힌 질문도 당시의 질문으로 남는다.
- 일반 제출은 프로젝트 대화에서 마친다. 사용자가 기기 알림을 요청하면 수신함과 연결된 경로를 사용한다. 알림을 열거나 제출했다는 이유로 결과를 수락하지 않는다.

## 기능별 시나리오

각 행은 이번에 선택한 오프라인 검사와 그 판단 범위다. 운영체제 화면과 실제 모델 대화는 별도다.

## 검사 결과

- 병합본에서 12개 기능에 해당하는 165개 검사 중 164개가 통과했다. Windows에서만 실행할 수 있는 요청 파일 경로 검사 1개는 건너뛰었다. 기능 사이의 경계와 목표 초안을 다룬 추가 검사 11개가 통과했다.
- 같은 17개 중단·파일 변경 사례를 보정 전후로 비교했다. 수정 요청의 선택 기록을 쓴 직후와 현재 상태를 교체하기 직전에 재개할 수 없었던 두 경우가 복구됐다. 이때 사용자가 파일을 바꿨다면 기존 요청으로 덮어쓰지 않는다.
- 인계에서 공식 실행 미리보기를 요청하는 7개 합성 사례는 별도로 확인했다. 일치한 1개만 미리보기를 받았고 다른 Work·프로젝트·기한·확인값·프로필은 거절됐다. 별도 실행기를 호출하거나 실제 사람을 인증한 결과는 아니다.
- Claude가 기능별 검사 범위와 구현 반례를 따로 검토했다. 결과 리뷰에서 나온 새 대화의 수락 복구, 이미 수락한 알림, 기존 접수 상태 표시를 보정했다. 보정 후 집중 검사 7개와 격리 런처 검사를 진행했다. 새 프로세스는 이전 대화의 확인값 없이 기록된 수락을 완료했다. 최초 장애 주입 도구는 프로젝트 런처 밖에서 호출해 거절됐고, 실제 런처 진입점으로 바로잡아 확인했다. 마지막 보정의 추가 독립 재리뷰는 진행하지 않았다.

## 공개 후보에서 남은 확인

macOS와 Windows ARM64에서 Codex·Claude Code 각각으로 결과 알림을 열고, 결과를 수정·재제출한 뒤 첫 알림도 다시 연다. 원래 제출, 현재 검토할 내용, 이미 수락한 상태가 구분되는지와 Windows 창의 첫 줄을 확인한다. 짧은 보완 요청은 작업 시간과 새로 물은 횟수를 따로 기록한다. x64 외부 확인은 배포할 파일이 고정된 뒤 진행한다.
