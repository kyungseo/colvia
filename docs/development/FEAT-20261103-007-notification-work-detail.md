# 알림에서 해당 Work 상세 열기

2026-11-03 Owner가 [공개 전 필수 조건](CHORE-20261103-005-notification-guidance.md#공개-전-필수-조건)의 구현 착수와 비식별 계획·결과 리뷰를 승인했다. 현재 상태는 Owner 수락·완료다. 아래 검증 기록은 각 단계 당시의 판단을 보존한다.

먼저 격리된 표준 계정에서 운영체제의 실제 클릭이 발신 앱 종료 뒤에도 같은 알림 식별값을 전달하는지 확인한다. Windows는 현재의 표준 계정 설치 방식에서 ARM64·x64 활성화 구성의 공급 및 등록 조건을 확인한다. 이 진입 검사를 통과한 플랫폼에 검증된 프로젝트·수신함 조회를 연결한다.

각 알림에는 새로운 무작위 조회 키를 발급한다. 사용자가 누르면 알림 당시의 질문 또는 제출과 현재 상태를 구분해 읽을 수 있다. 프로젝트 식별·authority home·Work·세대가 다르거나 기록이 사라지면 수신함으로 안내한다. 오래된 질문, 뒤이은 결과, 동일 ID를 쓰는 다른 프로젝트, 창 종료와 열린 창 전환을 검사한다. 결과를 확인하는 동작은 작업 실행이나 수락 권한을 쓰지 않는다.

Claude 계획 리뷰 1회에서 접수 행 재사용, 프로젝트 경로 교체, 열린 창의 응답 순서, 권한 거절 시 수신함 보존을 다뤘다. 각 이벤트의 고유 키, 정확한 기록 대조 및 읽기 전용 화면을 채택한다. Codex·Claude Code와 각 OS에서의 실제 클릭은 공개 후보에서 별도로 확인한다.

격리 macOS에서 제품 후보와 전용 Python을 준비하고 이 앱의 알림 허용을 켰다. 서로 다른 두 합성 프로젝트에 같은 ID(work-demo)로 제출한 결과가 각각 알림 센터에 도착했다. 상세 창이 닫힌 상태에서 먼저 보낸 알림을 누르자 설치 안내 A 확인, guide-A.md, 안내 A 문안 검토가 열렸다. 열린 창에서 남은 알림 본문을 누르자 B의 제목·guide-B.md·후속 행동으로 바뀌었다. 두 결과 모두 검토 대기였다. 클릭 전후 프로젝트별 일반 파일 경로와 SHA-256을 대조한 결과 A 52개와 B 52개가 각각 일치했다. 첫 클릭은 보기 버튼 위치에서 수행했으며 OS가 전달한 액션 종류는 별도 계측하지 않았다. 검증은 제품 명령을 사용한 합성 제출로 한정한다. Codex·Claude Code별 실사용과 Windows 클릭은 공개 전 별도 확인 대상이다.

Windows 11 ARM64 표준 계정(build 26300)에서 고정한 x64 Python 3.14.7을 시험 폴더에서 실행했다. python.exe와 python314.dll의 서명이 유효했다. 관리 도구와 Python PE는 AMD64(0x8664), Windows가 보고한 native machine은 ARM64(0xaa64)였다. 관리 도구의 status는 native Windows amd64 required 및 종료 코드 65로 끝났다. 설치와 첫 Work는 수행하지 않았다. OS 전체를 x64로 에뮬레이션하는 경로에는 별도 x64 Windows 게스트가 필요하다. 해당 게스트로 개발 검사 후 공개 후보의 Intel·AMD 환경 확인을 한 번에 묶는 순서를 유지한다.

같은 로그인에서 Windows 기본 알림 인터페이스로 notifier 객체 생성을 확인했다. 설정값을 읽은 문자열은 비어 있었고, 알림 전송·클릭·표준 계정 활성화 등록은 아직 확인 전이다. 게스트에 Windows App Runtime 1.8과 2.6.4 양쪽 아키텍처 패키지가 보였으며 개발 측에서 조사한 2.6.5의 공급은 별도다. 외부 기본 경로는 없었고 활성으로 표시된 장치는 로컬 loopback이었다. 지정 VM을 정상 종료하고 최초 설정 파일 전체 바이트와 모드의 일치를 확인했다.

Windows 11 ARM64 표준 계정에서 발신 프로세스가 끝난 뒤 알림 센터의 View 버튼으로 합성 B 결과(guide-B.md)가 열렸다. 창을 열어 둔 상태에서 남은 알림 본문을 누르자 합성 A 결과(guide-A.md)로 전환됐다. 두 경우 모두 같은 work-demo ID를 표시했다. 실제 콜백 식별과 동일 프로세스·동일 창 핸들을 확인했다. 최초 후보는 수신기 기동만 기록했고 상세 표시는 확인되지 않았다. 계측 후보의 성공으로 첫 시도의 원인은 확정하지 않는다. 이 단계는 합성 표시와 사용자별 등록의 진입 검증이다. 실제 Work 기록과의 결합, 갱신·제거 수명 주기, Codex·Claude Code 경로, x64 클릭은 별도다. 임시 등록을 제거했고 두 시험 VM 모두 정상 종료 상태다. Windows VM 설정 전체 바이트와 모드는 시작 전 원본과 일치했다.

Windows ARM64 관리 후보에 표준 계정용 알림 등록, 전송, 클릭한 Work 상세 읽기를 연결하고 오프라인 빌드를 완료했다. 별도 두 프로젝트에서 같은 Work ID로 제출하는 시험 매체를 준비했다. 이번 후보의 제품 알림 클릭과 프로젝트 파일 보존 판정은 대기 중이다.

Windows 11 ARM64 표준 계정에서 서로 다른 두 프로젝트의 같은 work-demo 제출을 확인했다. 알림 센터의 ‘보기’로 B의 guide-B.md를 처음 열고 열린 창에서 A의 알림 본문을 누르자 guide-A.md로 전환됐다. 두 창 모두 검토 대기와 각 제출의 후속 행동을 표시했다. 첫 창 후보의 제목 겹침과 닫기 후 프로세스 잔류를 보정했다. 보정판에서 같은 접수로 두 클릭을 다시 확인했고, 창을 닫으면 프로세스가 종료됐다. 클릭 전후 두 프로젝트의 일반 파일 52개씩이 모두 일치했다. 이전 수신기가 보낸 알림을 갱신한 수신기로 열었을 때 연결을 유지한 A는 원래 결과가, 연결을 해제한 B는 채팅에서 확인하라는 안내가 표시됐다. B의 Work·의도 기록 13개와 문서는 보존됐다. 연결 해제 이후 클릭 전후에는 A 52개·B 18개 파일이 일치했다. 사용자별 수신기 중복 등록·해제와 소유 등록 제거를 확인했다. 두 VM은 정상 종료 상태이고 Windows VM 설정 전체 바이트와 모드는 원본과 같다. x64 수신기는 개발 빌드까지 확인했다. 네이티브 x64와 공개 후보의 Codex·Claude Code별 실제 클릭은 남아 있다.

Claude Pro 결과 리뷰. 격리된 개발 환경에서 관측한 범위의 차단 사항은 없다는 판정이다. 등록 교체 실패와 부분 등록·해제 복구 지적을 채택했다. 이전 명령 복원, 등록 변경 전 복구 정보 저장과 단일 쓰기 잠금, 예기치 않은 키·값 보존을 구현했다. 실패 주입 회귀 검사 세 건을 통과했다. 보정 후 독립 재리뷰는 수행하지 않았다. 두 공급 후보의 실행 파일 PE machine을 직접 대조했다. 실제 클릭 후보는 ARM64(0xaa64), x64 개발 빌드는 AMD64(0x8664)다. 리뷰가 ARM64 클릭을 Prism x64 실행으로 분류한 부분은 이 근거에 따라 채택하지 않았다.

계획 내용은 수신함에서 원본 해시를 검증하고 알림 인덱스가 같은 접수 해시를 다시 대조한다. 따라서 리뷰의 질문 선택 변경 후보는 이중 검증을 고려해 분리했다. 결과가 달라져 기존 제출을 증명할 수 없으면 수신함으로 안내한다. 빠른 다중 클릭과 종료 동시 클릭, 이벤트 보존 기간, 이전 버전 실행 파일 정리, macOS 수명 주기 및 공개 후보의 도구별 사용은 후속 범위다. 복구 기록 없이 발견한 불완전 등록과 타 프로그램 값은 자동 정리 대상에서 제외했다. Windows 문서 세 파일의 원본과 ARM64·x64 배포 아카이브 내용을 대조했다. 개발 기록과 외부 근거, 두 배포물과 입력은 네이티브 재확인과 Owner 판단까지 보존한다.

Claude 결과 리뷰 후 보정한 Windows 알림 등록 복구를 지정 Windows 11 ARM64 표준 계정의 실제 사용자 레지스트리에서 확인했다. 검증 도중 실패한 갱신은 이전 수신기를 복원했다. 등록 및 해제 중단 직후 남은 부분 상태는 다음 관리 명령이 복구했다. 복구된 수신기에서 기존 A 제출의 알림을 다시 보내 ‘보기’를 누르자 설치 안내 A 확인 (work-demo), guide-A.md, 결과 검토 대기, 안내 A 문안 검토가 표시됐다. 창을 닫은 뒤 수신기가 종료됐고 연결된 A 52개와 앞서 연결을 해제한 B 18개 파일은 각각 기존 대조값과 일치했다. 중복 등록과 해제, 소유 등록의 제거를 확인했다. Windows VM은 정상 종료했고 설정 전체 바이트와 파일 모드는 보존한 원본과 일치했다. macOS VM도 정지 상태다. 이 개발 범위는 Owner 수락 대기다. 보정 후 독립 재리뷰, 네이티브 Windows 11 x64 및 공개 후보에서 Codex·Claude Code 각각의 실제 알림 클릭은 남아 있다.
