# README diagrams

These figures refine the seven editable originals at `../readme-*.ko.svg`. Keep their roles, labels and connections when updating them. The generated Korean files are `SCENE-light.svg` / `SCENE-dark.svg`; English files add `-en` before the theme. READMEs use `picture` to select the theme and embed the 2× PNG exports. The editable SVGs remain alongside them.

Run `python3 scripts/build-readme-gallery.py` from the repository root. The optional `--output` chooses another output directory. The Node compatibility entry accepts the same output-directory positional argument. The builder uses the approved outlined Colvia symbol and wordmark, keeps original node positions, centers labels, and makes arrow size independent of line width.

Each SVG embeds the regular and bold font subsets in `fonts/`. No installed font or remote font request is needed when the viewer allows embedded fonts. Because image hosts may restrict font data, the public README uses the PNG exports to preserve the rendered type. These subsets cover the current labels only. Editing text in the seven original SVGs or the translation map may require extending the subsets before regeneration. Use `--text-file PATH` to export the required characters. Subset the pinned Pretendard1.3.9 Regular/Bold fonts with fonttools4.53.1 and brotli1.1.0, preserving legal notices and renaming all modified font identity records to `SkinSans-Subset` in accordance with the reserved-name condition. Check full character coverage and update `fonts/PROVENANCE.json` before rendering. See [font license](fonts/LICENSE.txt) and [source and hashes](fonts/PROVENANCE.json).

The source originals remain editable text. The generated SVGs also retain text elements and embed the subset for portable viewing. Font licenses apply to the embedded fonts; diagram source and shapes follow the repository license. The manifest records original and generated hashes; it is not a user acceptance record.

After SVG generation, render each file in Chromium at exactly twice its viewBox dimensions, verify text bounds and appearance, and save the matching PNG beside it. Refresh the manifest’s `renders` entries from those bytes. Do not reuse a PNG after its SVG changes. The rendering environment is a source build tool, not an end-user dependency.
