## 설치하고 프로젝트에 적용하기

먼저 Codex 또는 Claude Code를 설치하고 로그인하세요. 운영체제에 맞는 설치 명령을 실행하면 Colvia가 배포 파일을 내려받아 검증하고 전용 Python을 준비합니다. 준비가 끝나면 [설치한 버전](#check-installed-version)을 확인하세요. 이후 절차는 [업데이트와 중단 복구](#업데이트와-중단-복구)에서 확인할 수 있습니다.

Windows에서는 시작 메뉴에서 일반 PowerShell을 표준 사용자로 열어 설치 명령을 실행하세요. 앱 전용 셸에서 설치 위치를 확인할 수 없다는 안내가 나오면 일반 PowerShell에서 이어가세요. 디스크 공간이 부족하다는 안내가 나오면 표시된 필요 공간과 여유 공간을 확인하세요.

설치가 끝나면 사용할 프로젝트 폴더에서 Codex 또는 Claude Code를 열고 요청하세요.

> 이 폴더에 Colvia를 연결해 주세요.

보고서를 쓰거나 웹앱을 만드는 등 새 일을 시작할 때는 빈 폴더를 연결해도 됩니다. 이미 작업 중인 프로젝트에도 연결할 수 있습니다. Git을 사용하는 프로젝트 폴더라면 먼저 [에이전트에게 Git 등록을 요청](#git-등록하기)한 뒤 저장소의 최상위 폴더에서 연결합니다. 에이전트가 보여 주는 연결 미리보기에서 폴더, 추가할 실행기와 안내, 기록 저장 위치를 확인한 뒤 승인하세요. 기존 프로젝트 규칙을 사용하고, 필요한 경우 에이전트 지침에 Colvia 안내를 덧붙입니다. 연결한 폴더에서는 macOS의 `./colvia guide` 또는 Windows의 프로젝트 실행기 `colvia.cmd`(PowerShell에서는 `.\colvia.cmd guide`)로 안내를 읽습니다. 에이전트는 같은 실행기로 `ordinary list`를 호출해 현재 작업을 확인합니다.

Colvia는 운영체제의 사용자 데이터 폴더에 있는 SQLite 데이터베이스에 프로젝트별 작업 기록을 보관합니다. 프로젝트 폴더에는 연결 정보와 진입 안내를 둡니다. 앱과 CLI는 같은 전용 실행기를 사용합니다.

작업이 막혔다면 에이전트에게 어디서 멈췄는지 물어보세요. 실행기가 열리지 않는 경우, 파일이나 기록 폴더를 읽고 쓸 수 없는 경우, Colvia가 승인 범위 밖의 변경을 거부한 경우는 각각 해결 방법이 다릅니다. 앱이나 CLI에서 필요한 경로만 허용할 수 있다면 그 방법을 사용하세요. 필요한 경로에만 권한을 줄 방법을 확인할 수 없다면 해당 변경을 멈추고, 막힌 위치와 확인된 다음 단계를 살펴보세요. 필요한 경로를 확인할 때도 파일 접근은 최소 범위로 유지하세요.

운영체제의 실행 허용, 알림 허용, Codex·Claude 구독 로그인은 사용자가 직접 해야 할 수 있습니다. 이는 전용 Python 준비와 별개입니다.

### 설치한 버전 확인하기

Colvia 준비가 끝나면 아래 명령을 실행해 `Colvia` 뒤에 표시되는 버전을 확인하세요.

macOS 터미널

```sh
"$HOME/Library/Application Support/Colvia/bin/colvia-manage" status
```

Windows의 일반 PowerShell

```powershell
& (Join-Path ([Environment]::GetFolderPath("LocalApplicationData")) "Colvia\bin\colvia-manage.exe") status
```

## 하고 싶은 일부터 시작하기

폴더 연결을 마치면 지금 대화에서 하려던 일을 한두 문장으로 알려주세요. 에이전트는 이렇게 안내할 수 있습니다.

> 폴더 연결이 완료되었습니다. 이어서 이 폴더로 어떤 작업을 하려는지 짧게 알려주세요.

> 팀 회의에서 나온 할 일을 모아 관리하는 작은 프로젝트를 시작하고 싶어요.

프로젝트 자료가 없는 폴더에서는 에이전트가 현재 상태를 설명하고 아이디어를 목표와 첫 작업으로 구체화하도록 도울 수 있습니다. 예를 들어 “회의 결과를 한 페이지로 정리하고 싶어요”라고 말해도 됩니다. 이미 목적이나 작업을 말한 경우에는 그 내용과 기존 브리프, README, 프로젝트 규칙을 바탕으로 작업안을 제안받을 수 있습니다.

문서라면 목차와 검토 기준을, 새 앱이라면 첫 버전의 범위와 권장 기술, 실행·검증
방법을 제안받을 수 있습니다. 한 브라우저에서 혼자 쓰는 할 일 목록은 간단한
웹페이지와 브라우저 저장소로 시작할 수 있습니다. 팀용 목록이라면 첫 버전의
범위를 검토할 때 데이터 공유 방식과 접근 권한 제안도 함께 살펴보세요.

이미 할 일이 분명하다면 바로 요청하세요. 짧은 질문이나 파일 조회는 이미 허용한 범위에서 바로 처리할 수 있습니다.

직접 요청한 오탈자·띄어쓰기·문장부호 교정은 새 Work 없이 처리할 수 있습니다. 프로젝트 규칙과 허용한 접근 범위 안에서 뜻과 동작이 유지되고, 별도 결과 검토나 보존, 인계가 필요 없을 때에만 해당합니다. 기존 Work에 속한 수정이라면 해당 Work의 승인 범위와 기록을 확인해 이어갑니다.

프로젝트 목표와 규칙은 작업 범위를 검토할 때 함께 다루거나 나중에
정리할 수 있습니다. 작업 범위를 승인하기 전에 파일 이름과 변경 내용을 확인하고, 계획을 기록하기 전에 [Colvia가 보관하는 내용](#본문과-백업)을 살펴보세요.

## 맡기고 검토하기

> 문의 유형과 자주 나오는 불편 사항을 정리해 회의용 보고서를 만들어 주세요. 개선 우선순위는 제가 정할게요.

에이전트가 만들 파일과 확인 기준을 제안합니다. 범위가 맞으면 진행하라고 답하세요. 작업을 마치면 에이전트가 검사 결과를 남기고 검토용으로 제출합니다. 제출본을 읽고 이 결과를 수락할지, 더 고칠지 결정하세요. Colvia는 어느 계획을 승인했고 어느 제출본을 수락했는지 기록합니다.

앱이나 CLI의 권한 요청은 에이전트가 어떤 파일을 읽고 쓰거나 어떤 도구를 쓸 수 있는지 정합니다. 작업 범위와 제출본은 각각 따로 확인하세요.

새 대화에서는 같은 프로젝트를 열고 “아까 맡긴 보고서에서 내가 확인할 부분만 보여줘”라고 물어보세요. Codex와 Claude Code를 모두 이용 중이라면 같은 프로젝트에서 두 에이전트를 번갈아 쓸 수 있습니다. 바꿔 쓰는 에이전트가 연결한 폴더와 Colvia 기록 폴더를 읽을 수 있으면 이전 기록을 찾을 수 있습니다. 앱이 만든 Git 작업 폴더라면 원래 프로젝트와 연결된 폴더인지 먼저 확인하세요.

여러 Work의 상태를 보관하는 것과 여러 에이전트가 동시에 같은 파일을 수정하는 것은 다릅니다. 첫 공개에서 실제 동시 실행을 지원한다고 가정하지 마세요. 겹치는 변경이나 확인할 수 없는 중단 상태에서는 멈추고 현재 상태를 확인합니다.

Colvia가 에이전트를 직접 호출하는 문서 실행은 첫 Preview에서 비활성입니다. Codex나 Claude Code의 일반 CLI와 데스크톱에서 작업하고 검토하는 흐름은 별개입니다.

다른 작업을 진행한 뒤 이전 결과를 고치려면, 고칠 부분을 말씀해 주세요. 에이전트는 기록된 수정 요청과 승인 범위, 마지막 제출 뒤 바뀐 내용을 확인해 이어갑니다. 기존 승인이 유효하고 요청한 수정이 그 범위 안에 있으면 같은 Work에서 이어갑니다. 다른 Work가 추가해 제출한 파일은 근거와 현재 내용이 일치할 때 구분하며, 출처가 불명확한 변경이나 범위 밖 수정·삭제는 원인 파일과 함께 안내합니다. 수정본은 보존되고, 결과를 받아들일지는 검토 후 결정합니다.

다른 작업의 추가 파일을 대조한 수정본을 다른 작업 폴더에 적용하는 기능은 아직 제공하지 않습니다. 해당 작업 폴더에서 결과를 검토·수락할 수 있습니다.

### 하위 Work와 격리 폴더의 결과

같은 폴더에서 큰 목표를 직접 하위 Work로 나눴다면 각 제출본을 검토하고 수락합니다. 격리 폴더(같은 저장소에 등록한 별도 Git 작업 폴더)의 결과를 반영할 때는 어느 제출본을 어느 대상 폴더에 반영할지 확인하세요. 아직 검토 중인 제출본이면 미리보기에서 반영과 수락을 함께 승인합니다. Colvia는 반영이 완료되고 대상 파일을 확인한 뒤 해당 제출본의 수락을 기록합니다. 이미 수락한 제출본이면 반영만 승인합니다. 반영 전에 대상 폴더를 확인하세요. 그 폴더에 승인됐거나 진행 중이거나 검토 중인 다른 Work가 있으면 Colvia가 반영을 멈춥니다. 한 건씩 반영하고, 여러 결과를 모은 상위 Work의 전체 결과와 검사 내용을 따로 검토해 수락합니다.

승인한 제출본을 대상 폴더에 반영하는 도중 멈췄다면 준비 기록이 남아 있는지 확인하세요. 그 기록이 있으면 승인한 제출본으로 반영을 이어갑니다. 대상 폴더의 연결과 공용 Git 정보가 유효해야 합니다. 준비 기록이나 대상 연결을 확인할 수 없다면 반영을 멈추고 진단을 요청하세요.

지정한 격리 Work의 반영과 수락을 위임할 때는 원본과 대상, 파일 범위, 지정한 대리인, 유효한 위임을 확인합니다. 이 위임은 지정한 격리 Work에 적용됩니다. 다른 Work와 상위 Work의 최종 결과를 수락할지는 사용자가 결정합니다.

Git에 등록은 남아 있는데 worktree 폴더가 사라졌다면 그 등록 상태를 먼저 확인하세요. 일반 Work 결과를 수락할 때는 해당 작업 폴더의 현재 파일을 대조합니다.

### 기록한 후속 작업 찾기

“회의 보고서 뒤에 무엇을 하기로 했지?”라고 물어보세요. 에이전트는
`ordinary list`로 해당 Work를 찾고, `ordinary view WORK_ID`로 작업을 보거나
`followup WORK_ID`로 기록한 후속 결정을 확인합니다. 모두 같은 프로젝트
실행기를 사용합니다. `candidate list`에서는 저장한 후보와 이미 연결한
Work를 볼 수 있습니다. 이 명령들은 기록을 조회합니다.

후속 선택을 기록한 적이 없는 경우, 후속 작업을 두지 않기로 한 경우,
결정을 미룬 경우를 각각 표시합니다. 후속 후보나 Work를 선택했다면 이름과
상태가 나옵니다. 선택한 뒤 계획이나 후보가 바뀌었다면 당시 기록과 연결된
선택이라고 표시합니다. 이어갈 때는 해당 Work의 범위 승인 기록을 확인하세요. 현재 범위에 유효한 승인이 있으면 재사용합니다.

작업 중 승인 범위 밖의 파일을 바꿔야 한다면 기존 수정본과 검사 결과를
보존합니다. 추가 파일·이유·새로 필요한 검사만 제시해 별도 Work로 승인받은
뒤 해당 파일을 수정하세요.

## 본문과 백업

Colvia는 계획을 기록할 때 계획에 적힌 기존 파일의 본문을 보관합니다. 승인 범위에서 바꾼 내용은 제출할 때 함께 보관해 나중에 검토한 판본을 읽을 수 있습니다. 계획에 필요한 파일만 적으세요. 범위 밖 파일의 변경 여부를 확인하는 정보는 본문과 구분해 보관합니다.

### 기록 백업과 복원

계획을 승인했는지와 관계없이 기록할 때 보관한 본문과 제출본은 백업에 들어갑니다. 프로젝트 자료와 같은 기준으로 백업을 보관하세요. Preview에서 보존 본문의 일부만 골라 지울 수 없으니, 어떤 자료를 보관할지 계획을 기록하기 전에 확인하세요.

Git commit이나 clone만으로 Colvia 기록이 백업되지는 않습니다. 기록·본문·설정·수락 이력을 옮기려면 Colvia의 내보내기와 복원을 사용합니다. 프로젝트 파일도 별도로 보관해야 합니다. 같은 기기에 만든 복구본만으로 기기 고장에 대비할 수는 없습니다.

### 업데이트와 중단 복구

공식 Colvia Preview를 이미 설치한 계정에서 업데이트하려면 [설치 페이지](https://colvia.github.io/downloads/)의 운영체제별 설치 명령을 다시 실행하세요. Colvia는 설치할 때 확인한 배포 주소에서 새 버전을 확인합니다. 이미 최신 판이면 같은 실행기를 계속 사용합니다.

업데이트 전에 등록된 기록의 복구본을 남기고, 기록에 필요한 기능과 새 실행기가 선언한 기능을 대조합니다. 이 호환성 확인이 모든 사용자 작업을 실제로 실행해 보는 것은 아닙니다. 이전 실행기로 돌아갈 때도 작업 이력을 과거로 되돌리지 않습니다.

업데이트가 중단되면 설치 파일을 바꾸기 전에 어디까지 진행됐는지 먼저 확인하세요. 재개하려면 준비한 배포본과 현재 상태가 일치하고 검증도 유효해야 합니다.

최초 설치의 다운로드가 중단됐다면 실패 기록을 보존한 상태에서 새로 다운로드할 수 있습니다. 이미 준비한 설치는 같은 파일로 재개합니다. 검증 유효기간이 지났다면 같은 배포 파일을 다시 인증하거나, 이전 실행기가 아직 선택돼 있을 때 중단된 갱신 파일만 이전 상태로 복구합니다. 다른 파일로 바뀐 배포 정보나 외부에서 수정한 파일은 덮어쓰지 않습니다. 보존한 파일을 지워 우회하지 마세요.

최초 설치가 일부 진행된 뒤 원래 배포본을 더 이상 사용할 수 없다면, 설치 상태와 격리 미리보기를 확인하세요. 이 설치가 만든 것으로 확인된 파일만 보존 격리하고 기존 신뢰 정보를 유지한 채 새 배포본을 준비할 수 있습니다. 격리 도중 중단되면 같은 작업을 재개하며, 출처가 불명확하거나 외부에서 바뀐 파일은 자동 정리하지 않습니다.

미완료 외부 작업이 남은 백업은 바로 실행 가능한 상태로 복원하지 않습니다. 원래 실행이 어디까지 반영됐는지 먼저 확인해야 합니다.

macOS에서 작업 폴더를 다시 확인하라는 안내가 나오면 해당 프로젝트와 폴더를 먼저 확인하세요. 미리보기에 표시된 프로젝트와 폴더를 백업과 대조한 뒤 확인을 적용하세요. 기존 작업 범위와 보관한 본문, 결정은 그대로 유지됩니다. 중간에 멈추면 실행 상태를 확인하고 같은 실행에서 남은 폴더만 이어서 처리하세요. 폴더를 옮기거나 교체했다면 [이동 조건](#프로젝트-폴더를-옮긴-뒤-이어가기)부터 확인하세요. 작업을 이어가려면 프로젝트의 연결 기록을 읽을 수 있는 실행기를 사용하세요.

### 기록을 보존하면서 Colvia 제거하기

설치에 사용한 표준 계정에서 [공식 설치 스크립트](https://colvia.github.io/downloads/)를 파일로 저장하세요. 열려 있는 Colvia 작업과 알림 창을 닫고, 진행 중인 Git 반영이나 갱신은 먼저 마무리하세요. 같은 계정의 기본 관리 폴더에서만 이 절차를 사용합니다.

1. **제거 범위를 확인하세요.** Windows에서는 일반 PowerShell에서 저장한 스크립트에 `-UninstallPreview <작업 ID>`를, macOS에서는 저장한 셸 스크립트에 `--uninstall-preview <작업 ID>`를 붙여 실행하세요. 작업 ID는 `remove-colvia`처럼 사용하지 않은 짧은 이름을 정하세요.
2. **확인한 범위를 제거하세요.** 출력에 표시된 실행기·실행환경과 보존 항목을 검토하세요. Windows에서 `-Uninstall <작업 ID> -Receipt <확인값>`, macOS에서 `--uninstall <작업 ID> <확인값>`을 사용합니다. 기존 Work·승인·제출본·프로젝트 연결·설정과 갱신 신뢰는 기본 관리 폴더에 남습니다. 검증한 설치 파일의 복구 자료는 해당 제거 작업 폴더에 따로 남습니다. 중단됐다면 같은 ID와 확인값으로 Windows의 `-ResumeUninstall` 또는 macOS의 `--resume-uninstall`을 사용하세요.
3. **필요할 때 다시 설치하세요.** 같은 계정에서 평소 설치 명령을 실행하세요. 같은 프로젝트를 열고 이전 Work와 제출본을 확인할 수 있습니다. 재설치가 중단되어 재개 안내가 뜨면 저장한 스크립트의 Windows `-ResumeReinstall` 또는 macOS `--resume-reinstall` 옵션으로 이어가세요. 기록이나 관리 폴더를 직접 지우지 마세요.

제거가 중단되고 아직 재설치를 시작하기 전이라면, Windows에서는 `-RestoreUninstall <작업 ID> -Receipt <확인값>`, macOS에서는 `--restore-uninstall <작업 ID> <확인값>`으로 설치 파일을 원래 위치에 복구하세요. Windows 알림을 사용했다면 제거를 되돌리거나 재설치한 뒤 다시 켜세요.

## 프로젝트 폴더를 옮긴 뒤 이어가기

### 에이전트에게 폴더 이동 확인을 맡기기

이미 폴더를 옮겼다면 프로젝트 폴더 밖에서 새 대화를 열고 다음처럼 요청하세요.

> 프로젝트 폴더를 옮겼어요. 새 위치에서 기존 Colvia 기록을 이어가게 해 주세요.

에이전트가 새 위치를 물으면 실제 경로를 알려 주세요. 필요한 접근 권한이 있으면 에이전트가 설치된 Colvia 관리자로 이동 미리보기를 준비할 수 있습니다. 미리보기에 나온 기존 위치와 새 위치를 확인하세요. Colvia가 같은 폴더임을 확인하면 기존 연결을 새 위치로 바꾸도록 승인하세요. 에이전트가 그 미리보기로 적용한 뒤 새 위치에서 프로젝트를 열고 이전 Work를 확인할 수 있습니다.

아직 폴더를 옮기기 전이라면 에이전트에게 먼저 이동 조건을 확인해 달라고 하세요. 원래 위치에서 진행 중인 실행·전달·Git 통합·복구를 마무리하거나 중단 상태를 해결하세요. 최신 Colvia 백업과 프로젝트 파일 사본을 따로 보관하세요. 폴더를 열어 둔 대화와 실행기를 닫고 같은 로컬 볼륨에서 폴더 자체를 옮긴 뒤 위 요청으로 이어갑니다.

일반 폴더 또는 자체 `.git` 디렉터리를 가진 단일 Git checkout에서 사용할
수 있습니다. 연결된 worktree나 submodule이 없어야 하고, 다른 Colvia
프로젝트와 겹치면 안 됩니다. 원래 경로에 폴더가 남아 있으면 안 되며, Colvia가
옮긴 폴더의 동일성을 검증해야 합니다. 복사본, 다른 볼륨, 다른 Colvia
프로젝트 하위의 위치는 이 확인에서 거부될 수 있습니다. 겹치면 다른
프로젝트 바깥의 위치를 사용하세요. 양쪽 파일과 기록을 보존하고 연결
파일이나 DB는 그대로 두세요. macOS에서 폴더를 다시 확인하라는 안내가 나오면
[현재 연결을 확인하는 절차](#업데이트와-중단-복구)를 따르세요.

### 명령으로 직접 확인하기

직접 명령을 쓰거나 에이전트에 필요한 접근 권한을 줄 방법이 없다면, 프로젝트 폴더 밖에서 설치된 관리자를 사용합니다. 기존 프로젝트 ID와
새 절대 경로를 넣고, 개인 로컬 폴더에 새 이름으로 미리보기를 저장하세요.
다음은 macOS 터미널 예입니다.

```sh
"$HOME/Library/Application Support/Colvia/bin/colvia" manage --json move-preview PROJECT_ID "/path/to/moved-project" > move-preview.json
```

Windows에서는 표준 사용자의 명령 프롬프트에서 저장하세요. Windows
PowerShell 5.1은 출력 파일의 문자 인코딩을 바꿀 수 있습니다.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage --json move-preview PROJECT_ID "C:\Work\MovedProject" > move-preview.json
```

미리보기가 성공하면 기존 위치와 새 위치를 확인하세요. 승인 뒤 위에 나온
같은 관리자 실행 경로에서 `manage move-apply --plan move-preview.json --receipt RECEIPT_FROM_PREVIEW --statement "YOUR_APPROVAL" --operation OPERATION_ID`로
저장한 원본 파일과 그 안의 확인값을 적용합니다. 파일을 다시 저장하지
말고, 적용을 시작할 때는 새 실행 ID를 사용하세요. 중단되면
`manage move-status OPERATION_ID`로 확인합니다. 승인 후 아직 반영 중이라면
`manage move-resume OPERATION_ID`에 같은 ID를 넣어 이어갑니다. 충돌하거나
원래 위치가 남아 있다면 양쪽을 보존하고 진단을 요청하세요. 완료 후 새
폴더를 열면 됩니다. 연결 위치를 갱신하고 Work의 기록·결정·보존 본문은
유지합니다.

현재 이동이 확인된 환경은 macOS 로컬 APFS의 일반 폴더와 Git 폴더입니다.
Windows NTFS에서 이미 옮겼다면 기존 연결 정보와 기록을 보존하고 진단을 요청하세요.
이동을 마친 기록을 열 때는 해당 기록과 호환되는 실행기가 필요합니다.

## Git을 사용할 때

### Git 등록하기

일반 폴더는 바로 연결할 수 있습니다. Git을 사용하는 프로젝트 폴더라면 저장소를 연결하기 전에 평소 쓰는 채팅에서 요청하세요.

> 이 프로젝트에서 쓰는 Git을 Colvia에 등록해 주세요.

에이전트가 현재 환경에서 쓰는 Git 실행 파일을 찾아 등록 미리보기를 준비할 수 있습니다. 경로가 여러 개라면 실제로 쓰는 Git을 골라 주세요. 미리보기에서 경로를 확인하고 등록을 승인하면, 에이전트가 미리보기 원본으로 등록을 적용합니다. 기존 등록을 바꾸는 경우에는 교체할 경로를 확인하고 별도로 승인하세요. 등록을 확인한 뒤 저장소의 최상위 폴더에서 연결을 요청하세요. 같은 Colvia 설치에서 이미 등록한 Git은 다른 프로젝트를 연결할 때도 사용할 수 있습니다.

앱이나 CLI가 등록에 필요한 경로나 실행을 막으면, 에이전트에게 어느 접근이 필요한지 확인하세요. 앱에서 필요한 범위만 허용할 수 있으면 그 방법을 쓰고, 직접 진행하려면 [아래 명령](#명령으로-git-등록하기)을 사용하세요.

#### 명령으로 Git 등록하기

신뢰하는 Git 설치의 실행 파일을 지정하세요. Windows PowerShell에서 `(Get-Command git).Source`로 사용 중인 Git 경로를 확인할 수 있습니다. 일반 PowerShell은 설치에 사용하고, 미리보기 원본을 파일로 저장할 때는 명령 프롬프트(cmd.exe)를 사용하세요. Windows PowerShell 5.1의 `>` 또는 `Out-File`은 출력의 인코딩을 바꿀 수 있습니다.

명령 프롬프트에서 아직 `git-registration.json`이 없는 로컬 NTFS 폴더를 사용하세요. 아래 예의 Git 경로는 방금 확인한 실제 절대 경로로 바꾸세요.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage git-register-preview "C:\Path\To\Git\cmd\git.exe" > git-registration.json
```

이 미리보기는 Git을 실행하지 않습니다. 저장한 파일을 읽어 Git 경로, 파일 해시, `receipt` 값을 확인하세요. `receipt`는 미리보기에 들어 있는 확인값입니다. 파일을 편집하거나 다시 저장하지 마세요. 미리보기에서 오류가 나면 그 파일을 적용하지 마세요. 안내된 원인을 해결한 뒤 다른 이름으로 새 미리보기를 저장하세요. 검토 후 등록을 승인했다면 같은 명령 프롬프트에서 아래의 `RECEIPT_FROM_PREVIEW`를 그 값으로 바꿔 적용하세요. 기존 등록을 바꿀 때는 교체를 확인한 뒤에만 `--replace`를 붙입니다.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage git-register --plan git-registration.json --receipt "RECEIPT_FROM_PREVIEW"
```

macOS에서는 아직 `git-registration.json`이 없는 로컬 폴더에서 터미널을 여세요. 아래의 `/path/to/git`은 사용 중인 Git 실행 파일의 절대 경로로 바꿉니다. 미리보기를 저장해 위와 같은 방식으로 검토한 뒤, 등록을 승인했다면 `RECEIPT_FROM_PREVIEW`를 확인값으로 바꿔 적용하세요.

```sh
"$HOME/Library/Application Support/Colvia/bin/colvia" manage git-register-preview "/path/to/git" > git-registration.json
"$HOME/Library/Application Support/Colvia/bin/colvia" manage git-register --plan git-registration.json --receipt "RECEIPT_FROM_PREVIEW"
```

미리보기를 검토하고 등록을 승인하면 Colvia 관리자가 선택한 실행 파일의 해시를 다시 확인한 뒤 Git 버전을 조회합니다. 해시는 그 실행 파일만 다루므로 Git 설치 출처와 함께 설치된 구성요소도 신뢰할 수 있어야 합니다.

### Git에 결과 반영하기

결과를 수락한 뒤 Git에 반영하려면 커밋에 들어갈 변경 전체와 현재 스테이징 상태를 확인하고 별도로 승인하세요.

작업 중 branch를 바꾸거나 pull·rebase로 기준이 바뀌면 자동으로 새 기준을 승인하지 않습니다. 범위 밖 변경을 숨기지 않고, 이어갈 방법을 확인합니다. 프로젝트 하위 폴더의 독립 연결이나 Git 사용 여부가 바뀐 폴더의 자동 전환은 첫 공개 경로에서 제외합니다. 심볼릭 링크와 submodule은 그대로 보호할 수 있지만 편집 대상으로 삼지 않습니다.

Git hook이 있거나 자동 통합 조건을 만족하지 않으면 Colvia가 임의로 hook을 끄거나 index를 초기화하지 않습니다. 수동 Git 작업으로 이어갈 때도 수락한 결과와 commit할 내용을 다시 대조하세요. Colvia의 Git 통합이 중단됐다면 `index.lock`을 지우거나 새 commit을 만들지 마세요. 원본 index를 보존하는 도중 현재 index가 잠시 없을 수 있습니다. 통합 상태를 조회하고 복구 경로로 이어가며, 잠금 소유자를 확인하지 못하면 먼저 진단해야 합니다. Windows의 Git 통합은 같은 볼륨의 준비 공간이 필요하며, 실행 비트가 없는 hook 파일도 활성 hook으로 취급합니다.

Windows에서 Colvia의 Git 통합이 중단되면 에이전트에게 “중단된 Git 통합 상태와 잠금 위치를 확인해 줘”라고 요청하세요. Colvia가 잠금 파일을 옮기기 전에 남긴 기록과 현재 파일이 일치하면 상태 확인 뒤 복구를 이어갈 수 있습니다. Git 반영 전 중단이면 이번 반영을 하지 않은 상태로 정리하고, 이미 반영을 시작했다면 승인된 변경의 완료 여부를 확인합니다. 다른 Git 프로그램의 잠금, 변경된 파일, Colvia가 만든 것으로 확인할 근거가 없는 잠금은 자동으로 가져오거나 지우지 않습니다. 다른 Git 작업이 끝났는데도 계속 막히면 중단 기록을 보존해 진단을 요청하세요. Work 수락과 새 Git 반영 승인은 이 복구와 별개입니다.

## 알림과 연결 해제

### 알림 설정하기

현재 설치본의 알림 수신기를 연결하고 운영체제에서 알림을 허용하세요. 알림을 사용할 수 있는 환경에서는 알림을 눌러 해당 Work를 열고, 제출본을 읽은 뒤 수락할지 결정합니다.

Windows에서 수신기가 업데이트됐다면 새 알림을 보내기 전에 현재 설치본에서 알림 연결을 다시 확인하세요. 전달 여부를 확인할 수 없으면 새 알림을 자동으로 보내지 않습니다. 같은 프로젝트 대화에서 “검토할 결과가 있나요?”라고 물어보세요.

새 알림을 그만 받으려면 에이전트에게 “이 계정의 Colvia 알림을 꺼 주세요.”라고 요청하세요. 설치된 관리자의 `notice-disable` 명령을 사용합니다. Work의 기존 기록은 남습니다.

### 프로젝트 연결 해제하기

같은 프로젝트에서 “내 파일과 기록을 보존하면서 Colvia 연결만 해제하려고 해요. 변경 미리보기를 보여 주세요”라고 요청하세요. Colvia가 관리하는 연결 정보와 안내를 확인한 뒤 해제를 승인합니다. 사용자가 작성한 파일과 작업 기록은 보존합니다. 이전 작업을 나중에 이어갈 계획이라면 연결 해제 전에 [기록을 백업하세요](#기록-백업과-복원). 복원한 기록을 폴더에 연결할 때는 폴더의 정체성과 변경 내용을 확인합니다. 설치 환경을 정리하려면 [기록을 보존하는 제거 절차](#기록을-보존하면서-colvia-제거하기)를 사용하세요.

## 지원 환경

Colvia Preview는 macOS Apple Silicon과 Windows 11 x64·ARM64에서 Codex와 Claude Code의 CLI·데스크톱 앱을 대상으로 합니다. Windows에서는 Windows용 앱과 CLI를 대상으로 합니다. WSL은 Linux 지원을 검토할 때 함께 다룹니다. 현재 파일시스템 경계는 macOS의 로컬 APFS와 Windows의 로컬 NTFS입니다. 네트워크 공유, 동기화되는 기록 저장소, Windows ReFS·Dev Drive는 검증하지 않았습니다.

설치와 갱신을 시작할 때는 운영체제에 맞는 공식 설치 명령을 사용하세요. 설치나 갱신이 멈췄다면 [업데이트와 중단 복구](#업데이트와-중단-복구)에서 현재 상태에 맞는 절차를 확인하세요. 격리 폴더의 제출본 반영을 다시 시작할 때는 준비 기록과 대상 폴더의 연결부터 확인하세요.

에이전트에 따라 작업 폴더뿐 아니라 Colvia 기록 폴더의 접근을 허용해야 할 수 있습니다. 검증한 Windows x64 설정은 사용자 승인과 지정 기록 폴더 쓰기를 허용한 Codex 앱, MXC를 사용한 Codex CLI 0.167.1입니다. 다른 앱 버전과 승인 방식은 확인 범위가 다를 수 있습니다. Linux와 추가 에이전트는 후속 후보입니다.

파일 수와 변경량에 따라 기록·백업에 필요한 공간과 처리 시간이 달라집니다. 기록을 자동으로 삭제하지 않으므로 큰 파일이 있는 프로젝트에서는 저장 공간을 확인하세요.

### 문서 실행 준비 상태 확인

첫 Preview에서 Colvia의 에이전트 직접 호출 기능은 비활성입니다. 설치된 실행기의 `execution readiness`로 현재 설정을 확인할 수 있습니다. 이 명령은 프로젝트 기록을 열거나 모델을 시작하지 않습니다. 필요한 파일이 바뀌었거나 없다면 표시된 상태를 확인하세요.
