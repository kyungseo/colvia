# 새 Preview의 설치와 작업 기록

이 안내는 작업 기록을 SQLite에 보관하는 새 Preview용입니다. 이전 시험본의 `.hrn/` 기록을 자동으로 옮기지는 않습니다.

## 설치하고 프로젝트에 적용하기

공개 배포에서는 운영체제별로 같은 명령을 처음 설치할 때와 기존 설치본을 갱신할 때 쓰는 경로를 준비하고 있습니다. 필요한 파일을 내려받고 검증한 뒤 전용 Python을 준비하고 버전을 선택하는 일은 Colvia가 맡습니다. Python ZIP을 고르거나 pyenv와 PATH를 조정할 필요가 없습니다. 공개 주소와 실행 명령은 Preview 배포와 함께 안내합니다.

Windows에서는 시작 메뉴에서 일반 PowerShell을 표준 사용자로 열어 설치 명령을 실행하세요. 앱 전용 셸에서 설치 위치를 확인할 수 없다는 안내가 나오면 일반 PowerShell에서 이어가세요. 디스크 공간이 부족하다는 안내가 나오면 표시된 필요 공간과 여유 공간을 확인하세요.

설치가 끝나면 사용할 프로젝트 폴더에서 Codex 또는 Claude Code를 열고 요청하세요.

> 이 폴더에 Colvia를 적용하려고 해. 기존 파일을 보존하면서 어떤 변경이 필요한지 보여줘.

빈 폴더와 기존 프로젝트 모두 연결 대상입니다. Git을 쓰는 프로젝트는 [Git 실행 파일을 등록](#git을-사용할-때)한 뒤 저장소의 최상위 폴더에서 연결합니다. 연결 전에는 추가할 실행 파일과 에이전트 안내, 기록을 저장할 위치를 확인합니다. 기존 지침은 보존하고 Colvia 안내 부분만 추가합니다. 연결한 폴더에서는 macOS의 `./colvia guide` 또는 Windows의 프로젝트 실행기 `colvia.cmd`(PowerShell에서는 `.\colvia.cmd guide`)로 안내를 읽습니다. 에이전트는 같은 실행기로 `ordinary list`를 호출해 현재 작업을 확인합니다.

작업 기록은 프로젝트별로 구분해 운영체제의 사용자 데이터 폴더에 보관합니다. 프로젝트 폴더에는 연결 정보와 진입 안내를 둡니다. 앱과 CLI는 같은 전용 실행기를 사용합니다. 접근이 막히면 실행기를 실행할 권한이 필요한지, 파일이나 기록 폴더를 읽거나 쓸 권한이 필요한지 먼저 확인합니다. 호스트가 필요한 경로만 허용하는 지원 방법을 제공할 때 그 방법을 사용합니다. 그런 방법이 없다면 해당 변경을 멈추고, 에이전트가 막힌 부분과 확인된 다음 조작만 짧게 안내합니다. 전체 파일 접근이나 시험 기능 활성화를 기본 해결책으로 안내하지 않습니다.

운영체제의 실행 허용, 알림 허용, Codex·Claude 구독 로그인은 사용자가 직접 해야 할 수 있습니다. 이는 전용 Python 준비와 별개입니다.

## 하고 싶은 일부터 시작하기

> 팀 회의에서 나온 할 일을 모아 관리하는 작은 프로젝트를 시작하고 싶어요.

프로젝트 자료가 없는 폴더에서는 에이전트가 현재 상태를 설명하고, 아이디어를
목표와 첫 작업으로 구체화합니다. 하려는 일을 한두 문장으로 말씀해 주세요.
브리프, README, 기존 규칙이 있다면 알려 주세요. 이미 정한 내용을 바탕으로
작업안을 제안합니다.

문서라면 목차와 검토 기준을, 새 앱이라면 첫 버전의 범위와 권장 기술, 실행·검증
방법을 제안받을 수 있습니다. 한 브라우저에서 혼자 쓰는 할 일 목록은 간단한
웹페이지와 브라우저 저장소로 시작할 수 있습니다. 팀용 목록이라면 첫 버전의
범위를 검토할 때 데이터 공유 방식과 접근 권한 제안도 함께 살펴보세요.

이미 할 일이 분명하다면 바로 요청하세요. 짧은 질문이나 파일 조회는 이미 허용한 범위에서 바로 처리할 수 있습니다. 변경 결과를 검토하고 보존하려면 에이전트에게 Work를 제안받으세요. 프로젝트 목표와 규칙은 작업 범위를 검토할 때 함께 다루거나 나중에
정리할 수 있습니다. 작업 범위를 승인하기 전에 파일 이름과 변경 내용을 확인하고, 계획을 기록하기 전에 [보존하는 내용](#본문과-백업)을 살펴보세요.

## 맡기고 검토하기

> 문의.csv로 회의용 보고서를 만들어줘. 문의 유형과 안내 개선안을 비교하고, 우선순위는 내가 정할게.

에이전트가 만들 파일과 확인할 내용을 제안합니다. 범위가 맞으면 진행하라고 답하세요. 승인한 작업이 준비되면 에이전트가 검사 결과를 남기고 검토용으로 제출합니다. 마지막에는 그 결과를 수락할지, 더 고칠지 결정하세요. 호스트의 권한 창은 파일이나 도구 접근을 결정합니다. Work 범위와 결과는 각각 사용자가 결정합니다.

새 대화에서는 같은 프로젝트를 열고 “아까 맡긴 보고서에서 내가 확인할 부분만 보여줘”라고 물어보세요. 다른 에이전트로 바꿔도 같은 프로젝트의 기록을 읽을 수 있도록 설계했습니다. 연결한 폴더와 기록 폴더에 그 에이전트가 접근할 수 있어야 합니다. 앱이 만든 worktree에서도 원래 프로젝트와의 관계를 먼저 확인합니다.

여러 Work의 상태를 보관하는 것과 여러 에이전트가 동시에 같은 파일을 수정하는 것은 다릅니다. 첫 공개에서 실제 동시 실행을 지원한다고 가정하지 마세요. 겹치는 변경이나 확인할 수 없는 중단 상태에서는 멈추고 현재 상태를 확인합니다.

다른 작업 폴더의 결과를 적용할 때는 적용할 결과와 대상 폴더를 따로 확인합니다. 그 결과의 적용을 승인하고 반영을 시작한 뒤에는 원 폴더가 없어지거나 원 파일이 바뀌어도 보존한 결과만 사용합니다. 나중에 편집한 내용까지 수락하는 것은 아닙니다. 대상 폴더와 프로젝트 연결은 여전히 정상이어야 하며, 공용 Git 정보까지 삭제됐다면 완료할 수 없습니다. 폴더만 삭제해 Git에 오래된 작업 폴더 등록이 남은 경우에도 먼저 Git 작업 폴더 상태를 확인해야 합니다. 일반적인 결과 수락에서는 계속 현재 파일을 확인합니다.

Colvia가 에이전트를 직접 호출하는 문서 실행은 첫 Preview에서 비활성입니다. Codex나 Claude Code의 일반 CLI와 데스크톱에서 작업하고 검토하는 흐름은 별개입니다.

다른 작업을 진행한 뒤 이전 결과를 고치려면, 고칠 부분을 말씀해 주세요. 에이전트는 기록된 수정 요청과 승인 범위, 마지막 제출 뒤 바뀐 내용을 확인해 이어갑니다. 같은 범위를 다시 승인할 필요는 없습니다. 다른 Work가 추가해 제출한 파일은 근거와 현재 내용이 일치할 때 구분하며, 출처가 불명확한 변경이나 범위 밖 수정·삭제는 원인 파일과 함께 안내합니다. 수정본은 보존되고, 결과를 받아들일지는 검토 후 결정합니다.

다른 작업의 추가 파일을 대조한 수정본을 다른 작업 폴더에 적용하는 기능은 아직 제공하지 않습니다. 해당 작업 폴더에서 결과를 검토·수락할 수 있습니다.

### 기록한 후속 작업 찾기

“회의 보고서 뒤에 무엇을 하기로 했지?”라고 물어보세요. 에이전트는
`ordinary list`로 해당 Work를 찾고, `ordinary view WORK_ID`로 작업을 보거나
`followup WORK_ID`로 기록한 후속 결정을 확인합니다. 모두 같은 프로젝트
실행기를 사용합니다. `candidate list`에서는 저장한 후보와 이미 연결한
Work를 볼 수 있습니다. 이 명령들은 기록을 조회합니다.

후속 선택을 기록한 적이 없는 경우, 후속 작업을 두지 않기로 한 경우,
결정을 미룬 경우를 각각 표시합니다. 후속 후보나 Work를 선택했다면 이름과
상태가 나옵니다. 선택한 뒤 계획이나 후보가 바뀌었다면 당시 기록과 연결된
선택이라고 표시합니다. 이어갈 때는 해당 Work의 범위 승인 기록을 확인하세요. 현재 범위에 유효한 승인이 있으면 재사용합니다.

작업 중 승인 범위 밖의 파일을 바꿔야 한다면 기존 수정본과 검사 결과를
보존합니다. 추가 파일·이유·새로 필요한 검사만 제시해 별도 Work로 승인받은
뒤 해당 파일을 수정하세요.

## 본문과 백업

Colvia는 계획을 기록할 때 계획에 적힌 기존 파일의 본문을 보존합니다. 승인 범위에서 바꾼 내용은 제출할 때 함께 보존해 나중에 검토한 판본을 읽을 수 있습니다. 비밀번호나 API 키, 불필요한 파일은 계획을 기록하기 전에 제외하세요. 범위 밖 파일의 변경 여부를 확인하는 정보는 구분해 보관합니다.

계획을 승인하지 않아도 기록할 때 담긴 본문은 보존되고 내보낸 백업에도 들어갑니다. Preview에서는 보존 본문의 일부만 골라 지울 수 없습니다. 기록할 대상과 백업 보관 위치를 정할 때 이 점을 고려하세요.

Git commit이나 clone만으로 Colvia 기록이 백업되지는 않습니다. 기록·본문·설정·수락 이력을 옮기려면 Colvia의 내보내기와 복원을 사용합니다. 프로젝트 파일도 별도로 보관해야 합니다. 같은 기기에 만든 복구본만으로 기기 고장에 대비할 수는 없습니다.

업데이트 전에 등록된 기록의 복구본을 남기고, 기록에 필요한 기능과 새 실행기가 선언한 기능을 대조합니다. 이 호환성 확인이 모든 사용자 작업을 실제로 실행해 보는 것은 아닙니다. 이전 실행기로 돌아갈 때도 작업 이력을 과거로 되돌리지 않습니다. 업데이트가 중단되면 새로 설치해 덮지 말고 멈춘 작업을 먼저 확인하세요. 재개하려면 준비한 배포본과 현재 상태가 일치하고 검증도 유효해야 합니다. 최초 설치의 다운로드가 중단됐다면 실패 기록을 남긴 채 새 시도로 이어갈 수 있습니다. 이미 준비한 설치는 같은 파일로 재개합니다. 검증 유효기간이 지났다면 같은 배포 파일을 다시 인증하거나, 이전 실행기가 아직 선택돼 있을 때 중단된 갱신 파일만 이전 상태로 복구합니다. 다른 파일로 바뀐 배포 정보나 외부에서 수정한 파일은 덮어쓰지 않습니다. 아래 비공개 HTTPS 시험에서는 중단 복구, 재인증, 격리를 확인하지 않았습니다. 일부만 설치된 파일을 격리하는 절차는 합성 소스 검사에서 확인했습니다. 보존한 파일을 지워 우회하지 마세요. 최초 설치가 일부 진행된 뒤 원래 배포본을 더 이상 사용할 수 없다면, 설치 상태와 격리 미리보기를 확인하세요. 이 설치가 만든 것으로 확인된 파일만 보존 격리하고 기존 신뢰 정보를 유지한 채 새 배포본을 준비할 수 있습니다. 격리 도중 중단되면 같은 작업을 재개하며, 출처가 불명확하거나 외부에서 바뀐 파일은 자동 정리하지 않습니다.

미완료 외부 작업이 남은 백업은 바로 실행 가능한 상태로 복원하지 않습니다. 원래 실행이 어디까지 반영됐는지 먼저 확인해야 합니다.

macOS에서 예전에 연결한 프로젝트는 작업 폴더를 다시 확인해야 할 수 있습니다. 미리보기에 표시된 프로젝트와 폴더를 백업과 대조한 뒤 확인을 적용하세요. 기존 작업 범위와 보관한 본문, 결정은 그대로 유지됩니다. 중간에 멈추면 실행 상태를 확인하고 같은 실행에서 남은 폴더만 이어서 처리하세요. 폴더를 옮기거나 교체했다면 [이동 조건](#프로젝트-폴더를-옮긴-뒤-이어가기)부터 확인하세요. 새 연결 기록을 읽지 못하는 이전 실행기로는 해당 기록을 열 수 없습니다.

## 프로젝트 폴더를 옮긴 뒤 이어가기

원래 위치에서 진행 중인 실행·전달·Git 통합·복구를 먼저 마무리하거나
중단 상태를 확인해 해결하세요. 최신 Colvia 백업과 프로젝트 파일 사본을
따로 보관합니다. 프로젝트를 열어 둔 에이전트 대화와 실행기를 닫고,
같은 로컬 볼륨에서 폴더 자체를 옮기세요. Colvia가 새 위치를 확인한 뒤
프로젝트를 다시 엽니다. 이미 옮겼다면 “프로젝트 폴더를 옮겼어. 기존
기록으로 이어갈 수 있는지 확인해 줘”라고 요청하세요.

일반 폴더 또는 자체 `.git` 디렉터리를 가진 단일 Git checkout에서 사용할
수 있습니다. 연결된 worktree나 submodule이 없어야 하고, 다른 Colvia
프로젝트와 겹치면 안 됩니다. 원래 경로에 폴더가 남아 있으면 안 되며, Colvia가
옮긴 폴더의 동일성을 검증해야 합니다. 복사본, 다른 볼륨, 다른 Colvia
프로젝트 하위의 위치는 이 확인에서 거부될 수 있습니다. 겹치면 다른
프로젝트 바깥의 위치를 사용하세요. 양쪽 파일과 기록을 보존하고 연결
파일이나 DB는 그대로 두세요. 예전 macOS 연결에는 [위의 같은 위치 확인](#본문과-백업)이
먼저 필요할 수 있습니다.

프로젝트 폴더 밖에서 설치된 관리자를 사용합니다. 기존 프로젝트 ID와
새 절대 경로를 넣고, 개인 로컬 폴더에 새 이름으로 미리보기를 저장하세요.
다음은 macOS 터미널 예입니다.

```sh
"$HOME/Library/Application Support/Colvia/bin/colvia" manage --json move-preview PROJECT_ID "/path/to/moved-project" > move-preview.json
```

Windows에서는 표준 사용자의 명령 프롬프트에서 저장하세요. Windows
PowerShell 5.1은 출력 파일의 문자 인코딩을 바꿀 수 있습니다.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage --json move-preview PROJECT_ID "C:\Work\MovedProject" > move-preview.json
```

미리보기가 성공하면 기존 위치와 새 위치를 확인하세요. 승인 뒤 위에 나온
같은 관리자 실행 경로에서 `manage move-apply --plan move-preview.json --receipt RECEIPT_FROM_PREVIEW --statement "YOUR_APPROVAL" --operation OPERATION_ID`로
저장한 원본 파일과 그 안의 확인값을 적용합니다. 파일을 다시 저장하지
말고, 적용을 시작할 때는 새 실행 ID를 사용하세요. 중단되면
`manage move-status OPERATION_ID`로 확인합니다. 승인 후 아직 반영 중이라면
`manage move-resume OPERATION_ID`에 같은 ID를 넣어 이어갑니다. 충돌하거나
원래 위치가 남아 있다면 양쪽을 보존하고 진단을 요청하세요. 완료 후 새
폴더를 열면 됩니다. 연결 위치를 갱신하고 Work의 기록·결정·보존 본문은
유지합니다.

로컬 APFS에서 일반 폴더와 Git 폴더의 이동을 소스 검사로 확인했습니다. Windows NTFS
이동과 이전 실행기·복구 런타임의 동작은 최종 후보에서 확인합니다. 이동을
마친 기록을 열 때는 해당 기록과 호환되는 런타임이 필요합니다.

## Git을 사용할 때

일반 폴더는 Git을 등록하지 않고 연결할 수 있습니다. Git 저장소를 연결하기 전에는 신뢰하는 Git 설치의 실행 파일을 Colvia 관리자에 등록하세요. Windows PowerShell에서 `(Get-Command git).Source`로 사용 중인 Git 경로를 확인할 수 있습니다. 일반 PowerShell은 설치에 사용하고, 미리보기 원본을 파일로 저장할 때는 명령 프롬프트(cmd.exe)를 사용하세요. Windows PowerShell 5.1의 `>` 또는 `Out-File`은 출력의 인코딩을 바꿀 수 있습니다.

명령 프롬프트에서 아직 `git-registration.json`이 없는 로컬 NTFS 폴더를 사용하세요. 아래 예의 Git 경로는 방금 확인한 실제 절대 경로로 바꾸세요.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage git-register-preview "C:\Path\To\Git\cmd\git.exe" > git-registration.json
```

이 미리보기는 Git을 실행하지 않습니다. 저장한 파일을 읽어 Git 경로, 파일 해시, `receipt` 값을 확인하세요. `receipt`는 미리보기에 들어 있는 확인값입니다. 파일을 편집하거나 다시 저장하지 마세요. 미리보기에서 오류가 나면 그 파일을 적용하지 마세요. 안내된 원인을 해결한 뒤 다른 이름으로 새 미리보기를 저장하세요. 검토 후 등록을 승인했다면 같은 명령 프롬프트에서 아래의 `RECEIPT_FROM_PREVIEW`를 그 값으로 바꿔 적용하세요. 기존 등록을 바꿀 때는 교체를 확인한 뒤에만 `--replace`를 붙입니다.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage git-register --plan git-registration.json --receipt "RECEIPT_FROM_PREVIEW"
```

macOS에서는 아직 `git-registration.json`이 없는 로컬 폴더에서 터미널을 여세요. 아래의 `/path/to/git`은 사용 중인 Git 실행 파일의 절대 경로로 바꿉니다. 미리보기를 저장해 위와 같은 방식으로 검토한 뒤, 등록을 승인했다면 `RECEIPT_FROM_PREVIEW`를 확인값으로 바꿔 적용하세요.

```sh
"$HOME/Library/Application Support/Colvia/bin/colvia" manage git-register-preview "/path/to/git" > git-registration.json
"$HOME/Library/Application Support/Colvia/bin/colvia" manage git-register --plan git-registration.json --receipt "RECEIPT_FROM_PREVIEW"
```

등록을 적용할 때 관리자가 선택한 실행 파일의 해시를 검증하고 버전을 확인합니다. 해시는 그 실행 파일만 다루므로 Git 설치 출처와 함께 설치된 구성요소도 신뢰할 수 있어야 합니다.

보고서를 수락하는 결정과 Git에 commit하는 결정은 따로 합니다. 수락은 “이 결과를 받아들인다”는 기록입니다. Git 통합에서는 commit에 들어갈 전체 변경과 현재 staging 상태를 별도로 확인합니다.

작업 중 branch를 바꾸거나 pull·rebase로 기준이 바뀌면 자동으로 새 기준을 승인하지 않습니다. 범위 밖 변경을 숨기지 않고, 이어갈 방법을 확인합니다. 프로젝트 하위 폴더의 독립 연결이나 Git 사용 여부가 바뀐 폴더의 자동 전환은 첫 공개 경로에서 제외합니다. 심볼릭 링크와 submodule은 그대로 보호할 수 있지만 편집 대상으로 삼지 않습니다.

Git hook이 있거나 자동 통합 조건을 만족하지 않으면 Colvia가 임의로 hook을 끄거나 index를 초기화하지 않습니다. 수동 Git 작업으로 이어갈 때도 수락한 결과와 commit할 내용을 다시 대조하세요. Colvia의 Git 통합이 중단됐다면 `index.lock`을 지우거나 새 commit을 만들지 마세요. 원본 index를 보존하는 도중 현재 index가 잠시 없을 수 있습니다. 통합 상태를 조회하고 복구 경로로 이어가며, 잠금 소유자를 확인하지 못하면 먼저 진단해야 합니다. Windows의 Git 통합은 같은 볼륨의 준비 공간이 필요하며, 실행 비트가 없는 hook 파일도 활성 hook으로 취급합니다.

Windows에서 Colvia의 Git 통합이 중단되면 에이전트에게 “중단된 Git 통합 상태와 잠금 위치를 확인해 줘”라고 요청하세요. 새 버전이 이동 전에 기록한 잠금 파일과 현재 파일이 일치하면 기존 복구 명령으로 이어갈 수 있습니다. Git 반영 전 중단이면 이번 반영을 하지 않은 상태로 정리하고, 이미 반영을 시작했다면 승인된 변경의 완료 여부를 확인합니다. 다른 Git 프로그램의 잠금, 변경된 파일, 사전 근거가 없는 이전 잠금은 자동으로 가져오거나 지우지 않습니다. 다른 Git 작업이 끝났는데도 계속 막히면 중단 기록을 보존해 진단을 요청하세요. Work 수락과 새 Git 반영 승인은 이 복구와 별개입니다.

## 알림과 연결 해제

알림을 쓰려면 현재 설치본의 수신기를 연결하고 운영체제에서 알림을 허용해야 합니다. Windows에서 수신기가 갱신됐다면 새 알림을 보내기 전에 현재 설치본으로 알림 연결을 다시 확인합니다. 알림은 결과를 찾는 지름길입니다. 알림을 눌러도 결과가 자동으로 수락되지는 않습니다. 전달 여부를 확인할 수 없으면 자동 재전송하지 않고, 프로젝트 채팅에서 결과를 확인할 수 있게 남깁니다.

Colvia 적용을 해제하면 Colvia가 관리하는 연결 정보와 안내를 확인한 뒤 제거합니다. 사용자가 작성한 파일과 작업 기록은 보존합니다. 다시 연결하거나 복원한 기록을 새 폴더에 적용할 때도 폴더의 정체성과 변경 내용을 확인합니다. 연결 해제와 기록 전체 삭제를 같은 작업으로 취급하지 않습니다.

## 지원 목표와 확인 상태

첫 공개 목표는 macOS Apple Silicon ARM64와 Windows 11 ARM64·x64입니다. Codex와 Claude Code의 CLI·데스크톱 앱을 대상으로 합니다. Windows 경로는 native Windows 프로세스를 뜻하며 WSL은 Linux 후속 지원에 포함합니다. 현재 파일시스템 경계는 macOS의 로컬 APFS와 Windows의 로컬 NTFS입니다. 네트워크 공유, 동기화되는 기록 저장소, Windows ReFS·Dev Drive는 검증하지 않았습니다.

고정 후보로 비공개 HTTPS 최초 설치를 확인했습니다. Windows x64 실기기에서 6번 후보를 설치하고 7번으로 갱신했으며, 기록·설정과 이전 복구 슬롯을 보존했습니다. Windows ARM64 14번과 macOS ARM64 11번은 시험 VM의 표준 계정에서 최초 설치와 전용 실행기의 정상 조회를 확인했습니다. ARM64의 오프라인 갱신과 복원은 각각 다른 후보에서 확인했습니다. 복구 슬롯 확인은 이전 버전으로 실제 전환했다는 뜻이 아닙니다.

비공개 HTTPS 시험에는 사설 주소와 시험용 신뢰를 사용했습니다. 공식 주소와 최초 공개 신뢰, 같은 설치 명령을 다시 실행하는 갱신은 최종 후보에서 확인합니다. 이전 Windows x64 시험에서는 사용자 승인과 기록 폴더 한 곳의 추가 쓰기를 적용한 Codex 앱의 사용자 지정 프로필(11번), MXC를 사용한 Codex CLI 0.167.1의 한정 쓰기(10번)를 확인했습니다. 이 프로필은 시험한 특정 설정에 해당합니다. 기본 승인 메뉴, 다른 권한 모드, 최종 후보는 각각 확인이 필요합니다. Linux와 추가 에이전트는 후속 후보입니다.

누적 기록 검사에서는 입력 파일 100개와 작은 보고서로 Work 300개를 남긴 사례를 확인했습니다. 본문 보존은 별도로 64 MiB 파일의 세 변경 상태를 확인했습니다. 파일 수·본문 크기·변경량이 다르면 저장 공간과 처리 시간도 달라집니다. 새 본문과 백업은 계속 공간을 차지하며 기록을 자동으로 삭제하지 않습니다. 이 수치를 장기 사용의 최대 용량이나 성능 보장으로 읽지는 마세요.


### 문서 실행 준비 상태 확인

첫 Preview에서는 Colvia가 에이전트를 직접 호출하지 않습니다. 설치된 실행기의 `execution readiness`는 프로젝트 기록을 열거나 모델을 시작하지 않고 구성만 점검합니다. 점검이 성공해도 실행이 켜진 것은 아닙니다. 실행 설정과 이력은 읽을 수 있고, 남은 설정은 끌 수 있습니다. 필요한 파일이 바뀌었거나 없다면 안내된 상태를 확인하세요. 우회하려고 Python을 바꾸거나 실행을 다시 시도하지 마세요.
