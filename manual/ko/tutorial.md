# Colvia 따라 하기

[사용 설명서](README.md) · 한국어 · [English](../en/tutorial.md)

처음 설치하고 폴더를 연결한 뒤, 고객 문의 보고서를 만들거나 팀용 할 일 웹앱을 만들어 보세요. 두 실습 모두 승인할 범위를 정하고, 제출본과 검사 결과를 읽고, 새 대화에서 같은 작업을 찾는 데까지 안내합니다.

[설치하고 연결하기](#설치하고-연결하기) · [고객 문의 보고서](#고객-문의-보고서) · [팀용 할 일 웹앱](#팀용-할-일-웹앱) · [다음에 해볼 일](#다음에-해볼-일)

첫 제출 전에 자리를 비울 때는 “여기까지 기록해 줘”라고 하세요. 같은 폴더에서 새 대화를 열고 “하던 일 이어가자”라고 하면, 마지막 메모와 그 뒤 바뀐 파일을 확인할 수 있습니다. [중간 메모 사용법](work.md#progress-note)

## 실습에서 쓰는 것

| 구성 | 하는 일 |
| --- | --- |
| 사용자 | 에이전트에게 목표를 알려 주고, 맡길 파일 범위와 확인 기준을 승인합니다. 제출본을 읽고 수락하거나 수정을 요청합니다. |
| Codex 또는 Claude Code | 폴더의 자료와 규칙을 읽고 작업안을 제안합니다. 파일을 작성하고 검사한 뒤 Colvia로 결과를 제출합니다. |
| 프로젝트 폴더와 Colvia | 문서와 코드는 프로젝트 폴더에 있습니다. Colvia 실행기는 연결된 에이전트가 Work 기록을 찾도록 돕습니다. Colvia는 승인 내역과 제출 본문, 수락 기록을 기기의 사용자 데이터 폴더에 보관합니다. |

Colvia는 범위를 정해 맡기고 검토하는 작업 한 건을 **Work(작업 단위)** 하나로 기록합니다. 앱이나 CLI에서 파일 또는 명령 접근을 허용하는 결정, Work의 범위를 승인하는 결정, 검토한 제출본을 수락하는 결정은 각각 따로 합니다.

## 설치하고 연결하기

1. macOS Apple Silicon 또는 Windows 11 x64·ARM64에서 사용할 Codex나 Claude Code를 열고 로그인 상태를 확인하세요. [지원 환경과 필요한 접근 권한](reference.md#environments)에서 자신의 환경을 확인할 수 있습니다.
2. [공식 설치 페이지](https://colvia.github.io/downloads/#ko)에서 운영체제에 맞는 명령을 복사해 실행하세요. Windows에서는 시작 메뉴에서 일반 PowerShell을 표준 사용자로 엽니다. 설치가 끝나면 완료 화면에서 설치한 버전을 확인하세요. [설치와 프로젝트 연결 상세 안내](install.md)
3. 새 로컬 실습 폴더를 만들어 Codex 또는 Claude Code에서 열고 요청하세요. 이미 작업 중인 폴더도 연결할 수 있습니다. Git 저장소라면 최상위 폴더를 여세요.

   > 이 폴더에 Colvia를 연결해 주세요.

4. Git 저장소인데 Git이 아직 등록되지 않았다면 연결 미리보기가 멈추고 먼저 등록하도록 안내합니다. [등록 내용을 확인하고 승인](git.md#git-register)한 뒤 연결 미리보기를 다시 요청하세요.

   연결 미리보기에서 폴더, 추가할 파일, 기록을 저장할 위치를 확인하고 승인하세요. 사용하는 앱이나 CLI에서 접근이 막히면 [필요한 권한을 확인하는 방법](install.md#access)을 참고하세요. 이 실습에서 Git이 필요하지 않으면 “일반 폴더로 연결해 주세요”라고 답하세요.
5. 지금 대화에서 하려는 일을 한두 문장으로 알려주세요. 이미 목적을 말했다면 에이전트가 그 내용과 기존 프로젝트 규칙을 참고해 작업안을 제안할 수 있습니다. 빈 폴더에서는 “팀용 할 일 앱을 만들어 보고 싶어요”처럼 시작해 보세요.

시작할 실습을 하나 고르세요. 두 가지를 모두 해볼 때는 Colvia를 한 번 설치하고 실습마다 새 폴더를 연결하세요.

## 고객 문의 보고서

### 예제 파일 준비하기

실습 폴더에 아래 가상 문의를 `inquiries.csv`라는 이름으로 UTF-8 형식으로 저장하세요. `report.md`에는 `# 주간 고객 문의 보고서`라는 제목을 적어 두세요.

~~~csv
id,유형,문의
Q01,환불,카드 취소는 언제 반영되나요?
Q02,환불,환불 신청은 어디서 하나요?
Q03,환불,취소 완료 문자를 받았는데 카드 내역에 남아 있어요.
Q04,환불,쿠폰을 쓴 주문도 환불할 수 있나요?
Q05,환불,환불 신청이 접수됐는지 알고 싶어요.
Q06,배송,주문 상태가 이틀째 배송 준비 중이에요.
Q07,배송,배송이 늦어지면 언제 다시 안내받을 수 있나요?
Q08,배송,운송장 번호가 아직 조회되지 않아요.
Q09,배송,도착 예정일이 지났는데 새 일정이 궁금해요.
Q10,사용,적립금 사용 방법을 알려 주세요.
Q11,사용,주문 내역에서 영수증을 어디서 보나요?
Q12,기타,고객센터 운영시간이 어떻게 되나요?
~~~

### 승인하고 검토하기

1. 연결한 폴더에서 이렇게 요청하세요.

   > 문의 12건을 주간 운영회의에서 볼 한 페이지짜리 보고서로 정리해 주세요. 유형별 건수, 자주 나오는 질문, 안내 개선 후보 두 가지를 넣어 주세요. 우선순위는 회의에서 정할게요.

   에이전트가 `inquiries.csv`를 읽고 `report.md`만 고치는 작업안을 제안하면 파일 범위와 검사 기준을 확인하고 승인하세요.

   > 문의 원본은 보존하고 report.md만 수정하는 이 범위로 진행해 주세요.

2. 검토용 제출본에서 바뀐 파일과 검사 결과를 확인하세요. 유형별 건수는 환불 5건, 배송 4건, 사용 2건, 기타 1건입니다. 합계는 12건입니다.
3. 같은 프로젝트에서 새 대화를 열고 아래처럼 물어보세요. 제목이 비슷한 Work가 여럿이면 이번 보고서를 선택하세요.

   > 주간 문의 보고서에서 제가 확인할 부분만 보여 주세요. 어떤 파일을 바꿨고 지금 제 결정이 필요한 게 뭔가요?

4. 결과를 읽고 수정할 내용을 정하세요. 기존 승인 범위 안에서 에이전트에게 다음처럼 요청해 보세요.

   > 배송 개선안에 ‘지연이 계속되면 다음 안내 예정 시각을 함께 적는다’를 넣어 주세요. report.md만 고치고 제가 차이를 보기 전까지는 제출을 기다려 주세요.

   “지금 파일과 마지막 제출본에서 달라진 문장만 보여 주세요”라고 요청해 차이를 확인하세요. 다시 제출받아 읽고, 원하는 결과가 맞으면 “이 제출본을 수락할게요”라고 답하세요. Colvia에 수락한 제출본이 기록됐고 원본 CSV가 남아 있는지 확인합니다.

제출이 거부되면 에이전트에게 어느 파일에서 왜 멈췄는지 물어보세요. 이미 바뀐 파일은 작업 폴더에 남습니다. 변경을 확인하고 정리한 뒤 다시 제출하거나, 추가할 파일을 고치기 전에 [범위 미리보기](work.md#scope-change)를 요청하세요. 이미 바뀐 파일은 편집 내용을 확인한 뒤 따로 보존할지, 직접 원래대로 돌리고 다시 미리보기를 요청할지 정하세요. [작업 검토와 수정 안내](work.md#review)

### 다음 날, 수정 요청에서 이어가기

제출된 보고서를 검토 중이라면 에이전트에게 “불편 사항마다 실제 문의를 하나씩 예로 들어 주세요”라고 수정을 요청해 보세요. 같은 프로젝트에서 새 대화를 열고 “어제 보고서에서 뭘 고쳐 달라고 했지?”라고 물어보세요. 내가 읽은 보고서와 고쳐 달라고 한 내용을 확인할 수 있습니다. 이미 수락했다면 이 실습은 건너뛰세요.

에이전트가 보고서 2판을 제출하면 문의 예시가 제대로 들어갔는지 읽고 수락 여부를 정하세요. 새 대화에서는 [검토할 일부터 조회](work.md#project-status)할 수도 있습니다.

## 팀용 할 일 웹앱

### 빈 폴더에서 첫 버전 정하기

별도의 빈 폴더를 연결하고 하려는 일을 알려주세요.

> 회의가 끝나면 할 일이 채팅에 흩어져요. 운영팀 네 명이 누가 무엇을 맡았고 끝났는지 한 화면에서 볼 수 있게 작은 웹앱을 만들고 싶어요.

어디서 실행하고 어떻게 확인할지 에이전트가 물으면 이렇게 답해 보세요.

> 첫 버전은 목록 하나면 돼요. 가상 데이터를 쓰고, 이 노트북에서 브라우저 탭 두 개로 확인할게요. 계정 로그인은 이후 작업으로 남겨 주세요.

예를 들어 작은 Node.js 서버와 브라우저 화면을 제안받을 수 있습니다. Node.js를 쓰기로 했다면 `node --version`과 `npm --version`으로 환경을 확인하세요. 에이전트에게 앱 실행·검사 명령과 브라우저에서 열 주소를 프로젝트 README에 남겨 달라고 하세요.

첫 버전을 승인하기 직전의 대화는 이렇게 이어질 수 있습니다.

> **나** “할 일을 추가하고 담당자를 지정한 뒤 완료로 표시할 수 있게 해 주세요. 앱을 다시 열어도 목록과 담당자, 완료 상태가 남아야 해요.”
>
> **에이전트** “화면, 서버, 목록 저장에 필요한 파일과 테스트 파일을 계획에 적었습니다. 한 탭에서 할 일을 추가하고 다른 탭에서 담당자를 지정한 뒤 완료로 표시하겠습니다. 두 탭을 새로고침했을 때와 서버를 다시 시작했을 때 모두 같은 목록과 담당자, 완료 상태가 보이는지 확인하겠습니다.”

계획에 나온 파일과 검사 방법이 원하는 첫 버전에 맞으면 “이 범위로 만들어 주세요”라고 한 번에 승인하세요.

에이전트가 서버를 다시 시작해 보니 방금 추가한 할 일이 사라졌다고 해 봅시다. 문제가 승인한 계획에 든 저장 코드에 있다면 에이전트가 그 코드를 고치고 같은 재시작 검사를 다시 실행할 수 있습니다. 같은 대화에서는 에이전트가 이렇게 고치고 다시 검사할 때마다 “계속해”라고 말하지 않아도 됩니다. 다만 Codex나 Claude Code가 명령 실행 권한을 물으면 그 요청에는 따로 답하세요.

계획에 없던 설정 파일을 바꿔야 한다면 에이전트가 그 파일을 바꿔야 하는 이유와 검사 방법을 설명하고 추가 범위를 제안합니다. 추가 범위를 승인하기 전에는 그 파일을 고치지 않습니다. 검사가 실패해도 합의한 검사 기준을 낮추지 않습니다. 기준 자체를 바꿔야 한다면 에이전트가 새 계획을 제안하고 승인을 기다립니다.

### 앱을 열고 결과 확인하기

1. 프로젝트 README의 명령으로 앱을 실행하고 같은 주소를 브라우저 탭 두 개에서 여세요. 첫 탭에서 ‘환불 안내 문구 정리’와 ‘배송 지연 안내 기준 정리’를 추가하세요.
2. 두 번째 탭을 새로고침해 두 항목이 보이는지 확인하세요. 한 항목에 담당자를 지정하고 완료로 표시하세요. 첫 탭을 새로고침해 같은 담당자와 완료 상태가 보이는지 확인하세요. 서버를 다시 시작한 뒤에도 두 항목과 담당자, 완료 상태가 남아 있는지 확인하세요.
3. 에이전트는 앱을 제출할 때 계획한 검사마다 통과, 실패, 실행하지 못함 중 하나로 결과를 남깁니다. 중간에 검사가 실패해 고친 부분이 있다면 무엇을 고쳤는지 제출 요약에 적어 달라고 하세요.
4. 같은 프로젝트에서 새 대화를 열고 “할 일 앱의 마지막 제출본과 검사 결과, 제가 결정할 내용을 보여 주세요”라고 물어보세요. “완료한 항목 숨기기” 같은 새 아이디어는 [후속 작업 후보](work.md#follow-up)로 남길 수 있습니다. 제출본과 검사 결과를 검토하고, 처음 요청한 대로 동작하면 “이 첫 버전을 수락할게요”라고 답하세요. 더 고칠 점이 있으면 수정을 요청하세요.

## 다음에 해볼 일

- **보고서 제출 알림 받아 보기.** 위 실습에서 보고서를 준비한 뒤 검토용으로 제출하기 전에 이렇게 요청하세요. “보고서 초안이 준비됐어요. 검토용으로 제출하고, 이 기기에서 알려 주세요.” 에이전트가 알림과 함께 제출을 맡았다면 그 제출 한 번으로 충분합니다. 운영체제가 권한을 물으면 직접 허용하세요. 알림이 열리면 제출본을 읽고 수락하거나 수정을 요청하세요. 전송 여부가 불확실하면 기존 알림 기록을 먼저 확인하세요. 알림을 놓치거나 열리지 않으면 같은 프로젝트에서 “검토할 결과가 있나요?”라고 물어보세요. [알림 설정과 전송 상태](maintenance.md#notifications)
- **다른 에이전트에서 이어가기.** Codex와 Claude Code를 모두 쓴다면 두 번째 에이전트에서 같은 프로젝트를 열어 Work를 찾아보세요. 작업 폴더와 Colvia 기록에 접근할 수 있어야 합니다.
- **Git에 수락한 결과 반영하기.** Git을 사용하는 프로젝트에서는 커밋할 변경과 현재 스테이징을 보고 별도로 승인할 수 있습니다. [Git 반영 안내](git.md#git-integration)
