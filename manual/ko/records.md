## Colvia가 보관하는 내용

Colvia는 계획을 기록할 때 계획에 적힌 기존 파일의 본문을 보관합니다. 승인 범위에서 바꾼 내용은 제출할 때 함께 보관해 나중에 그때 검토한 버전을 다시 읽을 수 있습니다. 계획에 필요한 파일만 적으세요. 범위 밖 파일의 변경 여부를 확인하는 정보는 본문과 구분해 보관합니다.

| 시점 | 보관되는 것 |
| --- | --- |
| 계획을 기록할 때 | 계획에 적은 기존 파일의 본문. 승인 전이라도 보관됩니다. |
| 중간 메모를 요청할 때 | 짧은 진척 요약과 승인 파일의 해시·존재 여부. 메모도 백업에 들어갑니다. |
| 중단·재개·폐기·대체를 확인할 때 | 사유, 원래 단계, 다음 행동과 지정한 대체 Work. 중단 때 확인한 경로의 해시가 백업에 포함됩니다. |
| 첫 제출 전 또는 수정 요청 후 파일 추가 | 추가 승인한 기존 파일의 원문과 결정은 백업에 포함됩니다. 새 파일은 추가 승인 시점에 없었다고 기록합니다. |
| 검토용으로 제출할 때 | 승인 범위에서 바꾼 내용(제출본)과 검사 결과 |
| 결정할 때 | 범위 승인, 결과 수락, 수정 요청, 후속 선택 |

기록은 프로젝트 폴더가 아니라 운영체제의 사용자 데이터 폴더에 있습니다. 위치는 [파일과 폴더 위치](reference.md#locations)에서 확인하세요.

파일 수와 변경량에 따라 기록·백업에 필요한 공간과 처리 시간이 달라집니다. 기록을 자동으로 삭제하지 않으므로 큰 파일이 있는 프로젝트에서는 저장 공간을 확인하세요.

## 기록 백업과 복원

계획을 승인했는지와 관계없이 기록할 때 보관한 본문과 제출본은 백업에 들어갑니다. 프로젝트 자료와 같은 기준으로 백업을 보관하세요. Preview에서 보존 본문의 일부만 골라 지울 수 없으니, 어떤 자료를 보관할지 계획을 기록하기 전에 확인하세요.

Git commit이나 clone만으로 Colvia 기록이 백업되지는 않습니다. 기록·본문·설정·수락 이력을 옮기려면 Colvia의 내보내기와 복원을 사용합니다. 프로젝트 파일도 별도로 보관해야 합니다. 같은 기기에 만든 복구본만으로 기기 고장에 대비할 수는 없습니다.

백업을 만들 때는 에이전트에게 이렇게 요청할 수 있습니다.

> 이 프로젝트의 Colvia 기록을 새 백업 파일로 내보내 주세요. 저장 위치와 백업 완료 여부를 알려 주세요. 프로젝트 파일은 제가 따로 백업할게요.

복원할 때는 먼저 무엇이 복원되는지 확인하세요.

> 이 백업을 복원하기 전에 대상 프로젝트와 보존된 Work를 확인하고, 복원과 재연결에 필요한 결정을 설명해 주세요.

1. 기록을 새 파일로 내보냅니다.
2. 백업 파일을 프로젝트 자료와 같은 기준으로, 가능하면 다른 기기나 저장소에 보관합니다.
3. 복원할 때 Work와 보존 본문을 확인합니다.
4. 대상 폴더를 확인한 뒤 복원한 기록을 그 폴더에 연결합니다.

Colvia 기록을 복원할 때는 Work와 보존 본문을 함께 확인합니다. 복원한 기록을 폴더에 연결할 때는 폴더의 정체성과 변경 내용을 확인합니다.

미완료 외부 작업이 남은 백업은 바로 실행 가능한 상태로 복원하지 않습니다. 원래 실행이 어디까지 반영됐는지 먼저 확인해야 합니다.

## 프로젝트 폴더를 옮긴 뒤 이어가기

### 에이전트에게 폴더 이동 확인을 맡기기

이미 폴더를 옮겼다면 프로젝트 폴더 밖에서 새 대화를 열고 다음처럼 요청하세요.

> 프로젝트 폴더를 옮겼어요. 새 위치에서 기존 Colvia 기록을 이어가게 해 주세요.

에이전트가 새 위치를 물으면 실제 경로를 알려 주세요. 필요한 접근 권한이 있으면 에이전트가 설치된 Colvia 관리자로 이동 미리보기를 준비할 수 있습니다. 미리보기에 나온 기존 위치와 새 위치를 확인하세요. Colvia가 같은 폴더임을 확인하면 기존 연결을 새 위치로 바꾸도록 승인하세요. 에이전트가 그 미리보기로 적용한 뒤 새 위치에서 프로젝트를 열고 이전 Work를 확인할 수 있습니다.

아직 폴더를 옮기기 전이라면 에이전트에게 먼저 이동 조건을 확인해 달라고 하세요. 원래 위치에서 진행 중인 실행·전달·Git 반영·복구를 마무리하거나 중단 상태를 해결하세요. 최신 Colvia 백업과 프로젝트 파일 사본을 따로 보관하세요. 폴더를 열어 둔 대화와 실행기를 닫고 같은 로컬 볼륨에서 폴더 자체를 옮긴 뒤 위 요청으로 이어갑니다.

### 이동 조건

- 일반 폴더 또는 자체 `.git` 디렉터리를 가진 단일 Git checkout에서 사용할 수 있습니다.
- 연결된 worktree나 submodule이 없어야 하고, 다른 Colvia 프로젝트와 겹치면 안 됩니다.
- 원래 경로에 폴더가 남아 있으면 안 되며, Colvia가 옮긴 폴더의 동일성을 검증해야 합니다.
- 복사본, 다른 볼륨, 다른 Colvia 프로젝트 하위의 위치는 이 확인에서 거부될 수 있습니다. 겹치면 다른 프로젝트 바깥의 위치를 사용하세요.
- 양쪽 파일과 기록을 보존하고 연결 파일이나 DB는 그대로 두세요.

macOS에서 폴더를 다시 확인하라는 안내가 나오면 [현재 연결을 확인하는 절차](maintenance.md#folder-confirmation)를 따르세요.

macOS의 로컬 APFS에서는 일반 폴더와 단일 Git 폴더를 같은 볼륨에서 옮겨 확인했습니다. Windows에서도 로컬 NTFS의 같은 볼륨 안에서 옮긴 일반 폴더를 관리 명령으로 다시 연결하고 기존 Work를 읽었습니다. Windows 11 ARM64에서는 공식 v0.1.0으로, x64 실기기에서는 0.1.0 격리 시험본으로 확인했습니다. Windows의 Git 폴더는 별도 검증 대상입니다. 해당 환경에서 이미 Git 폴더를 옮겼다면 기존 연결 정보와 기록을 보존하고 진단을 요청하세요. 이동을 마친 기록을 열 때는 해당 기록과 호환되는 실행기가 필요합니다.

### 명령으로 직접 확인하기

직접 명령을 쓰거나 에이전트에 필요한 접근 권한을 줄 방법이 없다면, 프로젝트 폴더 밖에서 설치된 관리자를 사용합니다. 기존 프로젝트 ID와 새 절대 경로를 넣고, 개인 로컬 폴더에 새 이름으로 미리보기를 저장하세요. 다음은 macOS 터미널 예입니다.

```sh
"$HOME/Library/Application Support/Colvia/bin/colvia" manage --json move-preview PROJECT_ID "/path/to/moved-project" > move-preview.json
```

Windows에서는 표준 사용자의 명령 프롬프트에서 저장하세요. Windows PowerShell 5.1은 출력 파일의 문자 인코딩을 바꿀 수 있습니다.

```cmd
"%LOCALAPPDATA%\Colvia\bin\colvia.exe" manage --json move-preview PROJECT_ID "C:\Work\MovedProject" > move-preview.json
```

미리보기가 성공하면 기존 위치와 새 위치를 확인하세요. 승인 뒤 위에 나온 같은 관리자 실행 경로에서 `manage move-apply --plan move-preview.json --receipt RECEIPT_FROM_PREVIEW --statement "YOUR_APPROVAL" --operation OPERATION_ID`로 저장한 원본 파일과 그 안의 확인값을 적용합니다. 파일을 다시 저장하지 말고, 적용을 시작할 때는 새 실행 ID를 사용하세요.

중단되면 `manage move-status OPERATION_ID`로 확인합니다. 승인 후 아직 반영 중이라면 `manage move-resume OPERATION_ID`에 같은 ID를 넣어 이어갑니다. 충돌하거나 원래 위치가 남아 있다면 양쪽을 보존하고 진단을 요청하세요. 완료 후 새 폴더를 열면 됩니다. 연결 위치를 갱신하고 Work의 기록·결정·보존 본문은 유지합니다.
