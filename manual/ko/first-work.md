# 첫 Work 완료하기

[이전: 준비](getting-started.md) · [목차](README.md) · [English](../en/first-work.md) · [다음: 재개](resume.md)

Work는 합의한 작업과 결과, 수락 결정을 연결하는 기록입니다. 사용자는 원하는 결과를 설명하고, 에이전트는 정확한 기록을 준비해 승인된 작업을 수행합니다. 범위와 결과 수락은 사용자가 결정합니다.

## 작은 결과 하나 정하기

문서 작업이라면 이렇게 요청할 수 있습니다.

> 이 README의 설치 안내를 보강해줘. 기존 인용·링크·예시와 나머지 내용은 보존하고, 수정 전에 바꿀 내용과 검사 방법부터 설명해줘.

에이전트는 프로젝트 지침과 `./colvia view --details`, 현재 adapter를 읽고 기존 계획, 대상 파일, 기대 결과, 검사, 한도와 중단 조건을 정리합니다. 중요한 미정 사항을 해소하고 사용자가 결정할 정확한 작업 요청을 준비합니다. 이미 유효한 승인은 이어서 사용하고, 범위가 바뀌거나 승인이 소비된 경우에는 해당 계약을 따릅니다. 자세한 기준은 [Guided Intent](../../docs/GUIDED-INTENT-FORMATION.md)에 있습니다.

## 구현하고 확인하기

정확한 범위가 수락되면 에이전트가 Work의 기준 상태를 기록하고 그 범위에서 수정합니다. 이 예시에서는 요청한 설치 안내가 반영됐는지, 구간 밖 내용과 링크·형식이 보존됐는지 확인합니다. 임시 검사 데이터는 수락할 결과의 일부가 아니라면 Work의 추적 대상 밖에 둡니다. 빠졌거나 실행할 수 없는 검사는 그대로 표시합니다.

에이전트는 결과를 기록하고 바뀐 내용, 확인한 것, 남은 한계를 설명합니다. 결과 confirmation을 준비하고 `./colvia view work WORK_ID --revision REVISION_ID`로 같은 판본을 확인합니다. 실제 ID와 canonical 입력은 에이전트가 준비하므로 사용자는 JSON을 편집하지 않고 설명과 confirmation을 검토할 수 있습니다. 기록 필드와 수락 규칙은 [General Work](../../docs/GENERAL-WORK.md)를 따릅니다.

## 결정하고 다음으로 넘어가기

합의한 기준을 충족했다면 화면에 제시된 정확한 결과를 수락합니다. 에이전트가 그 ticket을 적용하고 저장된 상태와 현재 파일을 확인합니다. 검사 통과와 리뷰 권고는 판단 근거이며, 수락은 사용자의 결정입니다. local 작업에서는 수정한 파일이 이미 control checkout에 있습니다. worker 결과는 별도의 정확한 적용 절차를 따릅니다.

완료 보고에는 달성한 내용, 프로젝트 계획에서 남은 일, 다음 추천과 이유가 함께 있어야 합니다. 여기서 마치는 것도 추천할 수 있습니다. 선택한 후속 작업이 없다면 그 상태와 다음에 결정하면 좋을 내용을 설명합니다. 추천만으로 다음 작업을 시작하지 않습니다.

## 결과 보존하기

수락 기록과 필요한 source·복구 입력을 보관합니다. commit이나 push를 결정하기 전에 Git 상태와 보존할 파일 목록을 요청하고, 중요한 ignored 산출물도 별도로 확인하세요. 소유권·남은 사용처·복구 가능성이 확인된 것만 정리합니다. Work 수락, Git 통합, 원격 게시는 각각 결정합니다.

적용이 멈추거나 현재 파일이 결과와 다르면 입력을 보존하고 지원되는 복구 경로를 확인합니다. 이후 [새 대화](resume.md)에서도 채팅 이력으로 권한을 추측하지 않고 프로젝트 기록을 기준으로 이어갑니다.

과거 checkout-1 실습의 관측은 당시 기록으로 유지됩니다. 새 배포본, agent 행동, 실제 프로젝트 품질은 각각의 근거로 확인해야 합니다.
