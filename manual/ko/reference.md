## 기기 알림 켜기

에이전트에게 “이 기기에서 작업 알림을 켜줘”라고 요청하세요. Mac에서는 설치할 때 확인한 관리 도구로 `notice-enable`을 실행하고 알림 권한을 허용합니다. Windows에서도 해당 관리 도구로 `notice-enable`을 실행하세요. Windows 관리 도구를 갱신했다면 새 실행 파일로 한 번 더 등록합니다. 기기 알림을 꺼 둬도 수신함은 사용할 수 있습니다. [환경별 명령과 알림 클릭 지원 범위](../../docs/REFERENCE.md#single-work-handoff-and-inbox)

## 재개와 복구의 기술 상세

### 현재 상황 되찾기

수락한 결과, 미완료 범위, 현재 파일의 일치·변경 여부, 소비한 시간·시도와 남은 유효 권한을 간결하게 설명해야 합니다. 이후 파일이 달라져도 완료된 Work의 과거 수락 기록은 남습니다. 설명 문서와 기록이 다르면 쓰기를 제안하기 전에 차이를 확인합니다.

이미 승인한 작업에 남은 일이 있고 조건이 유지되면 에이전트가 이어갑니다. 현황 확인이나 추천만 요청했다면 읽기 전용으로 답합니다. 진행 중이거나 확인할 수 없는 적용은 해당 복구 절차를 따릅니다. 새 대화가 실행 상태나 한도를 초기화하지는 않습니다. 복구에 필요한 기존 요청과 원본 파일을 보존하세요.


View는 작업 제목과 ID, 기록된 상태, 다음 확인을 함께 보여줍니다. `view work ID`에서는 기록된 범위와 제출 당시 확인 내용을 기술 상세보다 먼저 볼 수 있습니다. 에이전트가 해석한 내용은 화면 출력과 구분해 설명합니다.

실행 기록은 별도로 보여줍니다. 해당 실행에 기록된 문서 반영 여부와 프로세스 종료를 확인할 수 있으며, 같은 Work ID라도 현재 작업 기록과의 관계는 따로 확인해야 합니다. 미해결 실행의 반영 여부가 불명확하면 허용된 기록과 현재 파일부터 확인합니다. 이후 복구나 새 실행은 기존 승인 절차를 따릅니다. 이미 정리된 실행의 과거 효과가 불명확하더라도 현재 작업은 자신의 조건에 따라 진행할 수 있습니다. 자세한 근거에서 확인한 범위와 남은 한계를 볼 수 있습니다.

### 다음 작업 고르기

완료된 작업 다음에는 하나의 추천을 요청하거나 후보를 지정해 비교할 수 있습니다. 에이전트가 먼저 `./colvia view candidates`를 읽고 예상 범위·검사와 지금 필요한 이유를 설명합니다. 후보 저장을 명시적으로 요청하면 그 계획 변경을 수행할 수 있으며, 실행과 결과 수락은 각각의 기준을 따릅니다.

프로젝트를 옮기거나 복제한 뒤 실행 환경이 없다면 신뢰할 배포본에서 정확한 전용 Python을 준비합니다. 설치 진입점이 손상됐다면 독립된 신뢰할 배포본과 [Operations](../../docs/OPERATIONS.md)를 사용합니다. 연결 해제 뒤 남은 기록은 지원되는 방식으로 조회하며 새 프로젝트로 취급하지 않습니다.

새 CLI 프로세스의 조회와 연습용 프로젝트에서의 에이전트 행동은 서로 다른 관측입니다. 실제로 확인한 것을 기록하고 실사용에서 아직 확인하지 못한 한계를 유지합니다.


### 단일 Work 맡기기

자리를 비우는 동안 준비된 수정본의 제출과 기기 알림까지 맡기려면 에이전트에게 “이 수정본을 검토할 수 있게 제출해 줘. 준비되면 나한테 알려줘”라고 말하세요. 에이전트가 어떤 작업을 어디까지 진행할지, 기한은 언제이고 결과는 어디에서 볼 수 있는지 보여 줍니다. 내용이 맞으면 “좋아, 그 범위로 진행해 줘”라고 하세요. 그러면 이 기기의 작업 수신함에 요청이 접수됩니다. 기기에서 작업 프로세스가 실행되는 동안 대화창을 닫아도 그 단계가 진행됩니다. 현재 지원하는 단계는 작업 현황 정리, 준비된 변경 결과의 검토 제출, 선택형 macOS 구성의 승인된 문서 실행입니다. 프로젝트 연결 해제와 사용자 수락은 별도 결정입니다.

“맡긴 작업에 질문이나 결과가 있어?”라고 물어보거나 프로젝트에서 `./colvia view inbox`로 확인하세요. 질문을 받으면 해당 작업에 계속 또는 중단으로 답할 수 있습니다. 기기 알림에는 일반 안내만 표시됩니다. 알림을 놓쳐도 결과는 같은 수신함에 남습니다. 실행 중 기기가 멈췄다면 기존 실행과 문서 반영 상태를 먼저 확인하세요.

기한이 지났는데 어디까지 반영됐는지 알 수 없다면 “작업 기록을 대조해 줘”라고 요청하세요. 실행이 멈췄고 기록으로도 확인하기 어려우면 “반영 여부는 미확인으로 두고 이 접수를 닫아 줘”라고 선택할 수 있습니다. 사용한 한 단계와 이력은 수신함에 남고 다른 작업을 맡길 수 있습니다.

시험한 macOS·Windows ARM64 알림 후보에서 ‘보기’를 누르면 그 알림을 보낸 작업의 제출본이 열렸습니다. 프로젝트와 판본을 확인한 뒤 결정하세요. 배너가 보이지 않았다면 같은 Work의 수신함에서 찾을 수 있습니다. 최종 후보에서 Codex·Claude Code별 클릭과 네이티브 Windows x64 확인은 남아 있습니다.

## 검토와 수락의 기술 상세

### 작은 결과 하나 정하기

문서 작업이라면 이렇게 요청할 수 있습니다.

> 예약 정책이 바뀌었어. FAQ와 상담 답변에서 달라질 내용을 먼저 보여줘. 수수료는 아직 정하지 않았어.

에이전트가 프로젝트 지침과 기존 계획을 읽고 어느 파일을 어떻게 고칠지, 결과를 어떻게 확인할지 보여 줍니다. 이미 승인한 범위에서 진행할 수 있으면 이어서 작업합니다. 범위가 달라지거나 승인한 횟수를 모두 썼다면 다시 결정할 부분을 알려 줍니다. [작업 범위 정하기](../../docs/GUIDED-INTENT-FORMATION.md)

### 구현하고 확인하기

수정과 검사, 검토할 수정본까지 계획에 포함해 승인하면 에이전트가 Work의 기준 상태를 기록하고 그 범위에서 수정합니다. 이 예시에서는 두 문서에서 24시간 기준이 같은지, 수수료가 미정으로 남았는지 확인합니다. 임시 검사 데이터는 수락할 결과의 일부가 아니라면 Work의 추적 대상 밖에 둡니다. 빠졌거나 실행할 수 없는 검사는 그대로 표시합니다.

결과를 열면 바뀐 줄과 검사 결과를 함께 볼 수 있습니다. 확인하지 못한 부분도 여기에 표시합니다. 에이전트가 같은 작업의 같은 수정본을 찾아 보여 주므로, 변경을 받아들일지 판단하면 됩니다. [결과 기록과 수락 절차](../../docs/GENERAL-WORK.md)

### 결정하고 다음으로 넘어가기

요청한 줄만 고쳤다면 “이 수정본을 수락할게”라고 말하세요. 에이전트가 그 결정을 기록하고 현재 파일을 확인합니다. 프로젝트에서 직접 고친 내용은 이미 파일에 반영돼 있습니다. 별도 작업 공간에서 받은 결과라면 해당 수정본을 프로젝트에 적용하는 절차가 따릅니다.

완료 보고에는 달성한 내용, 프로젝트 계획에서 남은 일, 다음 추천과 이유가 함께 있어야 합니다. 여기서 마치는 것도 추천할 수 있습니다. 선택한 후속 작업이 없다면 그 상태와 다음에 결정하면 좋을 내용을 설명합니다. 추천만으로 다음 작업을 시작하지 않습니다.

### 결과 보존하기

수락한 결과와 복구에 필요한 원본을 보관하세요. 커밋하거나 원격 저장소에 올리려면 먼저 어떤 파일을 포함할지 확인합니다. Git이 추적하지 않는 파일에도 보관할 결과가 있을 수 있습니다. 복구할 수 있고 더 쓸 곳이 없는 파일만 정리하세요.

적용이 멈추거나 현재 파일이 결과와 다르면 입력을 보존하고 지원되는 복구 경로를 확인합니다. 이후 [새 대화](resume.md)에서도 채팅 이력으로 권한을 추측하지 않고 프로젝트 기록을 기준으로 이어갑니다.

과거 checkout-1 실습의 관측은 당시 기록으로 유지됩니다. 새 배포본, agent 행동, 실제 프로젝트 품질은 각각의 근거로 확인해야 합니다.

## 과거 설치본으로 진행한 실습

### 확인한 범위

과거 checkout-1 후보로 2026-10-05 macOS·CPython 3.14.7의 합성 Git 프로젝트에서 준비, 실제 source 설치, 정해진 형식의 작업 요청서 수락, local Work 제출·수락, 읽기 전용 재개를 실행했습니다. 예제 CLI는 빈 목록 조회, 순서를 지키는 추가·조회, 파일을 쓰지 않는 빈 할 일 거부, 데이터를 바꾸지 않는 조회의 네 가지를 검사했습니다. 각각 새로 실행한 CLI 프로세스에서 완료 기록과 변경되지 않은 결과를 읽었습니다.

실습의 수락 결정은 스크립트로 처리했습니다. **독립된 새 agent 세션과 실제 사람의 이해도는 시험하지 않았습니다.** Windows, Linux, 클라우드 배포, 잘못된 할 일 데이터의 복구, 일반적인 온보딩 사용성도 이번 실습에서 시험하지 않았습니다. runtime 버전 허용과 운영체제 검증은 별개입니다. [Security and Support](../../docs/SECURITY-AND-SUPPORT.md)를 참고하세요.

이 문서는 repository에서 읽는 검토판이며, 설치 프로젝트의 managed payload에 복사되지 않습니다. 설치된 프로젝트에서는 `./colvia view`가 현재 설치본의 manual과 adapter를 안내하고, `./colvia status`가 검증된 `documentation_root`를 보여줍니다. 실제 운영은 그 설치본 문서를 기준으로 합니다. 아래 상대 링크는 이 source checkout이나 전체 사본에서 열 수 있습니다.
